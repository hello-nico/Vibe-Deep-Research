## 1. 目标

本次用户确认：页面登记当前真实对象 → `@` 只在当前助手登记范围内选择 → 选中只钉身份 → 发送后按身份读取 → 回答依据绑定本次读取结果。动态的是候选，已选引用保持稳定；不把整页 context/JSON 当作对象引用或自动注入模型。

用户进一步确认：大盘行情、资讯雷达、行业研究、产业研究、个股研究对应五个不同角色定位的 DSH Agent。每个角色有独立 system prompt、实际活跃工具集、对象范围和会话绑定；不能缩成同一深度对话 Agent 的五份页面文案。Ask/Agent 是各角色内部的权限模式，不是这五个角色本身。

问助手拥有自己的侧栏输入。五个角色共用 DSH 会话机制、执行、工具权限、轨迹、中止和可复用组件，不搬入深度对话整棵页面或 composer。深度对话保留自己的独立角色、首页、输入和全局研究对象源，不属于上述五个页面角色。数据先更新，判断按需更新并经确认发布后才可回读。

## 2. 页面动态登记与对象覆盖

### 登记与候选生命周期

- 业务页面按当前已加载、当前栏目/分类/筛选下实际展示的数据，向当前助手范围注册对象；登记包含类型、稳定身份及已有标题、来源、日期、URL、观察范围/版本等展示与定位信息。卡片或表格是展示，组件名和数组下标不是对象身份。
- 共用登记、更新、注销、查询和插入机制，各页面只提供对象；不为每页复制一套 `@`，不新增资讯搜索器猜测页面内容。
- 问助手 `@` 从首轮起只查询当前登记对象，支持标题等展示信息搜索。候选为空或无读取能力时明确为空，不回退全局 Wiki、资料库或按公司代码重新搜索新闻。候选范围不等于限制研究中获授权工具的取证范围。
- 栏目/赛道/筛选或加载结果变化即更新候选；卸载注销。异步更新必须核对所属页面及当前加载批次，迟到结果不能覆盖新筛选或写进其他页面。
- 选中时保存该对象的身份与展示信息；候选刷新、切换栏目或注销不替换/删除已有 chip。恢复草稿时仍使用其原引用，不按当前候选位置重新解释。会话之间不转移草稿或引用。
- 登记、查询和选中不抓正文、不入库、不向模型发送完整列表；发送只携带用户选中的引用与必要页面语义。深度对话的全局 `researchObjectSource` 与页面助手候选范围分开。

### 已有读取契约

以下是可复用的读取能力，不是问助手应自动枚举的全局目录。只有当前页面登记、且有稳定读取身份的对象才进入其 `@`。

- 公司/行业/Theme/Comparison Wiki：`slug@input_hash`，`wiki_read` 核 hash；不匹配失败，不把当前稿当旧稿。
- Topic：`topic:{12hex}`，`topic_get`；问助手不写 Topic。
- 资料：`document:` 钉 revision/hash；未解析不能当正文。
- 宽基指数：`market:{000001.SH|000300.SH|399001.SZ|399006.SZ}`，`observe_market` 用 `marketBenchmarkId`。集合 `market:indices` 表示成员列表。
- A 股公司行情：`company:{code}.{EX}`，与 Wiki 不同对象。
- 新闻/公告：页面当前列表中的具体条目，以稳定 `url:` 定位，保留 `time` / `source` / `title` / `url`；不按公司名/代码另搜候选，无稳定 URL 不进 `@`。标题 chip 不代表已读正文。
- 产业研究 Profile：`profile:sw2:{code}:{sha256}`，只读 `read_industry_profile`；不是 Theme Wiki，也不是行业 Wiki。
- 市场情绪/资金流/涨停榜：本包缺口，不生成 chip。
- 日期是观察范围，不是对象版本或盘中快照。行情读取保留 `observe_market.asOf`；不得将发送后的新行情冒充页面当时数值。深度对话既有日期引用不因此加入页面候选。

## 3. 五个独立 Agent 角色 × Ask/Agent 模式

绑定：`plugin`（独立角色身份）+ `mode` + `target`，并关联当前页面对象登记范围。角色 system prompt、实际工具注册和 hook 都使用同一绑定。比较引用不改 `target`；切换栏目/筛选只更新对象候选，不把角色偷偷换成深度对话。

| 页面 / 独立角色 | system prompt 的业务定位 | 角色工具职责边界 |
|---|---|---|
| 大盘行情 Agent | 指数与市场表现、观察时点和口径解释 | 行情观察、确定性计算及必要依据读取；不继承公司/行业 Wiki 维护工具 |
| 资讯雷达 Agent | 具体新闻/公告的内容、事件、相关对象与影响分析 | 统一 Fetcher、资讯及必要关联依据读取；慢资料入库沿既有权限，快资讯默认不入库，不继承 Wiki 判断维护工具 |
| 行业研究 Agent | 固定 41 行业的结构、经营机制与研究判断 | 行业 Wiki 与证据读取、绑定行业的既有维护能力；不新造行业 refresh-api |
| 产业研究 Agent | 申万产业 Profile、供需及产业链资料分析 | `read_industry_profile` 与必要资料/证据读取；Profile 不冒充行业/Theme Wiki，不自动获得其写权限 |
| 个股研究 Agent | 当前公司的经营、财务、公告与 Wiki 判断 | 公司行情、Wiki、证据读取及绑定公司的既有维护能力 |

行业/个股可沿用 `industry_wiki` / `company_wiki` 角色身份；大盘、资讯、产业必须分别注册独立角色，撤销统一绑定 `deep_research` 的方案。具体注册名称遵循现有 DSH 接口，但运行时必须能区分五个角色。自选等非本次五模块入口不据此新增第六个角色，也不作为五角色验收替代。

每个角色分别定义 system prompt 与 Ask/Agent 两套明确的活跃工具允许列表，可复用公共规则和工具实现；不能只改输入占位、追加普通用户消息或给同一全量工具集写“不要调用”的提示。工具重叠允许，但须按角色职责显式选取，未授权工具在运行时不可调用。Ask 默认只读并跳过 review/finalize；Agent 仅增加该角色已有授权动作，无维护对象/接口的角色不凭模式名扩张写权限。后台 hook/子任务继承同一角色与模式边界。

已有只读工具供按角色选择，不得整表自动激活给五个角色：`today`, `resolve_refs`, `source_list_documents`, `source_get_index`, `source_scan_sections`, `source_read_blocks`, `topic_list`, `topic_get`, `search_external`, `query_observation`, `observe_market`, `observe_radar`, `calculate_metrics`, `read_research_method`, `wiki_read`, `wiki_list_pages`, `wiki_search`, `wiki_relations`, `read_research_result`, `calculate_market_result`, `fetch_source_url`(persist=false), `read_industry_profile`。实施须在各角色定义中落实精确工具清单，并记录实际注册结果供验收。

既有 Agent 增量边界：个股可加 `fetch_company_data`、`wiki_refresh_company_api`（仅绑定 slug）、`source_ingest_periodic_report`、persist URL、`stage_extraction`；行业可加 persist URL、`stage_extraction`（不新造行业 refresh-api）。大盘/资讯/产业仅按上表职责选择已有获授权的取数、计算、结果生成或慢资料入库能力，不继承深度对话全量增量、不发 Wiki 判断草案。五个页面角色均不注册 Topic 写入与 `wiki_report_publish`。

五份角色 system prompt 分别注入业务目标、读取与动作边界、依据纪律和失败语义；个股沿公司 schema v1.0.1（判断仅 `operating_model`），行业沿行业 v1.1.0（`operating_model`/`industry_structure`）。共用金融纪律不替代独立角色定义。Ask 只读；Agent 维护绑定目标，草案≠已发布。

## 4. 可回读 Wiki 闭环

主 Agent 不 publish。数据：`wiki_refresh_company_api` → 已接受页，保留 `research_blocks`。时间线：入库并解析完成后 `enqueue_wiki_refresh`；新闻不进时间线。判断：Agent 回合后知识整理子代理 → `POST /wiki/page-drafts/research` → `awaiting_authorization` → 用户 `publishWikiDraft` → 已接受页。公司/行业 Wiki 与问助手维护卡片接上现有审阅/确认发布。Ask 与单纯资料到达不改判断。

## 5. 问助手自有输入与会话生命周期

- 内容区在上、输入钉底；问助手拥有独立布局和输入，禁止搬用 `#dsh-conversation` 或嵌入深度对话整套 composer。可以复用公开组件与输入机制，但不得继承其首页文案、`+` 指令和无当前页面用途的工具条。
- 保留 Ask/Agent 与当前助手会话的模型选择；模型配置仍归 DSH。模型菜单须在侧栏真实可操作，切换不影响深度对话。附件入口仅在模块有明确上传业务时保留，不作为通用工具条顺带嵌入。
- 占位与提示词跟当前模块走，例如资讯“引用一条资讯，分析事件与影响…”，大盘“引用一个指数，分析市场表现…”。页面标题变化不等于已经完成提示词隔离。
- 打开时取得/创建该页面绑定的 DSH session_id，绑定 plugin/mode/target，完成前禁用发送。独立视图直接绑定助手会话，不通过抢占深度对话活动会话实现；不保留全局 pending 抢占路径。
- 关闭不 abort，重开恢复对应会话；新讨论才显式新建。切公司不复用上一目标会话，切页不串草稿、引用或执行目标。运行中切模式返回 409。
- 打开、关闭、卸载和切页均不得改变深度对话的会话、草稿、模型或运行状态；迟到绑定不得激活已离开的页面。视图卸载与 DSH 任务中止分别处理。

## 6. 发送后读取与本轮依据绑定

- 发送后，选中的 URL 经统一 Fetcher 读取；Wiki、资料和行情经各自正式读取能力处理。不另造 Fetcher，不在候选登记、选中或 serialize 阶段预取正文。
- 读取是本轮引用闭环的必要环节；仅序列化“发送时未读正文”并寄望模型自行调用工具不算完成。实施须明确现有 DSH/对象读取链中的触发与结果绑定位置，不能旁路新建执行器。
- 回答对引用内容作判断前须有本次成功读取依据；读取失败、只有摘要、解析未完成与正文可读分别表达，不以标题推断冒充全文分析。部分对象失败不伪装成全量成功。
- 将会话/轮次、对象身份、读取时点、实际返回的版本或内容 hash 与引用结果绑定，沿现有结果/证据 Owner 保存必要依据。不把 URL 本身当内容版本；后续重新抓取不得覆盖本轮结果，历史回答不得静默指向新正文。版本不可回读时明确缺口。
- 本轮只使用现有 revision/hash/结果机制，不引入 Git 统一版本。快资讯默认只读分析，`@` 或 Fetcher 读取不触发资料入库或判断维护；保存本轮必要依据不等于将快资讯积累为资料库 Document。若现有机制无法同时满足此边界与版本追溯，停止并回报。
- Ask 读 PDF 须有可读正文或明确 `parse_status`；截断拒绝 persist；慢资料沿现有契约授权入库且解析成功后才声称进入时间线；DNS 校验实际连接地址；Wiki hash 不匹配失败。

## 8. 验收

不点页面引用按钮。不重启现用服务。隔离实例可跑则跑，否则标待部署；测试≠产品闭合。

### 首个真实验收：资讯雷达截图中的华为云新闻

1. 在「AI / 大模型」实际列表中，首轮 `@` 能按标题找到“华为云全面面向智能体…”；候选来自本页条目，绑定其真实 URL、标题、来源、日期，不用夹具或另外搜索的同名新闻替代。原条目不可取得时报告阻塞，不声称原案例通过。
2. 选中显示标题 chip；网络/工具轨迹证明发送前未读正文，界面不声称已读。
3. 发送后轨迹显示统一 Fetcher 读取该 URL；成功回答依据对应本次正文。另以有标注的受控验证覆盖失败、摘要、解析未完成，不能用这些模拟结果代替真实成功链。
4. 换赛道/栏目/筛选后候选变为新列表，已选华为云引用保持原身份；离开资讯后不再出现在其他页候选中，迟到列表不能污染新页。
5. 本轮结果可核对读取时点和版本/hash；后续抓取即使内容改变，旧回答依据仍绑定原结果。快资讯未因引用或读取进入资料库。

### 页面与权限回归

1. 大盘首轮 `@` 只列当前登记且可读取的指数/集合，带观察范围及读取结果 `asOf`；不出现全局 Wiki 议题，不开放无读取身份的情绪/资金流。集合成员须与登记范围一致。
2. `@` 公告 URL：Ask 读正文或解析状态且不入库；Agent 按既有慢资料入库契约处理后资料对象与公司时间线可回读，不把所有 URL 自动入库。
3. 个股/行业绑定对应插件；产业研究 Profile 走 `read_industry_profile`。
4. Ask→Agent 只加该插件维护工具；比较引用不改 target；公司插件无 Topic 写入。
5. 后续轮次仍能 `@`；chip 身份/版本不丢失、不改读最新。
6. 关闭再打开、切公司不串；关闭不中止任务。
7. 数据刷新保留 `operating_model`；确认发布后判断才更新并可回读新 hash。
8. 深度对话与问助手对同一对象读取语义一致。
9. 侧栏自有输入钉底，占位随 Ask/Agent 各一句权限说明，Ask/Agent 和模型选择真实可操作；无深度对话首页文案与通用 `+` 指令。首轮及后续轮次均能引用；窄窗口菜单不裁切。
10. 助手打开/关闭/切页/新讨论不改变深度对话的会话、草稿、模型、全局候选和运行任务。通过真实浏览器与 DSH 轨迹验收，模拟生命周期测试只作补充。
11. 分别从五个模块创建助手会话，核对五个不同角色绑定、实际生效的 system prompt 和 Ask/Agent 活跃工具清单；不能仅核对标题/占位或源码存在五份字符串。验证越权工具不可调用，切模式仅改变当前角色允许的增量；hook/子任务不得绕过角色边界。
