## 3. 审查方法与单一职责标准

先画“页面对象 → 宿主实际传入 → 模型可调用工具 → Backend 行为/副作用 → 后台后续动作”，不能仅按工具名称或 description 判断。

每个工具都填：业务对象、唯一目标、输入身份/版本、输出、读/写副作用、外部调用、后台任务/唤醒、授权要求、失败与取消语义、重试幂等、现有调用方、证据位置。

- 一个工具完成一个明确业务动作。下载、解析、校验可以是实现步骤；自动选择研究方向、补取多类数据、推断、创建对象、写关系不能隐含串成研究流程。
- 同类对象的批量读取不自动违背单一职责；也不为压缩工具数设计通用 `action` 大分发器。
- 组件是同一对象的一组内聚能力，不要求整组常驻每个角色；先审查现有 DSH 能力，不预建动态工具加载器。
- 已在固定上下文完整提供的内容不重复抓取；摘要/截断/缺失不能冒充已提供完整对象。保留版本一致性、原文下钻和失败解释。
- 工具数只是成本信号；同时评估正确完成所需调用数、参数负担、返回体积、误选概率与补证能力，禁止设数量 KPI 强行删能力。
- 列表/详情、多引用/单绑定、子栏目差异必须进入配置建议；不得用页面位置代替对象身份或修改授权。
- 准备候选、Jev 分类、用户确认、持久化与审计逐段标明 Owner；读工具记录审计不等于授权写知识。

## 5. 多 Agent 审查分工

用户授权以多角度、多 Agent 审查本文范围；此处编制分工，不代表已经启动审查。各 Agent 只读源码与已存在轨迹，主线程唯一回填本文，避免多人修改相同文件。

1. **页面与上下文审查**：五页对象、子栏目/列表/详情、固定快照/@读取、缺口与典型问题；交付对象矩阵与最小能力需求，不先按现有工具倒推需求。
2. **工具与 Backend 审查**：逐工具沿实现追到正式服务，登记副作用、职责重叠、隐含工作流及缺失原子能力；区分工具门面复杂与实际职责复杂。
3. **授权与生命周期审查**：提示词、注册、执行门禁、Jev 候选、option、finalize、后台维护、审计；检查“读取后自动写入”、未确认执行及非 Topic 改主张路径。
4. **主线程综合及反向复核**：合并前三份证据，再由独立审查视角挑战最小工具方案是否删掉必要能力、过度拆分或引入平行机制。争议先按代码/轨迹消解，真实产品选择才交用户。

按独立性并行前三项；综合依赖前三项完成。遵守 Agent 路由约定：定位与调用图交 explorer；跨模块边界判断交 planner，不让 explorer 代替架构裁决。每份回传最多 8 个重点发现、证据 file:line、影响、建议、反例及未验证项，不输出原始大段轨迹。

### 9.7 综合复核：已定协议、工程取舍与未决问题

- 已定：五页凡维护核心对象都须用户确认，确定性回放/准入不能例外；角色+目标门控不能替代授权。不得整体撤除共享 hook token；只读触达不得直接引发未确认的知识写入。
- 已定：Agent 交互复用 DSH 用户选项组件；不重新把自建聊天 option 卡列为等价产品方案。具体授权绑定、持久审计与后台结果承接仍须工程设计；子 Agent 不直接询问用户。
- 同日用户确认：按一次维护意图组织可选择的批量变更提案，逐项结果与审计；无新增不弹框，部分失败不伪装整批成功。
- 已定：硬关系是核心对象之间的直接关系；按 Stock standard 的隶属、股权、供应/客户、公司行业归属、行业上下游核对。系统分类映射单列；不因推导可达就新建直接硬边。
- 工程取舍：对照 research-candidates / research-links / page-drafts 的真实契约决定如何复用提案与授权，不能仅按名称让用户选存储。Jev 粒度、刷新回执 Owner、现有后台生命周期复用先给证据化方案；不新增第二执行器。
- 待界定：大盘榜单公司的历史行情/深入研究范围。不能由一条“模型需要半年背景”的轨迹直接推定常驻增加行情与计算工具；先判断该取数是否必要、符合页面场景，遵循现有大盘边界。
- 已定与后续：行业需要稳定 Backend 资料刷新能力，具体接口复用待核；非 Topic 后台不能修订主张。记忆后续专议，不在本工具审查中笼统改造所有记忆写入。
- §9.4/9.5 是审查建议，尚未批准实施。特别是默认保留通用方法/成果工具、行业雷达，以及“仅 generate 能提供 result_id”等结论，须检查实际对象可达性与反例，不能单靠当前未注册生成工具判定读取/计算能力永远无用。

### 9.8 场景与失败走查（轨迹 + 代码）

盘面解释追问榜单公司：market 缺 observe_market，模型转 query_observation/list_documents/topic_list/search_external（轨迹 2 例）。新闻分析：同一钾盐新闻 4 次路径 2~14 次，最长读到半年报，read_blocks 触发回放写入（代码）。公告入时间线：模型自述无维护权，只输出待人工文字——当前 0 步可达，提案是“从不可达到一轮”。行业刷新 / Profile 来源核验 / 公司经营数据缺口：无 Agent 轨迹，按代码走查：行业无独立刷新入口；Profile 研报需 index/scan/read 且 evidence_docs 身份未传；公司数据经 fetch_company_data 落 ResearchResult。无须维护：轨迹多数回合无写意图，但 settle 仍会 finalize 触达块。失败：URL 失败/超时/空正文措辞正确不当正文；无身份时 wiki_search 兜底；版本 pin 失败即拒；重复提案靠 extraction_id/Topic CAS 幂等，触达回放无跨回合去重；拒绝草案无路由只能过期；finalize 失败仅 notify，pending 下一问清空无重试记录。未验证：GBrain 导航连通、intel 页面实际是否触发入库、Backend 候选拒绝率、`structured_output`。
