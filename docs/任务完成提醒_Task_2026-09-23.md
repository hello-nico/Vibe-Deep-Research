# 任务完成提醒

状态：2026-09-23 前端已实施并回填，待用户与规划方验收。不提交、不 push。

权威：[产品对象模型与交互 v1](产品对象模型与交互_v1_2026-09-23.md) §3.2 动作模式（任务在对象上发起，完成后回到对象）。

## 1. 目标

「生成报告」「刷新资料」这类慢任务发起后，用户可离开当前页面；任务结束时，无论用户在哪个页面，右上角弹出提醒卡片，点击回到该对象。本期只覆盖这两类任务；公司研究等其改为后台任务后再接入。

## 2. 冻结决定

- **产品自建**：DSH 无通用通知服务（仅对话内发送失败提示），在产品外壳实现一个常驻“任务提醒”组件，不随路由卸载。
- **不存第二份真相**：任务状态一律从现有来源读取——报告：`GET /wiki/reports?slug=` 与 `sessions.findReportTask(slug)`（`components/WikiReportPane.tsx` 现有用法）；刷新：研究后台刷新检查记录与维护提案（`components/CompanyRefreshConfirm.tsx` 现有用法）。组件只保存“正在跟踪哪些任务”的清单。
- 清单存 `localStorage`（读写均 try/catch，失败时退化为仅本页生命周期内跟踪）；刷新浏览器后继续跟踪未完成项。完成、失败或超过 2 小时未结束的条目自动移除。
- 何时弹全局卡片：报告**生成成功 / 失败**；刷新**已写入 / 失败 / 出现待确认差异**。刷新**无变化**只在当前页轻提示（现状），不弹全局卡片。用户仍停留在发起页且该页已原地显示结果时，不再重复弹卡。
- 以后对象状态接口（设计稿 T4）就绪后，改由其提供状态；本 Task 的登记接口保持不变。

## 3. 视觉与交互规格（写死，不自行发挥）

- **样式**：复用 `components/refresh-confirm.css` 的 `.refresh-notice`（右上 `right: 24px; top: 80px`、宽 `min(360px, 100vw-32px)`、14px 圆角、卡片底与投影、左侧图标 + 标题 13px/600 + 说明 12px 灰字）。抽成共用样式（如 `.task-notice`），刷新组件现有提示同步改用它，保证两处一模一样。
- **位置与堆叠**：多条提醒自上而下堆叠，间距 8px，最多同时 3 条（更早的自动收起）。新卡片 200ms 淡入 + 上移 8px；`prefers-reduced-motion` 时无动画。
- **内容**：
  - 报告成功：图标 `FileText`（主色）；标题「〈对象名〉· 图文报告已生成」；说明「点击查看」。整卡可点，跳到对象页并切到「图文报告」分段。
  - 报告失败：图标 `CircleAlert`（警示色）；标题「〈对象名〉· 图文报告没有生成成功」；说明「可在「我的研究 · 任务」查看过程后重试」；右侧文字按钮「查看任务记录」→ `/my-research?tab=tasks`。
  - 刷新已写入：图标 `Check`；标题「〈对象名〉· 资料已更新」；说明沿用现有回执文案（如“已更新 N 项数据”）；点击跳对象页「研究页」。
  - 刷新待确认：标题「〈对象名〉· 发现新资料，待你确认」；点击跳对象页并打开现有确认框。
  - 刷新失败：标题「〈对象名〉· 这次未能检查完」；说明「资料保持原样，可稍后重试」。
- **关闭**：右上角 × 关闭；成功类 8 秒后自动消失（鼠标悬停时暂停计时）；失败与待确认类不自动消失。
- **对象跳转**：公司 `/research?company=<slug>`，行业 `/sectors/<key>`；跳转带上分段（报告 / 研究页）。
- **可访问性**：卡片容器 `role="status" aria-live="polite"`，失败类用 `role="alert"`；关闭按钮 `aria-label="关闭提醒"`。

  5. 多条提醒堆叠、关闭、自动消失与悬停暂停符合 §3。

## 6. Out of Scope

- 公司研究任务、后台知识整理、议题任务的提醒；顶栏“进行中任务数”标记与任务列表下拉。
- 浏览器系统通知、声音。
- 改动报告生成、刷新检查、确认与写入的业务逻辑与接口。

## 7. Stop Conditions

- 现有来源无法判断某任务已结束（只能靠页面原地状态得知）：停止该类任务接入，记录缺口，不自造状态。
- 需要改研究后台或 DSH 插件接口才能读取状态：停止，回填后另议。
- 与其他工具同时修改同一文件：停止并告知用户。

## 8. 回滚
