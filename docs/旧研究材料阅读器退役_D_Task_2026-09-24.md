## 1. 问题（Claude 核实）

- 公司页 / 行业页里点页内链接（如公司页“相关页面”、行业页“成员公司”，`components/WikiReport.tsx` `IndustryMembers` 的 `onOpenSlug`）或底部「相关研究材料」，`components/ResearchKnowledge.tsx` `WikiReader` 在原地打开被链接页（`trail` + URL `?reader=`，顶部「返回上一份材料」），而不是进对象主页。
- 「相关研究材料」来自 `GET /wiki/pages/related`，读不出正文的页返回标题“研究材料（正文暂不可读）”（如 `companies/002617-sz`、`companies/601985-sh`），仍显示为按钮。
- 旧申万二级页（如 `industries/801161-si`，页面自述“不是统计局分行业 Wiki”）以“行业研究”名义原地打开；对象登记层把它映射到 `/sectors/801161-si`，该路由不识别（todo 小遗留）。
- 「相关研究材料」卡片比正文宽，未与 `max-w-4xl` 正文对齐。

## 2. 冻结决定

- **去掉原地阅读**：`WikiReader` 删除 `trail`、`?reader=` 与「返回上一份材料」；页内链接与「相关研究材料」一律调用对象登记层 `openRegisteredObject`（公司 → 个股研究页；统计局行业 → 行业研究页；主题 / 对比 → 只读抽屉，沿现有 `drawer`）。其他使用 `WikiReader` 的地方（议题页、`WikiDrawer`）行为同样按对象跳转。
- **申万二级旧页**：`industries/<代码>-si` 这类非 `nbs-` 行业 slug 不再当“行业研究”打开。对象登记层能映射到「产业研究」对应页面（`/sectors/profiles/<代码>`，以该页真实存在为准）则跳过去，标签显示“产业研究”；不能映射则显示为不可点击的文字。不改 Backend 数据。
- **不可读条目隐藏**：`related` 中 Backend 标记为正文不可读的条目不显示（按接口返回的可读状态判断；若接口只给占位标题，则在 Backend 已有字段里找可靠标记，找不到按 §6 停止，不靠比对中文占位文案）。
- 「相关研究材料」改为对象标签样式（与对话里的对象标签一致，名称走登记层），卡片与正文同宽对齐。
- 不做兼容：旧 `?reader=` 链接不再解析。
