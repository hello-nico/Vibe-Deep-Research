# 议题与问助手改用统一右侧面板（T3-b）

状态：2026-09-24 Codex 已实施并完成自动检查；真实会话与视觉待用户验收，视觉收尾由 Claude 做。按用户本次指令，代码在独立 worktree 的 `codex/t3-b` 分支提交，不 push、不合并；未重启主目录工作台。

权威：[Human Checklist](../human-checklist.md)「T3 改走方案 B：产品面板嵌入原生对话（2026-09-24）」；[T3-c Task](任务过程原生视图_T3-c_Task_2026-09-24.md)（已验收的嵌入做法）；[产品对象模型与交互 v1](产品对象模型与交互_v1_2026-09-23.md) §4.2–4.3、§5「议题研究」行。

## 1. 目标

议题研究与问助手的对话都放进同一个产品右侧面板（`finance-side-panel`），面板内是 DSH 原生对话渲染；**不再切换主区前台会话**。面板打开时切换页面、点对象标签，面板与会话保持不变。

## 2. 现状（2026-09-24 Claude 核实）

- **议题页**：`components/layout/Layout.tsx` 对 `/my-research/topics/*` 用 `ConversationWorkspace split` 分屏，右侧是 DSH 主区对话；`pages/TopicWorkspace.tsx` 经 `research.restoreTopic / startTopic`（`dsh/client.tsx`）把议题会话 `remember()` 为**前台会话**（`uiWorkspace.openSession`），并用 `dsh/topic-session-gate.tsx` 在会话切换期间阻塞页面。结果：打开议题会替换深度对话的当前会话。
- **问助手**：`components/ui/FinanceAiDock.tsx` 自绘轨迹（`TaskTranscript`，带逐轮「保存为记录」`saveTurns`）+ 产品自己的输入框（Ask / Agent 模式、模型选择、页面上下文由 `assistant/prompt.ts` 组装）；`assistant/apply.ts` `focusAssistantSession` 也会切前台会话。
- **已验收的嵌入做法**（T3-c）：`dsh/panel-conversation.tsx` 注册 `finance.panel.conversation`，`sessions.retain` + `SessionProvider` + `conversation.content`（embedded，Chat 固定）；面板作用域 CSS 隐藏输入区（`components/task-process.css`）。
- DSH 轮次尾部有槽位 `conversation.chat.turnTail`（`dsh-client-ui-chat`），可用于每轮的附加操作。

## 3. 冻结决定

### 3.1 统一面板

- 右侧面板同一时刻只显示一个：任务过程 / 议题会话 / 问助手；后开的替换先开的。面板状态放在产品根（与现有 `openTaskProcess` 同级，可合并为一个 `sidePanel` 状态），路由切换不关闭面板；关闭按钮与 Esc 关闭。
- 嵌入沿用 T3-c 的 `finance.panel.conversation`，增加“可输入”模式：议题会话显示 DSH 原生输入区；只读模式保持隐藏。嵌入**不调用** `uiWorkspace.openSession`。

### 3.2 议题

- 议题页改为普通整宽页面（去掉 `ConversationWorkspace split` 与 `topic-session-gate` 的阻塞）；「继续研究」「新会话」在右侧面板打开该议题会话并发送原有开场消息（`TopicWorkspace` `prompt()`）。会话绑定仍写 `topic-sessions`（`bindTopicSession`），只是不再设为前台会话；`restoreTopic / startTopic` 改为返回会话 id 给面板，不 `remember()`。
- **空白态**：面板内新议题会话首屏不显示深度对话首页（hero）与「最近对话」（`conversation.input.dock` 注入）；显示议题开场：议题标题、当前判断一句（无则“尚未形成判断”）、最多 3 条 `next_questions` 作为可点选的问题（点选即发送）。
- 深度对话页行为不变；在深度对话主区直接打开某议题会话（如从历史对话）仍可用。

### 3.3 问助手

- 面板外框换为统一面板；**保留产品自己的输入区**（Ask / Agent 模式、模型选择、页面上下文与 @ 引用组装不变），输入区之上的对话记录改为原生只读嵌入（同 T3-c），替代 `TaskTranscript`。
- 「保存为记录」迁到原生视图：经 `conversation.chat.turnTail` 为问助手会话的每个已完成回答轮次加「保存为记录」，行为与现有 `SaveNoteButton` 一致（同一保存接口、同一去重）。仅问助手面板内出现，深度对话与议题不加。
- `focusAssistantSession` 不再切前台会话，改为打开问助手面板。

### 3.4 清理

- 本 Task 后无引用的代码删除：`TaskTranscript.tsx`、`topic-session-gate.tsx`、`ConversationWorkspace` 的 split 分支及其样式。`lib/taskTrajectory.ts` 仍被工具行名称、任务提醒等使用的部分保留，只删无引用的导出。不做兼容保留。

## 4. 前置验证（第一步，先做先回填）

- **执行方（自动）**：`cd desktop && npm run typecheck && env -u NODE_ENV node --test test/*.test.ts`；`git diff --check`；`node dsh/build-ui.mjs`；重启工作台。更新受影响的源码断言测试；新增纯函数测试（面板状态替换规则、议题开场问题选取）。回填 §4 三项结论。

  1. 深度对话里开着会话 A → 去议题页点「继续研究」：右侧面板出现议题会话并开始回答；回到深度对话，主区仍是 A。

## 9. 执行回填

### §4 前置验证（2026-09-24，实施前）

1. **通过，接口与渲染链已核对**：DSH `conversation.content` 的 embedded 分支仍渲染 `conversation.composer.bar`，输入调用绑定的 Session；`SessionProvider` 可承载 `sessions.retain(sessionId)` 取得的顶层会话。会话取消已有 `cancelSession` 正式接口；原生 Chat 订阅会话快照并逐步更新。T3-c 的 `.task-process-native [data-composer-seat]` 只读样式只作用于任务过程，议题面板需用单独容器。此处是源码/接口验证，真实发送与实时视觉留给用户验收。
2. **通过，已确定冲突处理**：当前主区会话由 `openedSessionId`/`remember` 管理；议题绑定可独立返回 session id，不调用 `remember`。当主区打开与面板相同的会话时关闭面板；面板请求同一当前主区会话时不重复挂载。需在实现中对这两条路径落实。
3. **通过，组合边界已核对**：问助手的模式切换、页面快照、@ 引用、模型选择与发送都在 `FinanceAiDock`/`assistant/apply` 的产品输入链，`TaskTranscript` 只消费只读轨迹。换为原生只读记录不改变 `startAssistant` 的提示与权限边界；原生 Chat 继续呈现权限提示。真实 Ask/Agent 对话由用户验收。
