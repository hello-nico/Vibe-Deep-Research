# 财报日及时性（2026-10-27）

## 1. 问题

报告挂出后，公开财务源多久能取到该期？数据源未到时，已解析原文能否稳定取出数据包核心数字？对应 [财报日及时性验证](../../tasks/active/财报日及时性验证_Task_2026-10-27.md)。供后续「最新报告期」口径设计，不改产品。

## 2. 方法与数据集

样本 46 家：关注 A 股 17 家 + 东财预约 10-28 至 10-31 的分层 29 家（沪/深主板、创业板；剔除 ST）。报告期 2026Q3 / 2026-09-30。名单 [sample.json](sample.json)。

V1 每 30 分钟记录：巨潮定期报告是否挂出（`RegularReportProvider.list_documents`，period=2026Q3）；新浪利润表 `report_list` 是否有 `20260930`；东财 F10 `ZYZBAjaxNew` 是否有 `REPORT_DATE=2026-09-30`。不用同花顺凭据。时长 = 本机首次看见数据源 − 首次看见巨潮；同一轮同时看见记 `same_round_≤30min`。首轮双方已到记左删失。

V2 对已入库且已解析的 2026Q3 正文（不含摘要）跑现有 `extract_report` + `select_reading`，字段为数据包用到的营收、归母、扣非、营业成本、经营现金流，毛利用营收−成本对东财 `MLR`。比对新浪 `lrb/llb` 与东财主要指标。容差：半个末位精度，整数半元。

## 3. 环境

2026-10-27T23:00:32+08:00 起首轮，Stock `.venv` Python，不装包、不读 `.env`、不重启。工作台 5930 / Backend 8700 只读。限流走现有 `eastmoney_api` / `sina_api` / `cninfo`。证据等级：集成探针。

## 5. 结论与适用边界

执行方客观观察（**待 Claude 判定「最新报告期」口径**）：本轮分辨率下，已挂出的 20 家新浪与东财均已有该期，不能证明源滞后于公告，只能证明 23:00 时点无可见缺口。真时延要靠 10-28 至 10-31 未披露样本被后续轮次抓住。巨潮/新浪/东财日期多为次日 0 点，不能当盘后时刻。同花顺未测。原文抽取目前不能作为归母、扣非的到达前替代；营收/成本/现金流在表头与别名碰巧对齐时数字可靠，覆盖不足一半。未入库的已披露报告（巨石、移动、万华）不在 V2 内。不能推出产品已切换口径。
