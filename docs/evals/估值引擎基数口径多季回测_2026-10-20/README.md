# 估值引擎基数口径多季回测

## 1. 问题

四种利润基数与同窗口价格锚，能否在多家公司、多个季度上稳定胜过上一季利润、最近两季平均利润这两条简单基线。
本轮只作技术验证，没有修改估值引擎或产品规则。结论：尚无证据支持全局切换到最近单季、滚动半年或固定季节性加权口径。

## 2. 方法与数据集

用户补充确认：“最近半年”使用滚动最近两季；C4 上一季与上年同季各 50%，价格锚也同权。
方法在查看汇总分数前写入 `.local/base-window-backtest/protocol.json`，北京时间 2026-10-20 11:51:49 冻结。
SHA-256：`c44f58bae6dfb68b68d06320bd6ca2abe8946249efb4a3c38fab05e987683f33`。
没有搜索权重、按公司挑口径，或按结果调整系数。

| 方案 | 利润基数 | 价格锚 |
|---|---|---|
| C1 | 最近四季利润之和 ÷ 4 | 同四季区间全部日收盘均价 |
| C2 | 最近单季利润 | 同一季的日收盘均价 |
| C3 | 最近两季利润之和 ÷ 2 | 同两季区间全部日收盘均价 |
| C4 | 上一季利润 × 50% + 上年同季利润 × 50% | 这两个季度的各自均价，同样各占 50% |
| L1 | 上一季利润原样 | 不加价格项 |
| L2 | 最近两季利润之和 ÷ 2 | 不加价格项 |

每个候选：`推算单季利润 = 候选利润基数 + Σ 冻结年化系数/4 × (目标季均价 − 候选同窗口锚价)`。
实际调用 Stock 主目录 `app.analysis.sensitivity.sensitivity`，输入基数乘四、最后输出除四；所有候选、所有季度使用同一家公司同一批年化系数。
这些系数来自上一轮按已合入引擎 prepare 重算的 2026H1 模型，原件与代码哈希一同冻结，不重新估计税率、成本占比、销量、产品结构或归属比例。

这是一项**当今模型固定系数下的窗口对照实验**，不是历史时点滚动建模。2026H1 结构用于回看 2025，含后见信息；不能把结果当成真实事前预测收益或严格样本外能力。
基数绝不读取目标季利润；C4 只读取上年同季。历史年报究竟在当时哪一天可用、后来有无追溯更正，没有逐次还原。
因此即使某候选胜出，也还需要时点数据验证才能决定产品口径。

## 4. 结果

APE = `|推算 − 实际| / |实际|`。MAPE 为公司季度等权平均 APE，中位数也按季度计算；严格小于基线绝对金额误差才算赢，平局另记，不当胜利。
零利润会保留金额差、令相对误差缺口；亏损或绝对利润低于预先记录的 1,000 万元只作标记、不删除。本次没有零利润、亏损或该阈值以下样本。

## 5. 推荐与不适用情形

**推荐本轮不作全局口径切换。** C1 是这批固定系数样本中 MAPE 最低的候选，可保留为现行对照；它仅比 L1/L2 低 1.74/2.70 个百分点，赢 L1 的季度不足一半，2025 年还明显落后基线。
C2、C3、C4 没有形成跨公司、跨年份稳定优于两基线的证据。这里没有证明“TTM 就是正确口径”，也不能按公司事后挑一项最低误差作路由。
最终由 Claude 判定是否需要新 Task，不能直接把本轮最小 MAPE 写成生产决策。

不适用或尚未证明的情形：

- 亏损、利润接近零：相对误差会放大或失去经济意义；固定正利润模板和倍数不应强套。本次未覆盖这些极端样本，不能声称验证过处理能力。
- 一次性损益大：累计净利润本身包含非经常损益。本次复用包只有归母与集团净利，没有逐季扣非全覆盖，不能识别全部一次性损益季；没有按结果剔除它们。
- 结构变化、产销量或成本结构变化：固定 2026H1 系数不代表 2025 当时系数；公司收购、投产、销量、税率、少数股东比例变化都未校准。
- 公司实际售价与主连基差变化：煤代理尤其明显；百分比变量缺实际观测时只能给条件推算，不能称全部因素已解释。
- 季节性与报告可得时点：C4 虽有固定季节性权重，未拟合公司的季节规律；历史披露时点、可得模型版本也未逐次重建。

下一步若要决定生产口径，应先用当时可得的报告/模型版本做滚动验证，并保留这次冻结结果作对照；不应继续围绕神火某一季回调系数或权重。
