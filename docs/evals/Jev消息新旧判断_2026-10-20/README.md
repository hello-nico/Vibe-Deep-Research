# Jev 消息新旧判断（2026-10-20）

## 1. 问题

Jev 能否判断同一公司两条消息是「同一事件改写」还是「新进展」，是否比现行标题去重更全且不误合并。对应 [Jev消息新旧判断](../../tasks/archived/Jev消息新旧判断_Task_2026-10-20.md)。

## 2. 方法与数据集

样本：四批已标注资讯里同公司、日历 7 天内的标题对。先按事件键人工冻结 123 对（改写 50 / 新进展 40 / 无关 33），含跨来源改写、预告→正式（神火 112.05%→114.54%）、增持计划→完成→再抛、回购不同日。标注规则：同一数字同一日为改写；同一主题新数字或新阶段为进展；否则无关。标注时不看 Jev。无正文摘要（标题+来源+时间）。

Jev 一问 `choice`：rewrite / progress / unrelated，问法冻结于 `.local/jev-event-novelty/question.json`，结果后不改问法。现行规则：`same_story` 或 `same_event`（规范化相同/包含/同一带小数数字+公共文字）；产品窗口 48 小时另计。批量 `jev eval` 每批 8 对；20 条单条计时。

## 3. 环境

2026-10-20。`typesafe-ai/jev`，Vercel AI Gateway。密钥仅 `AI_GATEWAY_API_KEY`。未改代码、未碰 5930。

## 4. 结果

| --- | ---: | ---: | ---: |

Jev 混淆：改写→进展 3；进展→改写 2、无关 1；无关→进展 1、改写 1。

## 5. 结论与适用边界

Jev 漏合并远少于现行规则（3 vs 24），误合并略多（3 vs 1）。问法未按结果改。没有摘要，无日期标题易被判成进展。不能推出已接入产品。防过拟合：事件键来自本批标题，未在未见公司上重标。
