## 1. 目标

议题页有三个分段：研究页 / 证据墙 / 图文报告。证据墙把议题里的对象和它们之间的关系画出来，可以画假设线、点线看依据、请助手找依据升格；研究页显示“判断之后依据有更新”。

## 2. 冻结决定

### 2.1 议题页结构

- `pages/TopicWorkspace.tsx` 页头分段从现有「研究页 / 图文报告」扩为「研究页 / 证据墙 / 图文报告」，分段记在 URL（`?view=wall|report`），默认研究页。主按钮「继续研究」与「更多」不变（T3-b 已改为右侧面板）。

### 2.2 证据墙（画板 ①④）

- 数据：`GET /wiki/research-topics/{id}/wall`（T6-a）+ `basis-changes`（T5-b）；代理放行已由 T6-a 完成。标签名走对象登记层（`lib/objectRegistry.ts`），悬停出预览卡，点击节点打开对象主页（面板保持）。
- 渲染：DOM 节点卡片 + 一层 SVG 连线，**不引入新图形库**。节点卡片沿用对象标签视觉（类型图标 + 名称 + 类型小字）。
- 连线样式：硬关系深色实线带箭头 + 中文谓词标签；研究关联橙色实线；假设灰色虚线，标签“假设 · <说明>”；判断便签到依据对象为细虚线箭头。
- 判断便签：左上固定，显示判断状态、判断时间、判断正文前 2–3 行；无判断显示“尚未形成判断”。
- “判断后有更新”：`basis-changes` 中 `changed` 的研究页对应节点加标记；点击标记切到研究页分段并展开该项差异。
- 选中一条线弹出小卡：硬关系显示“只读”、关系文字、「查看依据（N）」（打开现有依据面板，逐条 `claim:`）；研究关联显示理由与依据；假设打开假设面板（2.3）。
- 布局：确定性自动排布纯函数（议题研究对象居中；资料、记录在左；其他公司 / 行业在右；判断便签左上），同输入同输出；可拖动节点，位置按议题存 `localStorage`（读写包 try/catch，失败即回到自动排布）；「重新排布」清除本议题位置。缩放 50%–150%，平移用拖动空白处。
- 截断：接口 `truncated: true` 时在墙角提示“对象较多，只显示前 60 个”。`sections.hard = "unavailable"` 时图例处提示“事实关系暂不可用”，不画假硬线。
- 空白态（画板 ④）：无节点时显示说明与「继续研究」。

### 2.3 假设（画板 ②）

- 「画假设线」进入画线状态（顶部提示“按 Esc 取消”）：依次点两个节点，弹出一句话输入（1–200 字），「保存假设」调用 `POST /wiki/research-links/hypotheses`；同对端点已有假设时提示并选中原假设。
- 点假设线打开右侧假设面板（沿用 `finance-side-panel` 契约）：未核验标记、创建时间、说明；「找依据」→ 打开议题右侧会话（T3-b）并发送一句请求：“请核对这条假设并找依据：<端点A> — <端点B>：<说明>（假设 ID）”；「撤回假设」二次确认后调用 withdraw。
- 升格提案：议题 Agent 经现有提案流程（`research-links/propose` 带 `hypothesis_id` 与 `basis`）给出后，假设面板“升格提案”区读取该议题待确认提案中带本 `hypothesis_id` 的一条，显示理由与依据链接，「确认升格」/「保持假设」分别调用 confirm / reject；成功后刷新墙，线变为研究关联实线。
- 议题 Agent 侧：Stock `dsh/src/topic-tools.mjs` 的 `topic_propose_link` 需能带 `hypothesisId` 与 `basis`（若 T6-a 未覆盖则在本 Task 补齐，只改工具参数透传与说明），`MY_RESEARCH_PROMPT` 加一句：收到找依据请求时核对原文，找到依据才提升格提案，找不到如实说明。

### 2.4 研究页的依据变化（画板 ③，即 T5-c2）

- 当前判断下方：`basis-changes` 有 `changed` 时显示“判断之后依据有更新”卡：每个依据一行（对象标签、按“研究结论 / 数据更新 / 资料时间线”计数、判断时 → 现在的日期）；可展开，按类别显示前后片段（`/wiki/pages/diff`，数字变化单列）；无变化的依据折叠为一行“资料无变化”。
- 卡片右上「带着这些变化继续研究」：打开议题右侧会话并发送“继续研究这个议题，先看判断之后依据的变化”。只提示、不自动改判断。
- `version_unknown` / `page_missing` 显示“无法对比”。
- 研究页右栏加「墙上对象」小卡（对象标签 + 线的计数 + 「打开证据墙」）。

## 4. 验收

- **执行方（自动）**：Vibe `npm run typecheck && env -u NODE_ENV node --test test/*.test.ts`、`node dsh/build-ui.mjs`；如改 Stock 则 `cd dsh && pnpm run test` 与构建；`git diff --check`；重启工作台。新增测试：排布纯函数（确定性、分区、便签位置）；连线样式映射（三种 + 依据箭头）；“判断后有更新”标记映射；假设输入校验与同端点去重；升格提案按 `hypothesis_id` 匹配；localStorage 失败回退。
- **用户验收**：
  1. 打开“电力行业公司结构”议题 → 证据墙：看到对象、长江电力持股湖北能源的实线与依据；判断便签指向依据。
  2. 画一条假设线并保存；刷新后仍在；拖动节点后刷新位置保持，「重新排布」复原。
  3. 点假设「找依据」：右侧议题会话开始核对；若给出升格提案，确认后变为实线。
  4. 刷新某依据公司资料使研究页更新后：墙上该节点出现“判断后有更新”；研究页出现变化卡，可展开看差异，可「带着这些变化继续研究」。

## 6. Stop Conditions

- T6-a 接口字段不足以画出设计稿中的某类线或节点：停止，回填缺口，不在前端拼数据。
- 升格需要改变提案 / 确认语义：停止回填。
- 60 个节点、200 条线时交互明显卡顿（拖动掉帧）：停止回填实测与方案（再评估是否引入图形库）。
- 与其他工具同时修改同一文件：先看 git 状态，冲突时停下告知用户。
