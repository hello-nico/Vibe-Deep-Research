## 已确认边界

1. 不默认统一为申万二级口径。东财、申万及未来来源保留自身身份、分类与数据口径，通过可维护映射关联。
2. 申万不是所有研究入口必须经过的中间层；允许对象直接建立适当关联。
3. 映射支持一对多、多对多、部分重叠及暂无对应；名称相似不代表等价。现有 41 个工业行业 Wiki 不强行吸收服务业等其他分类。
4. 支持手动拖入核心对象、移动节点、连线和填写关系说明；保留「加入研究画布」按钮，不要求跨页面拖拽才能完成操作。
5. 初步承载为 Topic 的研究画布，作为已有研究内容的一种视图。具体入口、布局和创建时机待 UI 梳理；不因浏览/拖拽自动创建正式 Topic。
6. 节点引用已有对象，同一对象可以参与多个研究；移除画布实例不删除原公司、Wiki、资料、成果或其他 Topic 的引用。
7. 用户假设、比较意图和可能错误的判断可以记录。后续修订保留原判断、理由、来源和过程，不以每次都正确作为记录前提。
8. 研究记录不等于事实准入或用户采纳；主线与后台沿用 M9.1–M9.3 的执行、审计和隔离边界。

## A. 多口径映射与跨页面入口

- 保留来源命名空间、原始代码、名称和口径；金额/涨跌幅绑定原统计对象和数据时点。
- Backend 拥有映射配置与查询，前端和 Agent 读取同一结果。核查并复用现有映射，避免重复维护同一关系。
- 映射需表达两端身份、对应性质（等价/宽窄口径/部分重叠）、依据及变更来源；具体字段与存储在原契约中确定。
- 「动态」指可维护、随来源变化修订、按当前对象查询；不代表模型每次凭名称猜测映射。
- 行情板块进入对应产业研究、相关 Wiki 和已有研究；行业/产业页面可反向查看相关对象。多候选可选择，无映射明确显示缺口。
- 不通过映射汇总重叠板块资金；多个产业共用板块时，不各自宣称拥有全部板块净额。
- 映射变化不得静默改写既有研究快照的身份、口径或当时引用；当前对应关系与历史上下文可以辨认。

## B. Topic 研究画布与对象复用

- 首条路径：一个行情板块/行情快照、一份产业研究、两家公司、相关证据或结论、一个 Topic。
- 节点引用业务对象；画布组织展示、选择和研究关系，不复制 Wiki 正文或另存金融事实。
- 支持加入、拖动、连接、关系说明、打开原对象、移除当前实例；具体卡片形态和操作方式待用户确认。
- 行情观察保留研究时点，区分最新行情与当时依据；刷新不能无声替换原判断依据。
- 从节点按需展开关联，默认不铺开全库图谱。
- 关系区分：分类映射、证据支持的研究关系、用户研究意图/假设。视觉表现待 UI 梳理，语义不能合并。
- 用户连线可保存为带作者和时点的研究关系；不自动修改公共分类映射，不提升为已核验硬关系。
- 跨 Topic 复用同一对象时，局部假设/说明保持各自上下文；共享对象更新不覆盖原有研究判断。

## C. 选中研究与结果回挂

- 框选节点及相关连线，带用户问题继续对话；向 DSH 提供对象身份、关系说明和有界摘要，按需补读材料。
- 所选内容是研究上下文，不是系统指令；不自动注入整张画布、全库知识或历史 Session。
- 结果可关联回来源 Topic/对象，并打开资料与证据；保存失败不显示已关联，重试不重复关联。
- 用户操作与 Agent 建议分别可追溯；后台复用既有交接 Owner、执行记录和来源会话，不灌回主线续写。
- M9.3 自动 Wiki/Topic 审计修订包未完成部分仍由 M9.3 拥有；本 Task 不假设已经上线，不另建执行器补位。

## 已确认的视觉方向

- 样式贴合产品本身：沿用现有配色、字体、卡片、圆角、阴影及交互组件，与行情页、Wiki 和 Topic 保持一致。外部白板产品用于参考交互，不直接照搬视觉皮肤。
- 用户要求效果尽量酷炫：重点打磨拖拽反馈、节点展开、连线建立与路径高亮、缩放聚焦、研究结果回挂的动效和空间层次。具体效果组合待 UI 方案确认，不要求机械叠加所有特效。
- 动效服务于对象关系和研究过程的理解；保持文字、数值、证据及连线标签清晰，避免遮挡、持续闪烁或动画阻塞操作。兼顾流畅度和减少动态效果偏好。
- 保留产品已验收的加载扫描与章节过渡体验；最终以真实浏览器中的静态观感、动态交互及用户验收判断，不以截图或构建通过代替。

- 未确认 UI 决定会影响用户行为或保存语义：保持该部分未实施，不自行补全产品决策。
- 出现双写、跨 Topic 串关系、原件删除、旧快照覆盖新判断或主线受阻：停止扩展，修复所属 Owner。
