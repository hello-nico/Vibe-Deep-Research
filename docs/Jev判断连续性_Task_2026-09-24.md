# Jev 判断连续性（M9.7 第一类落地）

状态：2026-09-24 用户确认，待 Codex 实施并回填 §9。**执行方只跑自动检查，不做真实 Jev 调用**（凭据由用户自行配置）。不提交、不 push。实施仓库为 Stock-Research（`backend/` 为主，`dsh/` 仅接线）。

权威：[M9.7 设计](Jev知识关系导航试验_Task_M9.7_2026-09-18.md) §2–§7；[Human Checklist](../human-checklist.md)「Jev 判断接入边界（2026-09-20）」「Jev 判断连续性（2026-09-24）」；[T5 设计](版本与差异_T5_设计_2026-09-23.md) §2 第 5 点；T5-b / T5-c1（依据带版本与 `basis-changes`）。

## 1. 目标

议题判断所依据的研究页发布新版本后，由 Backend 在后台请 Jev 判断“这些变化对该议题当前判断意味着什么”，结果作为**提示**附在依据变化上，供议题 Agent 续研与后续议题页（T5-c2）使用。**不自动修改判断。**

## 2. 用户决定（2026-09-24）

- 连续性指**判断连续性**（依据变化 → 对当前判断的影响），不是“新对话属于哪个议题”。
- **只发公开内容**：议题判断文字 + 研究页“研究结论 / 数据”两类块的前后片段。不发资料时间线、对话原文、上传资料正文、研究记录。
- 真实调用由用户在 Backend 环境配置 `AI_GATEWAY_API_KEY` 并设 `STOCK_RESEARCH_JEV_ENABLED=1` 后开启；执行方不接触、不打印凭据。

## 3. 现状（2026-09-24 Claude 核实）

- Backend 已有 Jev 适配：`backend/app/services/maintenance_jev.py`（Vercel AI Gateway `typesafe-ai/jev`，choice 问题带固定题库、公开片段、有界输入与重试、失败抛 `MaintenanceJevError` 不转业务结论、审计 `request_id` / 用量）；当前 `STOCK_RESEARCH_JEV_ENABLED=0`、无凭据。
- 依据与差异：`GET /wiki/research-topics/{id}/basis-changes`（T5-b）、`/wiki/pages/diff` 与 `wiki/page_diff.py` `compare_specs`（T5-a）；发布写台账在 `gbrain_adapter._commit_index`。
- 议题 Agent 经 `topic_basis_changes`（T5-c1）读取依据变化。

## 4. 冻结决定

- **传输复用**：把 `maintenance_jev.py` 中与用途无关的部分（配置、请求与重试、响应解析、审计、错误类型）提为 `app/services/jev_gateway.py`；维护审核与本 Task 各自持有题库与状态结构。维护审核行为与测试不变。
- **触发**：研究页发布成功后（台账已追加），Backend 找出 `judgment.basis_refs` 含 `page:<该 slug>@<旧版本>` 且旧版本 ≠ 新版本的议题，为每个议题排一次后台判断（进程内异步任务，单飞：同一议题同一版本对只跑一次；不阻塞、不影响发布结果）。
- **输入（状态）**：议题判断文字（≤2000 字）+ 判断状态；公开片段 ≤8 段：来自 `compare_specs` 中 `category` 为 `research` / `data` 的变化块，`before` / `after` 各截 1200 字，片段 `ref` 用 `page:<slug>@<from>→<to>#<kind>`；不含 `timeline`。无可发送片段时记 `insufficient_input`，不调用。
- **题目**（choice，封闭答案）：
  - `basis_change_effect`：对当前判断的影响 = `unaffected` / `supports` / `weakens` / `challenges` / `insufficient`；
  - `revisit_needed`：是否需要重新审视判断 = `yes` / `no` / `insufficient`。
- **结果存储**：`research/topic-continuity/`（Backend 自有，按议题一个 JSONL，只追加）：`topic_id`、`judged_at`（判断版本）、`slug`、`from`、`to`、`status`（`completed` / `not_enabled` / `insufficient_input` / `provider_error` / `budget_exhausted`）、`answers`（选项与概率）、`audit`、`created_at`。状态互不混用，概率不作为任何写入权限。
- **读取**：`basis-changes` 每个 `changed` 页附 `continuity`（该议题当前 `judged_at` 与该页 `from→to` 的最新一条；无则 `null`）。另提供 `GET /wiki/research-topics/{id}/continuity` 列出全部记录（只读）。
- **预算**：`STOCK_RESEARCH_JEV_DAILY_LIMIT`（默认 50 次请求 / 自然日，Backend 本地计数），超出记 `budget_exhausted`；单次请求沿用现有 `max_input_bytes` 与超时 / 重试上限。
- **议题 Agent**：`MY_RESEARCH_PROMPT` 加一句：`basis_change_effect` 是外部分类器的提示，结合差异自行判断；`challenges` / `weakens` 时向用户说明并讨论是否修订，仍不自动改判断；`not_enabled` 等状态如实说明“未做自动评估”。

## 5. 范围

- Backend：`app/services/jev_gateway.py`（提取）、`app/services/maintenance_jev.py`（改为使用网关）、`app/services/topic_continuity.py`（题库、状态构造、存储、预算、单飞）、发布后触发接线（`gbrain_adapter` 发布成功回调或 `api/v1/wiki.py` 发布路径，择一且不改发布锁语义）、`basis-changes` 附结果、continuity 只读接口、测试。
- Stock DSH：`dsh/src/consumers.mjs` 提示词一句。
- 同步 Stock `docs/human-checklist.md`；Vibe `human-checklist.md` 已由 Claude 记录用户决定。

## 6. 验收

- **执行方（自动，全部用假 Jev 客户端）**：`cd backend && uv run pytest -q`（已知环境类失败同 T5-a §9）；`cd dsh && pnpm run test`；两仓 `git diff --check`；重建 Backend 容器与 `dsh/dist`，重启工作台。新增测试：
  - 发布新版本只为依据含旧版本的议题排判断；同一议题同一版本对只跑一次；发布结果不受判断失败影响；
  - 状态构造只含 research / data 片段、截断、≤8 段；无片段记 `insufficient_input` 不调用；
  - 开关关闭记 `not_enabled`；超出日上限记 `budget_exhausted`；网关错误记 `provider_error` 且不写业务答案；
  - 完成时记录选项、概率与审计；`basis-changes` 带出对应结果；只读接口不触发调用；
  - 维护审核原有 Jev 测试全部通过（传输提取无行为变化）。
- **用户验收**：
  1. 未开启时：刷新一家作为议题依据的公司资料并发布新版本，打开 `basis-changes`，该页 `continuity.status = not_enabled`；议题续研时 Agent 说明“未做自动评估”。
  2. 用户自行配置凭据并开启后，重复一次：`continuity.status = completed`，给出影响与是否需要重审；议题续研时 Agent 引用该提示并讨论，但不自动改判断。

## 7. Out of Scope

- M9.7 另两类（判断复核、实体与关系整理）；“新对话属于哪个议题”的研究连续性；议题页展示（T5-c2）；离线质量评估（校准 / 验收集）——开启后另立；资料依据的连续性。

## 8. Stop Conditions

- 研究页块内容无法区分公开与私有（例如研究块中直接嵌入上传资料原文）：停止，回填样例，由用户定发送边界。
- 发布后触发需要改变发布锁或发布顺序：停止，回填方案。
- 提取网关导致维护审核行为变化：停止，回填差异。
- 与其他工具同时修改同一文件：先看 git 状态，冲突时停下告知用户。
