状态：目标已授权；依赖 M6-B 展示边界确定，类型与工具数据契约待核验；业务代码未实施。

## 权威与目标

遵循 [M4](研究闭环与DSH交互_M4_2026-09-08.md)、[M6](架构边界与UI组合方案_M6_2026-09-09.md) 与 [Human Checklist](../human-checklist.md)。

优先复用现有真实数据和文件成果机制。K 线与产业链图二选一，不能因截图示例就假定数据接口存在。

## 已核对的事实

- 当前已安装 DSH `conversation.chat.turnTail` 是 chain，首个接受者获胜；原生 deliverables 已使用，新增消费者不能遮掉原生文件成果。
- deliverables 还拥有 `chatFileMentions`，覆盖服务可能破坏既有正文文件引用。
- `presentResult` 是展示意图，不是已存在的通用 HTML 执行容器。
- 当前产品已依赖 ECharts，但依赖存在不证明 Agent 能生成、存储或恢复交互成果。

## Owner 与拟议实现

| Owner | 工作 |
| --- | --- |
| 数据与研究工具 | 获取真实输入，携带口径与证据；需要计算时走既有确定性计算 |
| 成果工具 | 验证输入并确定性生成一种成果；返回实际保存结果，失败不能报完成 |
| DSH | 保持消息身份、Session 和已有文件成果，提供可共存的成果展示位置 |
| Finance 成果组件 | 渲染已验证结构、交互和展开，复用 M6-B 的来源下钻 |
| FinanceShell | 布局、主题及展开位置，不承担生成和存储 |

建议 DSH 提供可追加的消息成果展示位置，并保证与原生 deliverables 共存；具体命名、owner props 和清理规则由 DSH 契约确定。本文件不把建议命名写成可调用接口。
成果采用受控结构和确定性 renderer；本轮无需模型生成任意可执行 HTML。

## 执行顺序

1. 在正式工具目录中核对 K 线或产业链数据，以有真实输入和来源的一种作为首例，记录选择。
2. 确定 DSH 追加展示接口；如果需要跨仓库修改，先确认范围，不改打包产物。
3. 复用现有受控工作区文件能力保存成果及来源，消息关联使用持久身份，不新增数据库。
4. 实现单一工具和渲染器，错误不留下可误认为成功的卡片。
5. 对话展示、展开和历史重开通过后，才讨论产业信号栏目卡片化。

## 验收

- 自然语言问题触发真实工具；数据来自本轮调用，来源可通过 M6-B 核对。
- 同一已保存输入产生一致图形；模型不能注入任意脚本或控制宿主页面。
- 对话内有图形并能进行所选类型的实际交互，不能只给文件下载链接代替。
- 展开、关闭、窄屏和主题正常；切会话没有残留成果。
- 刷新和重开历史读回同一成果，无需模型重新生成；文件缺失/损坏明确显示。
- 原生文件成果与新成果共存；不用 fixture 演示替代真实业务验收。

## Out of Scope

多图形通用平台、自由 HTML 执行、Artifact 数据库、产业信号整体改版、自动发布、全站插件迁移、页面助手执行路径变更。

## Stop Conditions

- 需要竞争 turnTail 或替换原生消息 renderer：回到 DSH owner 确认接口。
- 首个成果必须新增数据源、存储体系或扩大文件读取权限：先明确必要性和范围。
- 无法证明来源、真实保存或历史恢复：不标记成果完成。

## 当前检查结果

完成现有展示机制核对，尚无真实生成与恢复结果。M6-B 未通过前，不将 C 的展示草图视为交付。
