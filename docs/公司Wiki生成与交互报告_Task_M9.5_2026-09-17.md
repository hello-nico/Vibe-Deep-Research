## A. 缺页公司的明确研究入口

1. 详情缺页时显示公司名、代码、当前资料状态，主操作为「开始研究」，辅助操作保留上传资料。压缩无意义空白；不把“已加入研究”当作已生成知识。
2. 开始前核对 Backend 真实缺页；目录读取失败不得误判不存在。已有 Wiki 返回阅读，缺数据与整页不存在分别呈现。
3. 点击明确启动以该公司 Wiki 为产出的有界研究；复用现有 DSH 会话入口与 Backend 创建/沉淀能力。不能只发一句普通问答后让用户自行猜是否保存。
4. 先复用已有资料、事实和研究；不足时按现有工具协议补取必要证据，不为了填满报告刷新全量数据，不要求用户先上传 PDF。
5. 页面可查看真实执行进度、来源会话、失败原因及最终 Wiki；记录复用既有执行记录 Owner。离开公司页不将 DSH 任务等同于页面 fetch 取消；取消沿原生生命周期。
6. 同一公司执行中重复点击回到已有任务；失败可重试，成功只在 Backend 正式可读后显示。已有部分成果要保留并说明，不伪装全部完成。
7. 完成后刷新该公司与名单状态，重新打开仍可读；中途切换公司不得串用旧任务、错误或报告。列表不以仅有 slug 或模型口头“完成”判断成功。
8. 建立事实基础页和研究判断写入仍经 Backend 原有校验/审计；草案显示草案，正式页显示正式页。若当前 API 不能完成缺页创建，必须补齐同一 Owner 的最小契约，不能将 404 记作已完成。
9. 普通聊天不强制建 Wiki；本入口是用户主动启动。主线问答与后续后台沉淀保持隔离，不因建页或报告生成唤醒主线续写。
10. 本包先闭合已支持的 A 股 Company Wiki；港美股沿当前能力说明，不把未支持的创建入口伪装可用。

## B. 四类 Wiki 的模板底稿

每类有可独立阅读的底稿和缺数据表现；共用字体、主题、数字、引用及交互基础设施，业务叙事不同。

| Wiki 类型 | 底稿的阅读顺序 | 按真实数据生成的表达 |
| --- | --- | --- |
| Company | 公司身份与业务 → 关键经营证据 → 当前判断/边界 → 时间线与缺口 | 多期财务趋势、业务构成、现金流比较；缺数时用证据与机制说明，不硬造估值图 |
| Industry | 行业身份/口径 → 供需与利润机制 → 周期位置证据 → 传导与验证条件 | 同口径趋势、有依据的产业链或机制示意；41 行业身份与申万/东财分类明确区分 |
| Theme | 研究问题 → 核心判断与机制 → 支持/反证 → 催化事件与待验证条件 | 事件时间线、证据分组、定性机制图；图中推断和已证实关系明确区分 |
| Comparison | 比较对象/问题/可比性 → 同口径差异 → 权衡结论 → 缺口与下一验证点 | 对齐期间的矩阵、差异或趋势图；不可比项单列，不编综合评分与优劣排名 |

- `industry_code`、`page_status` 等内部字段不直接输出为正文；业务身份转换为中文，必要口径与时间仍可见，系统状态放适当状态区。
- 标题、导语、旁注、图表、表格、来源相互配合；支持目录定位、查看数据、引用下钻等有实际用途的交互，不能满页相同卡片或纯 Markdown 列表。
- 数量由真实内容决定，不按类型硬凑固定张数。纯定性 Wiki 也必须有完整设计，不能返回空报告或随意量化研究判断。
- 第一视口直接呈现该类 Wiki 的核心判断或最强证据，不以标题与元信息当封面；读者只看首屏应能复述主结论。
- 四类底稿共用固定字级刻度（标题/章节/正文/标签/注释），同类元素同字号同字重；生成层不得自定义任意字号与字重。
- 保留桌面工作区宽度；长文行宽受控、图表按内容展开，避免外层大卡片再嵌窄 A4 卡片。手机收为单栏，不以缩小字体解决溢出。

## C. 底稿与按数据生成的两层契约

1. 第一层是确定性模板：读取 Wiki 已有内容即可展示，有模型故障也可阅读；四类底稿均需真实样例证明。
2. 第二层是 Agent 生成：输入固定 Wiki 内容版本、相关已保存成果/数据及引用映射、该类型底稿和所需 Skill 片段；输出针对该份内容组织的 HTML 交互报告。允许选择图型、密度、旁注、章节重点和缺口呈现，保留底稿视觉约束。
3. 本 Task 建议首次点击图文报告时先显示底稿并启动一次生成；有同内容版本报告则直接复用；显式重新生成才重做。同一请求并发合并，不因组件重挂、切主题或返回页面重复调用模型。
4. Wiki 更新后旧报告保留对应版本标识，提示可更新；不能将旧报告包装为最新，也不能把生成中途的新正文混入旧快照。失败时保留可读底稿/此前报告及重试入口。
5. 生成只负责表达，不补造事实或在报告阶段继续广泛检索，不修改 Wiki 判断、Topic 或用户记忆。缺数据应显示缺口；用户继续研究后，由正式知识流程更新 Wiki，再生成新报告。
6. 所有数值来自输入数据或既有确定性计算；图表与精确数据表共用数据与筛选，标明时间、单位、口径和来源。模型不得重新心算派生值或用装饰数填槽。
7. 同一结论只保留一个证据主场；摘要卡、正文与表格不得以同等权重重复同一论点，后续位置只做精确查对与来源展开。
8. 图表编码必须诚实：长度类默认零基线，同组比较共享同一刻度与轨道，直接标注优先于图例；没有趋势、对比、构成或阈值关系要表达时不画图。
9. 生成版必须包含与该 Wiki 材料绑定的组织几何（比较基线、阈值、时间轴或同类结构）；换成其他对象数据仍原样成立的版式视为换皮。
10. DSH 拥有生成执行与模型；Backend 拥有持久报告成果、所依据 Wiki 版本/快照和来源绑定；Client 仅保存选择。优先扩展现有成果契约，不建第二 Artifact 数据库、浏览器模型链或新调度器。
11. 实施前明确现有成果是否可承载 HTML、内容版本与来源，写下最小接口差异；不得假定现在已支持任意 HTML。具体字段与路由由实际 Owner 契约确定。
12. 生成 HTML 在隔离容器中展示，执行能力仅服务本地交互；不得访问主页面 DOM、凭据、任意网络或任意导航。依赖使用受控本地资源，不直接照搬 CDN 脚本。
13. 来源点击通过校验后的引用映射交给现有依据面板；容器消息校验来源窗口、报告身份、动作及参数，不接受任意 URL/命令。图表数据、文本及资料中的指令都不能扩张生成权限。
14. 校验缺字段、非法引用、内容/数据不匹配、脚本加载失败与尺寸溢出；失败降级并保留记录。结构校验不证明研究判断正确，也不能声称机器已验证所有语义。
15. 原 Wiki 内容、引用和历史始终可访问；报告是有版本的表达成果，不成为第二份知识真相。会话里已有报告不因新版本而悄悄改值。

## E. 后台子 Agent 插件与只读过程（2026-09-18 确认）

**问题与范围**
- 当前 `client.tsx/startReportTask` 用顶层 `sessions.create → bind → prompt`；`WikiReportPane` 经 `openSession` 跳入深度对话，顶层会话又通过普通历史的 `!parentId` 筛选。工具受限不等于子 Agent 隔离。
- 将报告生成改为真实 DSH 子 Agent；报告与现有「知识整理」接入同一可复用插件的任务入口、过程查看和结果导航。知识整理保留原 `background-review.mjs` 触发 Owner，不启动第二套沉淀。
- 本包不把用户主动参与的公司研究对话一并改成后台任务，也不改变 Wiki/Topic 发布授权、报告模板和内容生成规则。

**Owner 与原生接缝**
- DSH 唯一拥有执行、父子身份、工具权限、日志和中止；Backend 唯一拥有报告/Wiki 等成果。产品插件只做任务身份绑定、原生执行适配与只读展示，不建队列、调度器、第二套会话或轨迹正文副本。
- 实施前检查安装版 `dsh-subagent`、`dsh-subagent-spawn-in-process`、`dsh-client-ui-subagent`、`dsh-client-ui-trajectory` 的真实 API/export；记录原生 spawn、身份绑定、首个 stream、取消和 UI 挂载顺序。包存在不代表支持独立挂载；不得凭名称假设接口。
- 从 Wiki 页启动可能没有来源对话：先核对原生 parent/host 要求。不得借用任意当前聊天或伪造 parentId；若必须新增专用任务宿主，先写清最小生命周期、历史隔离与卸载行为，涉及新持久化 Owner 时停止裁决。
- 子 Agent 在首次模型请求前完成身份和工具作用域绑定；报告继续只暴露既有 4 个报告工具，固定 slug/input_hash/来源快照，不继承无关聊天内容，不触发知识沉淀、不回灌主线回答。知识整理继续自己的权限与结果契约。
- 复用/扩展现有任务索引，记录业务对象、来源与原生执行 ID、成果引用；不复制 JSONL。运行/结束依据原生事件与持久日志，成功还需 Backend 成果回读；索引中的展示投影不成为第二执行权威。

**用户交互与生命周期**
- 「生成过程」在当前业务页打开可展开的只读面板；「我的研究／后台任务」使用同一查看器。保留任务标题、目标、状态、耗时、原生工具执行轨迹与结果入口，支持运行中订阅及完成后回看。
- 去掉输入框、上传、模型/权限选择、新建对话、对话/历史页签；只呈现执行过程。复用原生轨迹组件，不通过挂完整聊天再 CSS 隐藏控件实现。日志下载若保留，沿用现有权限与脱敏边界。
- 查看过程不调用普通 `openSession`，不导航深度对话、不覆盖当前聊天选择。关闭面板、切页或下一次提问不取消已交接任务；监听随查看器卸载释放，执行生命周期独立。
- 中止走实际支持的原生 run/control API，不能假设 one-shot 子 Agent 支持 continuable 控制接口。失败/取消/超时如实展示；重试是有独立执行记录的任务尝试，保留旧轨迹和成果，不开放续聊。
- 同对象同版本运行中重复点击复用；异版本运行中保留明确冲突行为。刷新或重启后从原生日志与 Backend 回读；无法确认时显示中断/待确认，不伪报成功、不自动重跑，也不承诺断点续跑。
- 既存顶层报告会话按正式 `report-tasks.json` 绑定识别，从最近对话、历史和默认会话选择中排除；旧直达入口转只读任务查看。禁止靠标题匹配、删除/批量归档、改写历史父子关系；历史报告与轨迹保持可访问，普通对话不受影响。

**实施与验收**
1. 先核对上述原生能力和现有报告/知识整理调用链，再实现一个共享插件接缝与查看器；两类任务保留各自业务工具、输入、触发与成果处理，不做通用工作流平台。
