## 1. 问题

2026-09-23 全量检查前端用户可见文案（`desktop/src` 金融页面、问助手、深度对话壳、`desktop/dsh/finance-ui`，以及 Stock 侧确认框中显示的维护选项），生硬之处集中为四类：

1. 只说“不做什么”，不说“能帮你什么”（“不取数、不写”“非推荐 / 非预测”）。
2. 内部名词直接上屏：快照、会话绑定、回查、回执、准入、Backend、编排器、底座、槽位、Topic、Wiki、主体标识。
3. 状态提示没有下一步，或一句叠三层免责。
4. 同一概念多种叫法：沉淀 / 记录 / 研究记录；Wiki / 研究页 / 资料页；议题 / Topic。

## 2. 目标与原则

- 先说用户能得到什么；限制只在会误解时说明。
- 界面不出现内部名词；开发诊断信息不上屏。
- 失败与等待给出下一步，一句话讲完。
- 统一术语（§3）。
- 模式名**保持 Ask / Agent**，只改说明文字。
- 只改展示文案，不改变行为、权限、数据流与模型输入。

## 3. 术语对照

| 现有叫法 | 统一为 |
|---|---|
| 沉淀、独立沉淀记录、存入沉淀 | 研究记录；“保存为记录” |
| Topic（用户可见处） | 议题 |
| Wiki（用户可见处）、资料页 | 研究页 |
| 回查、回执、待核实（执行结果） | 查看结果、确认中 |
| 正在取、抓取、拉取、存档 | 加载 / 更新、上次的内容 |
| Theme、Comparison | 主题研究、对比研究 |
| 本页对象 | 本页条目 |

## 8. Stop Conditions

- 某条文案被代码逻辑用作判断条件（字符串匹配、正则解析）：保留原串，记录到 §9，不连带改逻辑。

- 测试断言的是行为语义而非措辞：不为让测试通过而改断言含义，先核对后再定。
- 同一处文案两次调整仍难以兼顾准确与简洁：保留原文并记录，交用户裁决。
