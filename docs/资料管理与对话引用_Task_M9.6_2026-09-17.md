# M9.6：资料管理、双入口上传与对话引用

状态：2026-09-17 调研与交接稿；本轮仅写 Task，未实施、未做真实上传/模型/浏览器验收。

## 目标与范围

闭环：用户从「我的资料」或深度对话上传 PDF / TXT / MD → 同一资料库可见 → 阅读 → @ 选择资料提问 → 回到可核对的原文。
用户确认原始资料不限公司研报；未来可能导入网页 URL、YouTube 等链接。本期完成文件闭环，链接导入另期实施。
遵循 [Human Checklist](../human-checklist.md)、M8.5 数据归属、M6-B 依据阅读契约；与 M9.5 Wiki 报告互补，不恢复已暂停的 M9.4 画布。

## A. 页面设计

1. 页面主体是资料，顶栏为「搜索资料」和「上传资料」；上传表单放弹层/侧栏，拖入文件可唤起上传队列。空库时显示简洁拖放区及支持格式。
2. 默认紧凑列表：文件类型图标、标题、简短内容预览（仅已有解析文本）、格式、大小、添加时间、处理状态；公司/议题关联有则显示，不强制占位。
3. 搜索标题/文件名，按类型与处理状态筛选，按添加时间排序；结果分页/加载更多，不能把前 200 项冒充全部。全文搜索仅在复用现有索引可实现时纳入并明确范围。
4. 点击资料打开阅读页或右侧预览，沿用既有阅读/依据组件；保留列表筛选与滚动位置，返回无需重找。窄屏采用独立阅读页。
5. 行内主操作为阅读、引用到对话；下载原件、修改显示标题、重试处理放合适的操作菜单。修改标题不改文件内容、document_id 或历史引用。
6. 支持多选后引用到对话。首期不引入文件夹树、批量移动、复杂标签系统、装饰性统计卡或独立知识图。
7. 本期不新增永久删除；若沿用已有移除功能，必须明确移除资料库条目与删除原件/证据的区别，不级联破坏历史研究。缺失引用仍可解释。
8. 遵循产品明暗主题、橙色强调、字体与共享控件；用清晰层次、文档缩略预览、选择反馈和细腻过渡改善质感。不得给 TXT/MD 伪造 PDF 封面或生成装饰图占位。
9. 加载、空库、筛选无结果、读取失败、处理中、部分失败分别呈现；错误不在大块空白中静默消失。

## B. 两个上传入口，同一份资料

1. 「我的资料」和深度对话加号/附件入口都接同一 Backend 文档接收、原件保存、解析及证据链；DSH 仍拥有附件交互和会话身份，不改写原生运行时内部。
2. 本期支持 PDF、UTF-8 TXT、UTF-8 MD（含 BOM）；空文件、无效编码、格式不符、超限分别返回可操作说明。其他格式明确不支持，不以改扩展名处理。
3. 公司关联变为可选；普通笔记、跨公司对比、行业材料均可保存。模型建议的公司归属不能变成上传前置条件或未经核实的硬关系。
4. 复用 Backend Document 模型并审计 symbol 必填的所有实际消费者；保留已有 PDF 研报和已绑定公司数据的行为，不将通用资料伪装某公司研报。
5. 支持批量选择，逐文件显示上传与处理结果；一个失败不回滚已保存原件。原件保存成功后即应在列表可见，解析/索引未完成显示真实状态。
6. 文件体积限制以现有 32 MB 为起点贯通两入口与代理；批量并发、数量按现有能力设有界值并记录，不绕过限制或无限并发。
7. 上传前只是输入框本地待选附件，可移除；开始上传时明确提示将保存到「我的资料」。上传成功后，即使未发消息或移除输入框 chip，资料仍在库中；上传失败不得伪装已保存。
8. 重试和重复上传复用既有内容去重能力并核实作用域；同内容重试不多建条目，同名不同内容不得覆盖历史原件。需要版本变更时沿 Backend 正式身份契约。
9. 刷新或离开页面后可回读已保存条目与真实处理状态；不凭浏览器本地 pending 状态宣称后台仍执行。服务中断可恢复/重试的范围以现有执行能力明确报告。
10. DSH 原生附件的临时副本可以承担传输，但不能成为第二个持久资料 Owner；接入中断、Backend 失败和 DSH 发送失败各自保留可解释状态，不能重复执行双份解析。

## C. @ 资料与问答引用

1. 扩展现有 @ 研究对象选择器，增加「资料」类别，按名称搜索并展示类型、时间、状态以区分同名项；支持键盘选择和移除已选 chip。
2. 引用传递稳定 document_id 及发送时可读取的解析版本/哈希，复用现有契约；不是只把文件名贴进问题，也不将整库正文注入提示词。
3. 资料页「引用到对话」与对话内 @ 使用同一引用协议。先放入输入框待发送，由用户补问题；不得点击就隐式提交问题或创建 Topic。
4. 接收的原件未解析好时可显示待就绪 chip；发送前说明不能读正文，允许移除后继续，不把“已保存”当作“可供模型引用”。
5. 发送后引用成为持久消息的一部分，重开会话仍可定位相同资料/版本；资料重解析不悄悄改变旧回答引用。版本不可用显示明确缺口。
6. 模型按问题读取选中资料的必要 Block/片段，区分文件整体与已读范围；不因 @ 触发全量外部补数、不自动扫描全部资料。
7. @ 选择表示关注资料，模型若需使用其他来源应明确来源；用户说“只基于这些资料”时按该范围执行，资料不足如实说明。
8. 回答引用可回到 PDF 页码或 TXT/MD 的对应段落/行范围；文本文件不得伪造页码。原件、解析正文、证据索引状态分开。
9. MD 阅读禁执行脚本/危险 HTML，外部图片和链接按现有内容策略处理；资料正文不是系统指令，不可借附件内容扩大工具权限。
10. 沿现有 DSH 原生扩展点完成，不新增常驻“资料管理工具大全”、平行聊天输入框或执行器。资料不会因上传自动成为 Wiki 或已核实事实。

## 未来链接来源（明确延期）

- URL / YouTube 将来也进入同一资料列表，保留来源链接、获取时间、可读内容与定位能力；不按文件夹或供应商另建资料库。

## 验收与交接

1. 两仓基线和相关未提交改动先核对，避免覆盖 M9.5；只沿当前正式入口推进，不恢复旧资料库。
2. 每个入口分别上传真实 PDF、TXT、MD；至少一份无公司资料、一份同名不同内容、多文件中部分失败。刷新后列表/原件/正文一致。
3. 深度对话上传成功但不发送，确认我的资料可见；从资料库 @ 同一条目，确认没有再次上传/解析；发送后重开会话可读引用。
4. 真模型问题至少覆盖一份 PDF 引用和一份文本定位，以及跨文件比较；核对实际读到的 Block 与回答依据。测试夹具通过不代表完成。
5. 验证解析/索引失败、超限、重复点击、重试、切页、Backend 中断、缺失版本、无匹配搜索；分页不得漏报总量或重复条目。
6. 明/暗主题、桌面/窄屏截图及交互记录：上传队列、资料列表、预览、@ 选择、chip、来源返回。外部竞品截图不能充当产品验收。
7. 运行相关 Backend 文档/解析与引用测试、产品页面和 DSH 附件集成测试、类型检查与 diff 检查；记录真实命令及结果。
8. 所有 Execute / Review / Smoke 更新本 Task；附可复现会话/文档定位、已验证与未验证范围，用户拥有最终视觉验收。

## Stop Conditions

- DSH 无安全的原生附件/@ 接缝：记录安装版机制与最小可行接入供裁决，不修改 node_modules 或另造聊天执行器。
- 去掉公司必填会破坏现有文档身份/证据/去重或需要破坏性迁移：先列出具体影响和最小方案，不用虚假股票代码占位。
- 只能依赖 DSH 临时文件或 Client 正文副本实现列表，或无法绑定历史引用：停止该路径，修正 Owner 契约。
- 两次补丁仍不闭合上传/引用，或只能用假状态掩盖处理失败：保留轨迹重审契约，不继续补丁叠加。
