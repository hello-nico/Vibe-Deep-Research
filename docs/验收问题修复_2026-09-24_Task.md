### A. 关闭「查看依据」后公司页首卡空白

- 复现（用户）：个股研究 → 国电电力研究页 → 财务块任一「查看依据」→ 右侧依据面板正常显示 → 关闭面板 → 页首公司身份卡（`components/ResearchKnowledge.tsx` `WikiBody` 公司分支的 `GlassCard glow`：图标、“公司研究 · 日期”、名称、股票代码 / 所属行业 / 行业大类）只剩卡片底纹，内容与右上角光晕都不见；下方「经营」等卡正常。
- 线索（未证实）：依据面板属于 `finance-side-panel`，打开 / 关闭时 `research-surfaces.css` 的 `:has(.finance-side-panel)` 改变主区宽度；`.glass` 带 `backdrop-filter: blur(14px)`，`.glass-glow` 带 `overflow: hidden` 与 `::before` 光晕（`src/index.css`）。怀疑为宽度变化后合成层未重绘；也可能是面板关闭触发了该卡重新挂载或状态被清空。**须先定位真实原因再修**，不得用强制重挂整页等掩盖手段。

### B. 图文报告与公司研究同时进行时报告无法保存

- 复现（用户）：国电电力 15:51:08 开始公司研究（研究中），15:51:38 生成图文报告。报告任务按开始时的研究页版本钉住（Stock `dsh/src/research-material-tools.mjs` `state.reportTask.inputHash`）；期间公司研究发布了新版本，保存时 Backend `POST /wiki/reports` 返回 409「页面版本已变化」（`backend/app/api/v1/wiki.py` `create_wiki_report`），重读又被钉住版本拒绝，任务只能作废。钉住本身是正确设计（不静默换稿），问题在产品层：
  - B1 同一研究页已有进行中的公司研究或知识整理时，仍可点「生成图文报告」；反之报告生成中仍可开始公司研究 / 刷新资料。
  - B2 报告未保存，任务列表却显示「已记录」：`pages/MyResearch.tsx` 把会话 `run_status === 'completed'` 映射为 `recorded`，不看报告是否真的保存。
  - B3 报告任务标题显示 slug（“图文报告 · companies/600795-sh”），应为公司 / 页面名称。

### C. 旧知识整理任务摘要为英文（仅核对）

- 「我的研究 · 任务」15:04 的知识整理摘要为英文（“Settlement for 600309.SH …”）。该记录早于 15:09 提示词修复（知识整理用户可见字段须为中文）。只核对新产生的整理记录为中文；旧记录不改。

## 2. 冻结决定

- **A**：定位根因并做最小修复；修复须覆盖依据面板、任务过程面板、问助手面板三种右侧面板的开 / 关（同一 `finance-side-panel` 契约），以及公司页、行业页的首卡。
- **B1**：同一研究页（同 slug）上，公司研究（含其知识整理阶段）与图文报告互斥：一方进行中时，另一方入口禁用并提示“公司研究进行中，完成后可生成图文报告” / “图文报告生成中，完成后可刷新资料”。判断依据用现有任务绑定（`reportTasks` `sessions` 的 `kind` / `slug`）与原生会话运行状态（`taskRunning`），不新增存储。不同公司之间不受影响。
- **B2**：报告任务状态以“是否真的保存”为准：会话结束后按 slug 查 Backend 报告（`/wiki/reports?slug=`）是否有 `created_at` 晚于任务开始的记录；有 → 「已生成」；无 → 「未保存」，摘要说明“研究页在生成期间已更新，请重新生成”，行上提供「重新生成」（对当前版本新开报告任务）。用词与现有任务状态表统一（`MyResearch.tsx` 状态映射）。
- **B3**：标题用 `bind.title` 或对象登记层解析的名称；取不到时再退回 slug。
- 不改变报告钉住版本、Backend 409 语义与发布锁。
