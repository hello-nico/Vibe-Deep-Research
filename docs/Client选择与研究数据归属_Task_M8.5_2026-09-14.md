## 实施顺序与验收产物

### A. 先收口接口和迁移清单

- 枚举所有记录写入者：页面问助手、已有报告/复盘/回测等仍在使用的保存入口；所有读取者：页面、DSH 工具、关联校验。禁止只迁 `MyResearch` 留下第二份正文。
- 盘点界面偏好的当前键与作用域，仅迁持久偏好；不迁密钥、模型凭据、临时输入、滚动位置或 DSH Session。
- 在现有模块契约定义记录创建/分页查询/读取/删除、研究名单操作及按对象 ID 查询；沿用可用接口，不新增通用存储框架。
- Backend 记录建议使用现有 PostgreSQL 与迁移机制，保持原记录 ID、分类、标题、Markdown 正文和时间；这是计划方案，不是已确认表结构。
- 明确删除已关联记录的行为、记录长度与分页、超时重试及重复创建处理，再进入迁移。无法从既有合同确定的用户语义提交用户判断。
- 实施采用以下约束：创建请求使用稳定的操作标识，超时后重试同一次保存不得重复；相同内容由用户再次主动保存不应被内容哈希自动吞掉。沿用现有 10 万字符长报告能力，超限明确拒绝，不截断正文。
- 列表只返回有界摘要、总数与分页信息，全文按 ID 读取；按保存时间倒序并以 ID 保证稳定排序。搜索在全量存储中完成，不能只筛当前页。`note-…` 与 `note:note-…` 沿用现有规范化规则，不改旧身份。
- 不新增记录编辑、共享、自动总结或自动转事实能力。删除关联记录是否拒绝、保留历史标记或解除关联，仍需先核对现有语义；若无定义，列出实际受影响对象请求用户裁决，只暂停删除与有关切换，不停下独立的选择/页面工作。
- 产物：已核对的消费者清单、接口契约、数据映射与可执行迁移检查项，更新既有 Owner 文档。

### B. Client 选择落 SQLite

- 在产品本地服务集中读写，前端 `watchlist`、公司选择和偏好消费同一入口；不让页面、DSH 各自打开数据库。
- 自选和加入研究分别保存，使用规范公司 ID；不把“加入研究”写进 Wiki 或当成 Topic 关系。
- 从旧自选台账迁移，保留现有选择；新研究名单不能按全部 Wiki 或全部自选自动填充。若存在历史显式加入研究的证据，仅据该证据迁移；否则从空名单开始，提供明确加入入口。
- 查询只带实际选择，支持列表分页/搜索；已加入但尚无 Wiki 的公司仍展示并说明资料状态，不静默消失。
- 验证 SQLite 事务、重启持久化、多页面并发、重复加入/移除和写入失败；变更失败不能显示成功。
- 优先复用当前运行环境可用的 SQLite 能力；数据库路径由产品持久数据根派生，禁止放临时目录、仓库跟踪路径或浏览器存储。服务负责连接关闭和迁移版本；不将 SQLite 连接放进 React 或 DSH 工具。
- 按单个对象增删并在库中保证唯一，不通过客户端旧快照替换整张名单。切换公司/快速搜索时取消或忽略过期响应；Backend 不可用时仍能读到本地选择，知识区域显示可重试的错误。
- 自选现有 A 股/港股/美股身份不缩水、不猜市场；加入研究遵循现有 Backend 支持范围，不支持的对象明确说明。无 Wiki 不等于无公司；从自选加入研究只保存选择，资料获取沿用现有明确入口，不把选择写入成功伪装成 Wiki 已生成。

### C. 沉淀记录归 Backend

- Backend 成为正文与记录身份唯一写入者；保存问答只创建记录，不自动创建 Topic 或关联。
- 前端记录服务改走 Backend；DSH 原有记录工具保留业务含义，原生 HTTP 读取，不再直接读产品文件。
- Backend 的关联校验读取同一记录存储；迁移保留既有 Note ID，旧 Topic/Link 不需重建。
- 迁移成功并完成读回后，移除记录台账挂载、旧环境变量、重复读取端点与旧 note 写入路径；保留仍有其他用途的 ledger 能力。
- “我的研究”开始对话时默认提供记录上下文；沿用有界摘要与按需读全文，不能声称模型已经读取未加载的所有记录。
- Agent 只对相关记录提议，用户确认才建立关联；无显著议题的大盘问答仍可独立保存与阅读。
- 记录接口失败不能返回空列表冒充“没有记录”，也不能阻止自选等独立区域使用；页面与 DSH 都应明确记录上下文是否实际加载。默认上下文仍有界，后续分页可检索更早记录。
- 记录正文、已有来源引用及来源上下文原样保存；展示摘要只作投影。不得从聊天文本猜造证据 ID，也不能为了迁移重写旧 API 来源或替换成最新数值。

### D. 页面与命名收敛

- 个股研究默认只显示加入研究名单，搜索和公司切换遵循同一范围；加入/移除入口和自选星标含义清楚，不恢复重复“从自选开始”按钮。
- 产业研究：申万 Profile 使用该产品名，说明真实分类/来源；现有产业信号收为研究入口内的栏目，保留已有功能和可访问路径。
- 行业研究继续展示 41 行业八块 Wiki；简介接口已经补齐，不重新生成内容。产业研究不得替换这套行业身份。
- 我的研究：搜索、页签和按钮复用现有样式；创建表单按需展开。议题显示实际问题/进展/对象，无内容不编进展。
- 记录展示清楚标题、日期和简短摘要，避免重复“问助手”和裸 Markdown；展开全文使用现有阅读/依据组件，保留原文与有效引用。
- 沿用已确认的页面布局与组件直接实施，提供真实页面截图供验收；只有新增交互语义、删除功能或改变对象归属才需另行决定。宽屏/窄屏、空/加载/错误/长标题均需检查。
- 加载复用 `ResearchLoading` 与现有 `renderLoading` 接口，保留扫描/章节轮换动画；动画不代表处理进度。财务估值刷新保留已读正文，状态绑定当前公司。不得再换成单纯骨架或建设 slot 注册中心。
- 引用复用 `ConversationCitations`、`EvidenceCard` 和原文阅读路径；保留短标题、悬停预览及失败后的「重新读取」。行业卡片继续用已有简介，不退回“规上利润”“已有正文”或统一占位说明。

### E. 迁移、切换与闭环验证

- 迁移先预览数量、ID、正文摘要哈希、时间和关联映射；备份旧文件，不输出私人正文或凭据到日志。
- 切换期间阻止旧入口继续写入；导入事务完成后读回核对再启用新入口，不长期双写。
- 相同 ID/内容重复运行不新增记录；同 ID 内容冲突、损坏输入或缺失引用应停止并报告，不能覆盖或静默跳过。
- 中断后可安全重试；保留原数据备份。切换后已产生新写入时，禁止直接回退到旧 JSON 丢失增量，必须先核对与导出新数据。
- 完成代码审查后按仓库与职责提议提交；未经用户请求不提交、不 push。

## 执行分包与交接要求

按以下依赖顺序完成，每包先验证再扩大范围；这些是同一 Task 的执行步骤，不另建重复计划。

1. **Backend 记录包（A → C 的服务部分）**：收口记录 API、存储、身份与关联校验，提供迁移预览/应用/读回工具；先对临时 PostgreSQL 库验证。不得提前删除产品旧文件。
2. **Client 选择包（B）**：SQLite 服务、自选与研究名单、持久偏好及旧自选迁移；名单与知识读取分离，独立验证。与记录包可独立准备，但实际运行切换要串行。
3. **消费者与页面包（C → D）**：产品与 DSH 接新接口，初始化解除互相阻塞，产业研究/我的研究/个股研究呈现收敛；记录创建、读取、关联必须消费同一 Backend 存储。
4. **真实切换与验收包（E）**：先停旧写入并备份，迁移核对后切换所有入口、重建受影响服务；检查运行中的版本，不能只编译源码。最后验证旧写入路径不可再用，备份仍可恢复。

交付必须列出两仓各自 diff、实际迁移前后数量及哈希核对结果、旧入口移除清单、运行/构建命令、页面截图和真实场景结果；说明测试使用的临时库、故障模拟、真实模型与未通过项。不得以 Agent 自述、单个 HTTP 200 或测试总数宣布验收。

Codex 后续审查顺序：用户闭环与职责归属 → 数据完整性与兼容行为 → 组件复用与代码规模 → 错误处理、测试及真实运行。重复状态、第二个正文 Owner、跨仓绕过接口、无当前需求的框架均需说明或收敛。

## 业务验收场景

| 场景 | 必须看到的结果 |
| --- | --- |
| 已有 Wiki，但未加入研究 | 个股研究不显示；显式加入后显示，重启仍在 |
| 自选与研究名单独立 | 加入/移除其中一个不改变另一个；Backend 知识不被删除 |
| 加入暂无 Wiki 公司 | 名单保留，可进入已有资料获取/研究流程；不伪造 Wiki |
| 保存两条问答 | Backend 可读回原文与引用，产品重开仍在；不自动创建 Topic |
| 连续研究 | DSH 获得记录上下文，只对相关记录提议，确认后关联；无关记录独立保留 |
| 迁移已有资料 | 旧 Note ID、正文、日期与 Topic 关联保持；既有议题继续研究可用 |

| 故障和重复操作 | Backend 不可用不报保存成功；重试不重复；迁移中断/冲突不丢数据 |
| 页面与证据 | 原文无裸 Markdown、无内部路径；依据可打开、追问可接续，空状态布局完整 |
| 多窗口选择 | 两个窗口先后加入不同公司都保留；移除 A 不覆盖另一个窗口新增 B |
| 长记录与旧记录检索 | 10 万字符范围的报告原样保存、可读；当前分页之外的记录可检索和关联 |
| 部分服务不可用 | Backend 停止时产品仍能打开和读取 Client 选择；记录/知识显示失败，恢复后重试成功 |
| 不同分类入口 | 行业研究仍进入 41 行业八块 Wiki；产业研究保留申万 Profile 内容和已有信号功能，来源说明清楚 |

M8.5 关闭须上述场景逐项有结果；确实不适用的遗留入口须有可达性证据。M8 的历史 API 引用缺存档、回答计算可靠性不在这里顺带修复，但迁移后有效引用打不开属于本任务回归，必须修复。最近华友钴业半年报第 39/40 页已实际读回，读取失败→重试恢复已验证；该结果不是所有历史引用均已修复的证明。

最低验证：迁移/持久化集成测试使用真实临时 SQLite 和 PostgreSQL 测试库；类型检查与相关回归；Computer 在真实页面跑保存→研究→确认→重开。明确模拟数据与真实模型轨迹各自证明范围，HTTP 200 或静态测试不算闭环通过。
