## 1. 问题

深度对话主对话里的工具行由 DSH 通用行渲染，显示英文工具名与原始参数（如 `today · {}`、`calculate_market_result · result:<id>`），与产品中文界面不一致，并暴露内部编号。问助手 / 任务过程已用 `lib/taskTrajectory.ts` 的中文名，深度对话没有。

## 2. 已核实（2026-09-24，Claude 只读，DSH 0.1.7-alpha.2）

- DSH 官方扩展点：keyed 槽位 `tool.call.toolview`（`@deepseek-ai/dsh-client-ui-tool` `contract/slots.d.ts`），按工具名注册即替换该工具的整行；未注册的工具仍走通用行。
- 官方样板 `dsh-client-ui-skill` 的 `SkillRow` 就是自绘整行（约 60 行 + 自带样式），只依赖 `dsh-client-ui-primitives`。**整行自绘是正式扩展方式**，不是补丁。
- 槽位入参 `ToolCallOwnerProps`：`toolName`、`callId`、`block`（运行中 `RunningToolCall{ name, argsRaw, time }` 或结束 `ToolResultNode{ call{name,argsRaw}, content, isError, callTime, time }`）、`useDisclosure`、`inspect?`（跳到轨迹）。
- 产品已有同类注册先例：`dsh/result-node.tsx` 用 `ctx.slots.inject(... register({ name, key }, Component))` 注册 `conversation.chat.node`。
- 中文名与参数摘要已有：`lib/taskTrajectory.ts` 的 `TOOL_LABELS`、`toolLabel`、`toolStepTitle(name, argsRaw)`（计算类型、区间、研究页等摘要）。

## 3. 冻结决定

- 只为**本产品研究插件注册的工具**注册行视图（Stock 插件工具，即 `TOOL_LABELS` 中除 `web_search`、`web_fetch`、`stock_search_external` 外的键）；DSH 自带工具保持原样。
- 一个组件 `FinanceToolRow`，按工具名循环注册；不为单个工具写专门视图。
- 标题与摘要复用 `toolStepTitle`，与任务过程面板同源；**摘要不得出现内部编号**：`result:`、`claim:`、`evidence:`、`source:`、`document:` 身份、64 位哈希、parse revision 一律不显示（有则只显示中文名）。研究页 slug 可显示。
- 视觉与 DSH 通用工具行一致（行高、字号、颜色、展开箭头、状态点、间距），参照 `dsh-client-ui-skill` 的 `SkillRow` 样式取值写入产品 CSS；**不引用 DSH 的哈希类名**。明暗主题都用变量。

## 4. 范围

### A. 行组件（`desktop/src/verticals/finance/dsh/tool-row.tsx` + `tool-row.css`，新增）

- 折叠态一行：展开箭头（可展开时）· 中文标题（含摘要）· 右侧耗时（结束后，`time - callTime`，同任务过程面板格式）。
- 状态：运行中显示进行中样式；出错时标题后显示“未完成”并用错误色；中止显示“已停止”。
- 展开态：“参数”（格式化 JSON，默认折叠长文本，最多 12 行可滚动）与“结果”（`content` 中的文本，最多 20 行可滚动；错误时显示经 `userFacingRuntimeError` 转换后的中文，原文仅在展开的“详情”里）。
- 有 `inspect` 时展开区底部显示“在轨迹中查看”。
- 用 `useDisclosure` 管理展开状态（与 DSH 行为一致，轮次重置时收起）。

### B. 注册（`dsh/client.tsx` 或 `dsh/result-node.tsx` 同处）

- 导出 `FINANCE_TOOL_NAMES`（来自 `TOOL_LABELS` 键，去掉 §3 排除项）；`for` 循环 `ctx.slots.inject('tool.call.toolview', () => ctx.slots.register({ name: 'tool.call.toolview', key: name }, FinanceToolRow))`。

### C. 术语对齐（`lib/taskTrajectory.ts` `TOOL_LABELS`，同时影响任务过程面板）

按界面术语表改：`topic_*` 的“研究主题”→“议题”（列出议题 / 读取议题 / 选择议题 / 更新议题 / 列出议题关联 / 提出议题关联）；`note_list` / `note_read` →“列出研究记录 / 读取研究记录”；`read_hard_relations` →“读取对象关系”；`read_research_links` →“读取研究关联”；`stage_extraction` →“暂存事实候选”；`wiki_schema_graph` →“读取关系类型”。其余不动。

### D. @ 下拉菜单被裁（2026-09-24 用户实测补充）

- 现象：对话为新会话、输入框靠近面板顶部时，输入 `@` 弹出的候选菜单向上展开，顶部条目（如“水泥”）被面板上沿裁掉。
- 已核实：DSH 菜单挂在 `[data-trigger-menu]`（`dsh-client-ui-input-trigger`），每个分组列表 `max-height: 180px`，公司 / 行业 / 资料三组叠加后超过输入框上方可用空间；外层滚动区 `overflow: hidden`。
- 修法：在 `dsh/native-dsh.css` 用 `#dsh-conversation [data-trigger-menu]` 限制整个菜单高度并内部滚动（按输入框上方可用空间，建议 `max-height: min(22rem, 45vh)`；若 DSH 支持向下展开则优先向下），不引用 DSH 哈希类名；深度对话全屏、右侧面板（问助手 / 议题）三处都不被裁。

## 5. 验收

- **执行方（自动）**：`cd desktop && npm run typecheck && node --test test/*.test.ts`；`git diff --check`；`node dsh/build-ui.mjs` 重建。新增测试：注册清单覆盖研究插件工具且不含 DSH 自带工具；摘要过滤内部编号（`result:…`、哈希、`document:…` 输入均不出现在标题）；错误态显示中文；术语对齐后的中文名。
- **用户验收（用户自己走）**：新会话里输入 `@`，候选菜单完整可见、可滚动，不被上沿裁掉。在深度对话里问一个会查资料、算指标的问题（如“海螺水泥上半年营收同比多少”），主对话工具行全部为中文（如“读取研究页 · companies/600585-sh”“计算 · 同比”），无英文工具名与 `result:` 编号；点开能看参数和结果；DSH 自带的网页搜索行不变。

## 6. Out of Scope

- 问助手 / 任务过程面板改用原生对话视图（T3）；DSH 过程分组的类别名（按工具名写死，金融工具归“已调用工具”）；模型思考内容中出现的工具名；DSH 原生“系统提示词 / Session 日志”入口。

## 7. Stop Conditions

- `tool.call.toolview` 注册后通用行仍显示（键不生效）或与 DSH 过程折叠冲突：停止，回填现象与 DSH 源码位置。
- 需要改 DSH 包或新增补丁：停止说明。
- 与其他工具同时修改同一文件：先看 git 状态，冲突时停下告知用户。

## 8. 回滚

删除新增组件与注册、还原 `TOOL_LABELS` 并重建；DSH 自动回到通用行。
