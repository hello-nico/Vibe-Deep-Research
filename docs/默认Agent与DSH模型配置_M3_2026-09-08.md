1. 首页使用原生 DSH 会话，取消旧接入弹窗与 Agent 开关。

## 职责与实现

| Owner | 本轮实现 |
| --- | --- |
| desktop/dsh-dev.ts | Vite 开发宿主启动独立 DSH 子进程；同源启动入口、HTTP/WS 代理；退出时终止自己启动的进程 |
| orchestrator/src/dsh_paths.ts | 路径优先级、目录访问检查、状态与工作目录隔离、运行时版本核对 |
| desktop/src/verticals/finance/dsh/NativeDsh.tsx | 产品外壳内加载 DSH 客户端；应用拥有外壳，DSH 拥有会话、消息、设置与事件 |
| desktop/src/verticals/finance/dsh/native-dsh.css | 产品主题映射与会话/设置外壳样式，不进 core |
| desktop/dsh/presets/vibe/ | 产品 Agent preset；当前装配助手 persona，研究工具留给 M4 |
| DSH | Provider、凭据解析、模型调用、会话日志、停止 |
| 现有业务服务 | 行情、台账、资料、旧研究 HTTP 路径 |

没有 iframe，不把 DSH 包装为旧 /chat 的 CLI Provider。React / ReactDOM 固定 18.3.1，Vite dedupe 与 DSH staticModules 共用实例。

应用替换 DSH 的 layout/sidebar 两个外壳插件，通过已有 slot 渲染 conversation、settings、overlay 和 details。目录按钮在 rc.1 composer 内硬编码，目前仅在会话容器内用 CSS 隐藏；工作区仍在后台注册。

替换 layout 时同步接管其主题展示职责：应用 DSH theme tokens、字号与深浅标记，并同步产品外壳。产品主题按钮把选择交给 DSH，DSH 设置保留主题配置权威。侧栏不能设置 backdrop-filter，否则内部原生设置的 fixed 遮罩会被限制在侧栏内。

视觉入口集中在 `desktop/src/verticals/finance/dsh/native-dsh.css`：产品 HSL 变量映射到 DSH 语义颜色，覆盖其全局 body 背景和字体，统一菜单、输入、消息、设置与暖橙强调色；不改行情涨跌语义。设置触发按钮按 slot 标记适配侧栏；弹窗宽度 880px、圆角 18px、分区边框与产品一致。不依赖 DSH 构建后的 hash 类名，不改安装目录。

实际运行时固定为本机 dsh-desktop 的带补丁 0.1.2-rc.1。本地 deepseek-harness 的 alpha.3 源码仅作机制参考，不能混用接口。当前类型路径仍假定相邻 dsh-desktop；任意安装布局尚未验证。

## 设置入口对齐产品导航

用户确认：侧栏「设置」不要用 DSH 默认触发器外观，用产品同一套 nav 样式包一层。右上角主题按钮与 DSH 设置配色重复，已从顶栏去掉；产品仍通过 `useDarkMode` 同步 DSH 主题到 `html`。

`Layout` 用 `workspace-nav-link` 包住 `#dsh-settings`（与「研究记录」同行高、13px、收起时只留图标）。内层仍是 DSH trigger，撑满这一行并继承颜色与 16px 图标；点击和弹窗仍走 DSH。不把「设置」写成 `/settings` 路由，不改设置内容。

入口位于 nav 内、紧接「研究记录」，不放在 flex-1 导航之后的独立底栏。内边距只由真实按钮承担，避免外层 padding 与按钮高度叠加。浏览器实测两行均为 40px 高、13px 字号、间隔 2px；收起时仅显示 16px 图标，展开/收起均可打开原生弹窗。fixed 遮罩正常相对视口定位，祖先不得用 filter/transform 等意外建立包含块。

## 配置与启动

继续使用仓库原有开发入口：首次或依赖变更运行 `./scripts/setup`，日常运行 `./scripts/start`。访问 http://127.0.0.1:5930/ 。前端代码自动更新；路径或启动配置修改后重启开发服务。

| 项目 | 优先级（从高到低） |
| --- | --- |
| 工作区 | VRA_DSH_WORKSPACE → 配置 workspace → 数据根/dsh-workspace |
| DSH 状态 | DSH_HOME → 配置 home → 数据根/dsh |
| DSH 安装 | VRA_DSH_RUNTIME → 配置 runtime → 相邻 dsh-desktop |
| 配置文件 | VRA_DSH_CONFIG → 仓库根 dsh.config.json（可缺省） |

数据根沿用 VRA_DATA_ROOT / 产品配置。相对路径相对仓库根。显式指定但不存在的配置报错；状态目录和工作区不能相同或嵌套，包括符号链接解析后的路径。

模型设置和凭据由 DSH 管理；不复制其他宿主认证文件，不读取浏览器旧 vr-llm。DSH 支持启动环境变量及状态目录、工作目录中的配置来源；指定这些路径和环境本身就是选择配置来源。

端口：5930 前端、8765 原业务 API、5941 DSH。开发宿主限本机，拒绝 VRA_LAN=1。启动认证留在服务器进程内，浏览器不接收启动 cookie；代理校验 Host / Origin 后转发。
