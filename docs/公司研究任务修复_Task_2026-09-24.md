## 1. 问题与证据（2026-09-24 用户实测 + Claude 诊断）

以海螺水泥研究任务 `5c0c7d93-…` 为例：研究 21 步、38 次工具调用、正常完成（`run_status: completed`），但：

1. **没有进入知识整理**（S2 闭环断点，最重要）：
   - 研究中有几次工具报错且模型随后自行纠正（`blockRange includes a Block not returned…`、`source_number_invalid`、`block_id … was not read as a materialized Block`）。
   - Stock `research-host.mjs` `dispatchReview` 在 `sourceErrorCount !== 0` 时直接不整理；计数来自 `research-tools.mjs:368`，**任何研究工具**报错都记入（含 `stage_extraction`、`calculate_metrics`），与是否已纠正无关。
   - 另两处同样静默跳过：`!jobsSettled`（研究结束时入库作业未完成；后台任务只有一轮，不会有下一轮补做）；`reviewSnapshot` 超过 160000 字符返回 `null`。
   - 跳过不留记录，任务列表只能一直显示“结果待确认”。万华化学那次（研究沉淀整理修复 Task §8.3）同样因来源报错整理未启动。
2. **「查看过程」整页白屏**：过程面板 `TaskTranscript` 的 `ResultEmbeds` 把轨迹中出现的所有 `result:` 都渲染为 `ResearchResult`；`fetch_company_data` 产生的 `kind: company_data` 成果没有 `missing` 字段，`ResultCard`（`components/ResearchResult.tsx:106`）`payload.missing.map` 抛错；外层无错误边界，整个根节点崩溃。
3. **「打开研究页」进不了公司页**：`MyResearch.tsx`（约 282、384 行）拼 `/research?company=<去掉 companies/ 的 slug>`，而个股页按完整 slug `companies/600585-sh` 匹配；行业报告被拼到个股页；旧公司研究记录目标拼成 `companies/600309`（缺交易所后缀）。
4. **标题用了代码**：研究任务标题存为 `公司研究 · 600585`，`CompanyWiki.tsx:166` 在 Wiki 标题与行情名都未取到时回退为代码。
5. **控制台刷屏**：`userFacingRuntimeError` 在渲染路径调用，同一错误反复 `console.warn` 数十次。

## 2. 冻结决定

- **已纠正的工具报错不阻止整理**：整理只能引用快照内成功读取的原文块（`validateReview` 对 refs 的校验不变），失败读取不会进入依据，放开不降低证据要求。
- 研究任务结束时若有入库作业未完成：**等待作业结束再整理**，上限 10 分钟；超时则按当时已读材料整理，并在任务记录中注明“年报入库未完成”。
- 任何跳过整理都写明原因，任务记录显示“本次没有整理：<人话原因>”，不再停在“结果待确认”。
- 过程面板一张成果出错只影响该卡片，不影响页面。

## 3. 范围

### A. Stock 整理闭环（Codex，Stock `dsh/`）

1. `dispatchReview` 去掉 `sourceErrorCount` 一票否决；`sourceErrors` 仍记录并写入快照（供整理 Agent 知道本轮有过读取失败），`finalize` 失败的既有语义不变。
2. 研究任务（`researchTask`）在 `turn/end` 时 `jobsSettled` 为假：保留 handoff，监听该研究状态的作业结束（现有 `markPeriodicReportDelivered` / 作业轮询路径），结束或 10 分钟超时后派发整理；研究子 Agent 释放时不得丢弃这次等待（沿用 S2 的 `entry.finalizing` 移交）。普通深度对话行为不变。
3. 快照超限、无可整理材料（`reviewSnapshot` 返回 `null`）、等待超时等跳过情形：研究任务写 `settlement_status: 'skipped'` 与 `settlement_reason`（枚举：`no_material` / `snapshot_too_large` / `ingest_timeout`），经 `updateResearchSettlement` 落到绑定。
4. 测试：有已纠正工具报错仍整理；作业未完成时等待后整理；超时按已读材料整理并带原因；快照为空 / 超限写 `skipped` 与原因；报告任务与 Ask 不受影响。
