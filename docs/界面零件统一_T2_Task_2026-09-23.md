状态：2026-09-23 用户确认，待实施。Claude Code 规划与验收，Codex / Cursor 按本文实施并回填 §9。不提交、不 push、不重启现用服务。

权威：[产品对象模型与交互 v1](产品对象模型与交互_v1_2026-09-23.md) §3.2 动作模式、§4 界面线（12 条原则）、§5 页面差距；[Human Checklist](../human-checklist.md)「产品对象模型与交互方向（2026-09-23）」。

## 1. 目标

把个股研究、行业研究、议题研究三个对象页的页头、刷新与生成反馈统一到同一套零件和同一个动作模式；修复议题页“最近对话”卡片排版。只改前端展示与交互，不改数据流、接口、权限与写入协议。

## 2. 冻结决定

- 页头结构：**返回 · 对象切换下拉 · 分段切换 · 主动作 · 「更多」菜单**。同类控件只用一种样式（原则 5、12）。
- 动作模式（设计稿 §3.2）：按钮只负责触发并显示简短文字状态，**不再转圈**；等待效果落在对象内容区域，统一使用新建研究页时的完整加载效果（`WikiLoading` / 非 compact `ResearchLoading`：左侧章节轮换 + 右侧当前章节骨架卡片，用户 2026-09-23 指定为样板）；完成后原地换成新内容；无变化则恢复原内容并轻提示；失败原地提示并可重试。
- 报告空态与生成中不再有「生成过程」按钮或“在生成过程里查看”的文字；需要排查时指向「我的研究 · 任务」。
- 已验收的扫描动画、章节轮换保留，不重新设计（AGENTS.md）。
- 左侧导航、集合页（我的资料风格）不动。右侧对话面板改造属 T3，本 Task 不改议题页左右分栏布局。

### B. 刷新动作模式（个股、行业、议题材料）

- `components/CompanyRefreshConfirm.tsx` 的 `RefreshConfirm` 增加向页面上报状态的回调（如 `onStateChange('idle' | 'checking' | 'updating')`），按钮去掉 `animate-spin`，只显示文字状态（“正在检查资料…”“资料更新中…”）。确认对话框内的 `animate-spin` 同样改为静态图标 + 文字。
- 个股、行业页据此把研究页内容区切换为 `WikiLoading`（标题“正在检查资料” / “正在更新资料”，章节用 `wikiLoadingSections(slug)`），与新建研究页同一效果。结束后按现有 `onUpdated` 刷新正文；无更新或失败时恢复原正文，轻提示保持现有顶部通知。检查期间用户切到图文报告分段不受影响。
- 议题页「刷新材料」采用同一完整加载效果（章节如“读取已关联材料”“核对研究页”“整理待确认关联”），按钮不转圈。
- 刷新检查、确认、回执的业务逻辑与接口调用不变。

### C. 生成报告动作模式

- `components/WikiReportPane.tsx`：
  - 删除 `processButton`（约 294 行）及其在空态、生成中、失败提示中的使用；删除“进度在生成过程里…”文案（约 311 行）；失败 / 结果未确认的提示（约 196、215–216 行）改为“可在「我的研究 · 任务」查看过程后重试”。
  - 生成中：报告区显示 `ResearchLoading`（非 compact），标题“正在生成图文报告”，步骤：读取报告方法 → 选择模板 → 读取研究页 → 组织图文 → 保存报告；研究页分段仍可切回阅读。步骤轮换是展示节奏，不宣称真实进度（与现有加载动画口径一致）。
  - 空态只保留说明 + 一个主按钮「生成报告」/「重新生成」。
- 议题页的图文报告视图若有生成入口，同样适用。

### D. 最近对话卡片修复

- `dsh/client.tsx` 约 704–712 行 compact 列表用 `sm:grid-cols-2`（按视口宽度），放在议题页窄分栏时两列过窄，标题与“继续研究 · 时间”被挤成竖排。改为按容器宽度决定列数（容器查询或最小列宽的自适应网格），窄容器单列；卡片内标题单行省略、元信息单行。

## 8. Stop Conditions

- 页头「更多」需要把页面业务逻辑搬进共用零件才能实现：停止，零件只接收动作列表，不承载业务。

- 与其他工具同时修改同一文件（先看 `git status` / 修改时间）：停止并告知用户（见 2026-09-23 research-input.ts 并发改动先例）。
