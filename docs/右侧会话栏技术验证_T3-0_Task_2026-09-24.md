## 3. 要回答的问题

1. **任务过程（只读）**：在任意产品页，用 `openResource` 打开 `subagentchat` 地址显示一个已完成的后台任务（报告、公司研究、知识整理各一），是否为只读原生视图；整轮折叠、中文工具行（`FinanceToolRow`）、任务清单卡片是否正常；运行中的任务能否实时更新与停止。
2. **顶层会话（交互）**：议题会话、问助手会话不是子会话。能否由产品仿照 `ui-subagent` 注册自己的资源与标签类型（如 `financesession`），持有该会话 `SessionReference` 并经 `sidebar.chat.conversation` 渲染；输入、发送、停止、Ask / Agent 模式（问助手绑定）是否可用；是否与主会话区的同一会话冲突。
3. **停靠面归属**：侧栏按会话持有停靠面。在个股页、议题页等非深度对话页，侧栏归属哪个会话？能否用一个**稳定的产品侧栏宿主会话**（可复用隐藏任务宿主，或新建专用宿主）承载所有侧栏标签，使切换页面、切换深度对话会话时侧栏标签不变；刷新后能否恢复。
4. **议题空白态**：议题新会话在侧栏中首屏能否替换为议题开场（不显示深度对话首页与“最近对话”）；可用哪个槽位或 CSS 范围。
5. **布局**：`push` 形态与产品布局（左导航、`#workspace-main`、现有 `finance-side-panel` 让位规则）是否兼容；两者择一还是可合并；宽度拖拽、全屏、窄屏表现；与 FinanceRoot 现有固定 `rightbar` 容器的关系。
6. **导航保持**：侧栏打开时点对象标签，主区路由切换，侧栏标签与会话是否保持不卸载。
7. **多标签**：同时开议题、问助手、任务过程三个标签，切换是否保留各自滚动与输入草稿。

## 4. 做法

- 原型用开发开关控制，默认关闭（如 `localStorage['finance-side-sessions'] = '1'`，读取包 try/catch）；开关关闭时产品行为完全不变。
- 在开关打开时提供最小入口：任务列表“查看过程”改走侧栏 `subagentchat`；议题页“继续研究”与问助手按钮改开侧栏会话标签。其余入口不动。
- 不改 DSH 包、不新增补丁；需要补丁才能实现的，按 §6 停止并说明。

### 关键结论与停止原因

DSH 右栏是**每个会话一套停靠面**，当前公开导航 `sidebarRight.openResource/openTab` 必须有前台已挂载的会话，并把标签写入该会话。`RightbarRoot` 只把被选中会话的面板显示出来。产品现有 `remember()`、议题 `restoreTopic/startTopic`、问助手 `focusAssistantSession` 都通过 `uiWorkspace.openSession(id)` 切换这个前台会话。因此，在议题侧栏打开后切换到另一深度对话会话，显示的必然是后者的停靠面；原标签保存在原会话下，却不继续显示。对象页路由切换若不切会话则可能保持，但不能据此满足“所有页面共用、切换深度对话仍在”的要求。

依据：`dsh-client-ui-sidebar-right/lib/types/client/service.d.ts` 的 `ISidebarRight`（公开操作无宿主参数、`mounted` 为前台会话）；同包 `lib/client.js` 的 `openResource()` → `require()`、`RightbarRoot/SessionView`（只显示 `view.selected`）；`desktop/src/verticals/finance/dsh/client.tsx` 的 `remember()` 与 `restoreTopic/startTopic`；`desktop/src/verticals/finance/assistant/apply.ts` 的 `focusAssistantSession()`。这些 DSH 文件位于 `desktop/dsh/runtime/node_modules/`，仅作已安装版本的核验依据。

用既有隐藏任务宿主或新建宿主都不能单靠产品代码固定可见停靠面：让宿主成为前台会话会改变主区所选的深度对话；保留别的前台会话又会隐藏宿主停靠面。DSH 内部虽有 `openResourceIn(sessionId, …)`，类型声明明确它不属于公开 `ISidebarRight`，且只服务已被采用的会话；调用它也不会令后台宿主面板可见。要满足方案 A，需要 DSH 提供独立于前台会话的可见停靠面/宿主选择能力（包改动或补丁），命中 §6 第 3 项停止条件。

### §3 逐项判定

| 项 | 判定 | 依据与未验证处 |
|---|---|---|
| 1 任务过程 | 有条件可行 | `dsh-client-ui-subagent/README.zh.md` 与 `lib/client.js` 已提供带准确 parent/child/mode 的 `subagentchat` 资源；one-shot 只读，运行中会话有独立 Stop 的路径。报告、公司研究、知识整理的真实任务地址、整轮折叠、`FinanceToolRow`、任务清单卡片及实时刷新均未实际点击核验；任务类型不能从本地展示状态推断 mode。|
| 2 顶层会话 | 有条件可行 | `dsh-client-ui-sidebar-right/README.md` 的 Extension seats 和 `dsh-client-ui-subagent/lib/client.js` 示范资源注册、`SessionProvider`、`conversation.content` 渲染；可设计 `financesession`。但顶层会话输入/发送/停止、Ask/Agent 绑定、与主区同时挂载是否冲突均未运行验证。即使成功，也不解决第 3 项。|
| 3 停靠面归属 | **不可行（当前公开接法）** | 当前公开导航只写前台会话，且只显示其停靠面；不存在固定可见的产品宿主参数。刷新可恢复**各会话自己的**布局，不能恢复一套跨会话可见的全局标签。触发 §6 停止。|
| 4 议题空白态 | 有条件可行 | `dsh-client-ui-subagent/lib/client.js` 通过 `conversation.content` 的 `hero/active` 阶段渲染嵌入视图；产品现有 `conversation.input.dock` 注入最近对话（`dsh/client.tsx`），需针对侧栏资源作用域替换或隐藏。未验证槽位区分是否足够。|
| 5 布局 | 有条件可行 | DSH README 声明 `push`、`fullscreen`、窄屏自动全屏及原生宽度拖拽；`FinanceRoot.tsx` 当前却把 `rightbar` 包在固定 480px 容器中，`research-surfaces.css` 另用 `:has(.finance-side-panel)` 给主区让位。接线时须改这个根容器并与现有让位规则择一，未做浏览器尺寸验证。|
| 6 导航保持 | 有条件可行 | `RightbarRoot` 保留其他会话子树但将其隐藏；仅路由切换而前台会话不变时有保持基础。对象标签跳页、切换深度对话会话的真实交互未验；后者按源码会换可见停靠面。|
| 7 多标签 | 有条件可行 | 同一会话停靠面支持多资源标签和地址去重；类型可声明 `keepMounted: true` 保留已访问正文。内置 `subagentchat` 未声明此选项；三类标签切换时的滚动位置、输入草稿未实测。跨前台会话仍受第 3 项限制。|

### 接法与工作量

- **方案 A 的前置工作**：先由 DSH 增加全局可见宿主停靠面或等价的公开宿主选择接口，并定义主区会话、侧栏宿主与布局持久化的关系；这是运行时所有权/接口变更，不能当成产品插件小补丁。完成后重新做 T3-0 真机验证，约 1–2 天（不含 DSH 设计及改动时间）。
- **退回方案 B**：保留产品拥有的右侧面板与统一让位规则，在产品侧按会话引用嵌入原生对话内容；任务过程先替换自绘轨迹。这样会放弃 DSH 自带的标签栏、全屏与停靠持久化，需要产品自行完成这些交互。T3-b 议题/问助手约 2–4 天，T3-c 任务过程约 1–2 天，均需真实会话与浏览器验收后才可确认。
- 用户需裁决：是否授权 DSH 运行时接口变更以继续方案 A，或改走方案 B。方案 A 的交互目标已由 Human Checklist 确认，本次没有擅自更改。并行工作树中 `dsh/client.tsx`、`dsh/result-node.tsx` 等已有其他 Task 改动；本次仅修改本 Task 文档。
