## 1. 目标

模型可以生成指标卡、传导链两种组件，并像行情图一样嵌在正文对应的段落里。指标卡上的每个数字都能点回出处，并且已经过 Backend 校验。

## 3. 冻结决定

V1. **两种新的成果类型**：
- `stat`（指标卡）：1–4 张卡片。每张卡的字段：名称、数值、单位、时期或时点、可选的变化幅度（附比较基准）、出处引用。整组还有一行口径说明。
- `flow`（传导链）：3–6 个有顺序的节点（短句），再加一句说明（例如"这是一条需要检验的机制"）。节点原则上不写数字；如果写了数字，同样要带出处，并按 V3 校验。

V2. **新增生成接口与 Agent 工具**（暂名 `compose_visual`，最终名称由执行方定）。沿用 `ResearchResults().generate` 的写法：用 `operation_id` 保证幂等，保存后不可修改，返回 `result:` 引用。模型拿到引用后，按现有的 C1 标记写法嵌入正文。

V3. **数值校验**（确定性，由 Backend 执行，不通过就拒绝保存，并返回具体是哪个数、什么原因）：
- 原始数值：必须在所引出处的原文中找到对应的值，允许确定性的单位换算；可用的出处为 `claim:` / `evidence:` / `source:`、行情或财务成果中的单元格（`calculation_evidence.resolve_quantity`）、V7 的网页快照；
- 派生数值（变化幅度、比率、差值）：必须引用一次计算工具的结果，并且与该结果的输出一致；
- 引用了不存在、读不到或不支持的出处：拒绝。

V4. **前端**：在 `ResultCard` 中新增两种类型的渲染。
- 指标卡：卡片横向排列，窄屏时换行；显示名称、大号数值、时期、变化幅度。出处用现有的引用标记呈现，点击可以回到原文。
- 传导链：竖向节点加箭头，底部一行说明小字。

两种组件都直接可见，不需要点击；样式贴合现有产品主题（亮色和暗色都要支持），沿用已授权的设计语言。这两种类型不提供"图表｜数据"切换，指标卡可以提供"查看出处"。

V5. **提示词**（在深挖 Task 合入之后再加）：在 `DEEP_PROMPT` 中说明什么时候用这两种组件。
- 指标卡：有 2–4 个需要对比、或者需要突出的关键数字时使用；
- 传导链：在解释一条因果或传导机制时使用；
- 不为了装饰而用，一个回答中组件不宜过多；
- 嵌入方式同行情图。

V6. 不改 DSH 补丁，不改内嵌检查脚本；成果类型以外的现有行为保持不变。

V7. **网页只读快照（2026-10-08 用户确认）**：`fetch_source_url(persist=false)` 读取网页时，Backend 额外保存一份筛查后正文的只读快照，记录 URL、抓取时点和 `content_sha256`，**不进资料库，不产生 Document，也不进入事实准入**。快照返回一个可以引用的标识（例如 `snapshot:<sha256>`，具体命名由执行方定），工具结果里带上这个标识，模型用它给指标卡的数字注明出处，V3 在快照原文里核对数值。快照的保留期限可以配置（默认 90 天；被成果引用的快照不会过期清理）。快照内容一律按外部不可信内容处理。只读与入库的区别不变。
