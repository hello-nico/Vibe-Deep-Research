## 3. 冻结决定

K1. 清点范围：`calc/`、`datasources/`、`.agents/skills/`（每个技能一行）、`orchestrator/src/` 每个文件与子目录、
`orchestrator/test/` 与 `desktop/test/` 中指向上述模块的测试、`scripts/` 下的脚本、CI 中的每个测试步骤。
`desktop/src/` 只在被上述模块引用或引用上述模块时纳入。

K2. "在用"的判定只认当前产品调用链上的证据，写到文件和行号：
- 页面 → `orchestrator` API 路由 → `service` → 模块；
- `scripts/start`、`scripts/setup`、`scripts/doctor` 的启动与检查路径；
- DSH 插件（`desktop/dsh/finance-ui/`）的注册与调用；
- 模型工具（会话日志的 `request/header` 工具名）。

只被测试、文档或另一段同样无调用方的代码引用的，不算在用。

K3. 每一行给出：模块、当前调用方（文件:行，或"无"）、对应测试与 CI 步骤、现有失败、建议、理由。
建议只有三种：
- **保留**：有当前调用方；
- **退役**：无调用方，代码与测试一起删（另立 Task）；
- **移出 CI**：暂时保留代码（例如用户可能恢复），但不再在 CI 和执行中测试。

K4. 动态调用（按字符串拼路径、子进程调用 Python 脚本、注册表驱动）必须追到实际被拼出的路径；
追不到的标"待核实"，不得默认为在用或不在用。

K5. 每个建议"退役"的模块，列出删除后需要同步改的文档位置（README 模块表、AGENTS、契约、CATALOG 等），不改。
