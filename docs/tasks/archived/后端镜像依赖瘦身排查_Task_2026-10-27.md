## 1. 目标

弄清 Stock 后端镜像里每个依赖是否还被当前功能用到，给出可删除或移出镜像的清单与证据，并在 worktree 里改好。

## 2. 现状（Claude 核实）

- 镜像：`stock-research-backend:latest` 1.97GB，`stock-research-migrate:latest` 980MB（构建于 10-26）。
- `backend/requirements.txt` 一份同时给运行、迁移和测试：fastapi、uvicorn[standard]、pydantic、httpx、respx、pytest、sqlalchemy、psycopg[binary]、alembic、liteparse==2.14.5、akshare>=1.17、playwright==1.63.0。
- `backend/Dockerfile`：gbrain（bun 构建，从 GitHub 拉）→ dependencies 层装全部 requirements → migrate 阶段；backend 阶段另装 `playwright install --with-deps chromium`。
- 注释自述：akshare 只用于行业分类/成分股快照再生，API 运行时不导入；playwright 用于图文报告保存前的渲染质检（`app/services/report_quality.py`）。

## 3. 冻结决定

D1 判定以当前代码为准：逐个依赖（含 gbrain、Chromium、git）查 `backend/app`、`backend/alembic`、`backend/scripts`、`data/`、compose 与 dsh 调用方的真实引用，区分「API 运行需要 / 只迁移需要 / 只测试需要 / 只离线脚本需要 / 已无人用」。
D2 惰性导入、子进程调用（`lit`、`gbrain`、`playwright`）也算引用，要追到调用点，并说明该功能今天是否仍在产品路径上（例如图文报告质检、wiki 同步是否还会被触发）。
D3 测试依赖（pytest、respx 等）移出镜像，放到单独的 `requirements-dev.txt`；离线脚本依赖同理放单独文件并在脚本旁注明。不做兼容层。
D4 某功能仍在用但依赖很重（如 Chromium），不擅自删功能：写清体积、用途、可选替代，交 Claude 定。
D5 体积用本机已有环境估算（`backend/.venv` 的 site-packages 按包统计、`docker image history` 看各层），不重新下载。
