## 3. 冻结决定

T1 模板登记：新增 `backend/app/services/valuation_templates.py` 与数据文件 `backend/app/data/valuation_templates.json`。七个模板：commodity_pe、volume_pe、backlog_pe、bank_pb、insurance_pev、realty_nav、infra_yield；
  每个写 id、中文名、估值方法、最少输入（字段 id 与来源：财报 / 行情 / 目录价格 / Profile）、三档构造方式、驱动类别。申万二级 → 模板映射由 eval `results.csv` / `sw2_profiles.csv` 生成，存进数据文件并写生成脚本；
  无 Profile 的三个行业按 eval 兜底模板。
T2 统一结果结构（本阶段只定结构与 commodity_pe 适配，不实现新模板计算）：`{template_id, tiers:{悲观,中性,乐观}, position, grade_base, drivers:[{id,name,direction,sensitivity}], flips}`；commodity_pe 用现有 sensitivity 结果映射，现有行为与测试不变。
T3 行业 Wiki 公共层：行业页新增块 `valuation_framework`（模板 id 与名称、方法一句话、来自 Profile 的估值驱动列表与对应核心问题、产业链与上下游二级行业），带 refs（profile 与 eval 来源）。用现有 Wiki 编译与写入路径，不手改 md。
T4 公司 Wiki：identity 块增加 `valuation_template`（按所属申万二级映射）。
T5 只读接口（契约冻结，D 阶段按此做页面）：
   `GET /api/v1/wiki/industries/{code}/valuation-framework` → `{industry_code, industry_name, template:{id,name,method}, drivers:[{id,name,kind,source}], core_questions:[...], chains:[{chain_id,name,role}], companies:[symbol]}`；
   `GET /api/v1/wiki/chains/{chain_id}` → `{chain_id, name, nodes:[{industry_code, industry_name, role, template_id, companies:[symbol]}], transmission:[{from, to, driver, text}]}`；
   `GET /api/v1/wiki/chains` → 链列表。链定义来自 eval `chains.csv`，存数据文件。
T6 测试：映射覆盖 131 个二级；commodity_pe 适配不改现有结果；两个接口用夹具返回契约字段；Wiki 块写入后可读回。
