## 1. 目标

1. 年报、半年报的目录接口直接给出「关键页」：「管理层讨论与分析」一章，加上附注里风险、敏感性、成本、分部所在页及其前后各一页。
2. 关键词检索时，关键页上的命中排在前面。
3. 研究流程查利润驱动与敏感性时先看关键页，少走几步。

## 3. 冻结决定

R1 **不落库，按固定版本即时算**：新文件 `backend/app/services/report_key_pages.py`，纯函数 `select_key_pages(page_texts: list[str]) -> KeyPages | None`（输入按页号顺序的每页文本）。不改解析流程、不加表、不迁移；已入库的旧报告直接受益。进程内按 `parsed_content_sha256` 缓存最近 32 份。
R2 **适用范围**：`document_type` 为 `annual_report` 或 `quarterly_report`，且 `md_page_count ≥ 40`；其余返回 `null`（摘要、季报、研报不需要）。
R3 **章节**：
  - 章节标题行：去掉行首 `#` 和全部空白后，整行匹配 `^第[一二三四五六七八九十]+节` 加名称；含 `|`、`.`、`…`、阿拉伯数字的行一律不算（排除目录页）。
  - 「管理层讨论与分析」起始页 = 第一个名称含「管理层讨论与分析」的章节标题行所在页；结束页 = 其后下一个章节标题行所在页减一；没有下一章时取到末页。
  - 找不到，或这一章超过全量页数 40%，`chapter` 为 `null`，只用关键词页。不做无编号标题的猜测（紫金这类留给关键词）。
R4 **关键词**：常量 `KEY_PAGE_KEYWORDS = ("敏感性分析","汇率风险","利率风险","风险价值","营业成本构成","成本构成","分部","汇兑","每上升","每变动")`，每页去掉空白后做子串匹配；命中页与前后各一页（不越界）并入。
R5 **响应**：`SourceIndexResponse` 加可选字段 `key_pages`，仅在标题树模式（不带 `keywords`）返回：
```json
{"chapter":{"title":"第三节管理层讨论与分析","start_page":11,"end_page":37},
 "pages":[10,11,12,…],
 "hits":[{"page":175,"keywords":["敏感性分析","利率风险"]}],
 "page_count":55,"ratio":"0.2619"}
```
  `pages` 升序去重；`ratio` 为四位小数字符串。
R6 **关键词模式排序**：命中 Block 按「在关键页上」优先、原顺序其次稳定排序，再按 `offset/limit` 分页；每个 Block 加 `key_page: true|false`（不适用的文档一律 `false`，排序不变）。`SourceBlockSummary` 加可选 `key_page`。
R7 **DSH 透传**：
  - `projectHeadingIndex` 透传 `key_pages`，把 `pages` 压成区间字符串（如 `"10-38, 84-86, 174-177"`）以省 token；`chapter`、`hits` 原样；`null` 时不出该字段。
  - `projectKeywordMatches` 每个 Block 透传 `key_page`。
  - `document-tools.mjs` 的 `source_get_index` 说明加一句：年报、半年报的标题树带 `key_pages`（管理层讨论与分析及风险、敏感性、成本、分部所在页），先读这些页；关键词结果里 `key_page:true` 的优先回读。
  - `consumers.mjs:73` 改为：先看 `source_get_index` 返回的 `key_pages`，有 `chapter` 就扫这一章；再用关键词检索，优先回读 `key_page:true` 的命中。其余要求不变。
  - 刷新模型表面快照（`UPDATE_MODEL_SURFACE=1 pnpm test`）。
R8 不接入向量检索，不加新工具，不改 `source_scan_sections` / `source_read_blocks`。
