## 3. 冻结决定

C1. **目录 v1**（本 Task 实现范围）：
- 数据组件：`chart ref title`（行情、财务成果）；`stat`（子元素 `item label ref unit`，1–4 项）；`compare title`（子元素 `bar label ref`，2–8 项、同单位）；`flow note`（子元素 `step`，3–6 步）；
- 推荐：`suggest type=question|company`，子元素 `q`（question 为追问文本；company 为 `q code=` 加一句理由）；每回答最多一组，位于末尾；
- 布局：`section question`（标题即答案）、`grid cols`（仅 2 或 3）、`row`。
- 不在 v1：`scenario`、`valuation`、`tabs`、`suggest type=indicator`（跟踪项归 T12）。

C2. **数字规则**：数据组件的数值只经 `ref` 绑定（`result:`、`claim:`、`evidence:`、`provider:`、计算凭据）；`title`、`label`、`question`、`note`、`step`、`q` 等文字不得含数字，`grid cols` 为布局例外。

C3. **提示词**：`DEEP_PROMPT` 删除"先调 `suggest_next`"与"写 `![](result:…)`"两段，加入面向模型的目录说明（以 S0 修订 2 实验段为底稿，按 C1、C2 更新并给一个完整示例）；同时处理 todo 记录的"需要说明的口径："单独成段问题（口径写在对应图或判断旁）。深度对话角色移除 `suggest_next`。其他角色提示词不变。

C4. **事件契约**（Stock 写、Vibe 读）：回合正常结束后，Stock 插件解析最终回答中的全部 `vibe` 块，追加一个可忽略事件 `stock-research/vibe-check`：
`{ turn, blocks: [{ index, ok, elements: [{ path, component, status: "ok"|"dropped", reason?, values?: { <ref>: { value, unit, period, source_title } } }] }], suggest?: { type, items: [...] } }`。
- 校验：语法、未知组件或属性、C2 数字规则、引用经 Backend 解析可回读；推荐复用 `validateSuggestions` 的去重与禁用措辞规则（company 去掉已关注由 Vibe 显示为"已关注"，沿用 T1 现行做法）；
- `values` 提供数据组件渲染所需的已解析数值，Vibe 不再自行解析引用；
- 校验失败只影响对应元素，事件本身失败时整块按原文代码显示并记一条诊断。

C5. **渲染**（Vibe）：按 C8 路径以限定补丁把 `lang=vibe` 交给产品注册的渲染函数；流式未闭合或尚无 `vibe-check` 事件时显示占位；收到事件后按其结果渲染，`dropped` 元素不显示；`chart` 复用 `ResearchResult`；新组件样式贴合产品主题（亮暗色），图例颜色不重复（处理"收盘"与"20 日均线"同色）。复制原文时组件转为一句文字摘要，不露裸成果 ID。

C6. **推荐点击**：question 作为下一句发出；company 调 `addWatch` 只加入"个股研究"名单，不启动研究；点击后卡片显示结果。原 `stock-research/suggestion` 事件投影与 `suggestion-node` 改为由 `suggest` 组件承接，旧事件保留只读兼容已存在会话。
