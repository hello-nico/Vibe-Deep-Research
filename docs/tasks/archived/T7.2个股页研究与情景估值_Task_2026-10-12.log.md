### D1 · packet_field 请求

沿用 `POST /api/v1/analysis/primitives`（DSH `calculate_metrics` 调用的 Backend 入口）。Quantity 只填 `name` 和 `source`，禁止模型补传 value、unit、currency、period、scope、basis、refs。`field_id` 必须逐字使用当日 `data-packet.fields[指标键].field_id`，不是把指标键当字段身份；以下 ID 为样例。

```json
{
  "operation": "per_share",
  "equity_value": {
    "name": "归母净利",
    "source": {"kind": "packet_field", "symbol": "600863.SH", "as_of": "2026-10-12", "field_id": "net_profit_attributable:example"}
  },
  "shares": {
    "name": "总股本",
    "source": {"kind": "packet_field", "symbol": "600863.SH", "as_of": "2026-10-12", "field_id": "shares:example"}
  }
}
```

Backend 按 Asia/Shanghai 当日校验 `as_of`，定位当日数据包中同一 `field_id`，绑定数值、原单位、期间、口径及来源。缺口、冲突、跨日、不存在字段或 caller 补数字均拒绝；现有 document_number / result_cell 请求不变。总利润情景仍用 `scenarios[].earnings` + 顶层 `shares`，两者必须都是 packet_field。

### D1 · 每股模式

同一入口，`operation="scenario_price"`。每档使用 `eps`，不传 `earnings` 或顶层 `shares`；三档必须为悲观、中性、乐观各一条。`eps` 必须绑定 eps_ttm 或机构 EPS 字段，三档同公司、同日。倍数保留现有 ScalarAssumption（显式模型假设），不把倍数当事实。

```json
{
  "operation": "scenario_price",
  "scenarios": [
    {"name": "悲观", "eps": {"name": "每股收益", "source": {"kind": "packet_field", "symbol": "600863.SH", "as_of": "2026-10-12", "field_id": "eps_ttm:example"}}, "multiple": {"name": "估值倍数", "value": "8", "basis": "assumption"}},
    {"name": "中性", "eps": {"name": "每股收益", "source": {"kind": "packet_field", "symbol": "600863.SH", "as_of": "2026-10-12", "field_id": "eps_forecast:example"}}, "multiple": {"name": "估值倍数", "value": "10", "basis": "assumption"}},
    {"name": "乐观", "eps": {"name": "每股收益", "source": {"kind": "packet_field", "symbol": "600863.SH", "as_of": "2026-10-12", "field_id": "eps_forecast:example"}}, "multiple": {"name": "估值倍数", "value": "12", "basis": "assumption"}}
  ]
}
```

返回沿用 `PrimitiveResult`，包含 `calculation_ref` 与 `input_bindings`；`extra.scenarios[]` 按悲观、中性、乐观排序，行含 `name`、`earnings`（每股模式为 EPS 数值）、`earnings_period`、`earnings_basis`、`multiple`、`price`。每股模式的 `extra.mode="per_share"`；总利润模式为 `total_profit` 并保留 share_count / share_period。页面数值只从保存的计算凭据取，不从研究文本解析。

D2/D3 数据包字段键：`shares` 为腾讯字段七十三的期末总股数；`eps_ttm` 为 TTM 归母净利除以当前总股本；`eps_forecast` 为当年机构 EPS 中位数，`eps_forecast_next` 为次年机构 EPS 中位数；两者各为独立可绑定标量，带 period、institution_count、latest_published_at、样本少提示。`forward_pe` 使用当年 eps_forecast。原动态 field_id 规则保留，实际来源身份由当日返回值提供。

### A 线联合接口核对发现（2026-10-12）

- B `dsh/src/company-page-tools.mjs` 的保存器会给包括 gapNote 在内的请求自动添加 basisVersion；追加裁定要求 gapNote 分支其他字段必须缺省，因此 Backend 将按规则返回该字段的 422，B 线须只对完整研究自动补版本。A 不修改 dsh。
- B 的情景缺口说明采用省略 scenarioRef 的写法。A 将其与显式 null 统一为无情景引用，返回仍含 `scenarioRef:null`；不新增兼容层或伪造凭据。缺口原因由估值节叙述，Backend 不通过某个固定词语来认定模型是否写了原因。
- 待裁定的字段身份：现有 field_id 含 provider 引用或输入哈希，每次 ensure 都可能变化；C `companyPacket.findField` 只按指标键或精确 field_id 找字段。资料没变时研究不派生过期，但旧研究的动态 fieldIds 会失去当前值映射。
  推荐把页面可引用 field_id 固定为指标键（如 eps_ttm），来源 ref、输入引用和绑定凭据的完整字段 / packet_sha256 保持实际来源身份；D1 的 symbol + as_of 仍保证当日取值。另一选项为保持快照 field_id，并将当前值映射作为已知缺口交接。依赖这个决定的身份修改尚未执行。
