## 1. 目标

1. 个股页数据层只读一份数据包：数秒内出现，字段按已核对、来源、冲突（两值并列）、缺口显示。

## 3. 冻结决定

D1. **数据包字段作来源**（`field_id` 为稳定指标键，见过程记录裁定 4）：`calculate_metrics` 的 Quantity 来源新增 `packet_field`（`symbol`、`as_of`、`field_id`）。Backend 从当日数据包取值、单位、期间、口径并绑定，模型不传数值；
  字段为缺口或冲突时报错并说明原因。现有 `document_number`、`result_cell` 不变。`scenario_price` 的利润与股本必须用 `packet_field`；
  另支持每股模式：三档各给每股收益字段（`eps_ttm` 或 `eps_forecast`）与倍数，不传股本，价格 = 每股收益 × 倍数。
D2. **股本与 PB 口径**：`shares` 改用腾讯行情字段 73（期末总股数；字段 72 是无限售股数，不得使用），保留报价时点；与最新定期报告股份变动表期末数一致为已核对，不一致两值并列并注明两个时点，不判冲突。
  数据包新增 `eps_ttm` = TTM 归母净利 ÷ 当前总股本（代码计算）。PB 复算分母改为归母权益减其他权益工具（优先股、永续债），取不到其他权益工具时 PB 复算标缺口，不再与 provider 并列冲突。
D3. **机构预测**：数据来源为东方财富研报列表单篇 EPS（`predictThisYearEps`、`predictNextYearEps`；17/17 有，机构数 1–12）。数据包新增 `eps_forecast`（当年、次年）：
  每家机构取最近 180 天内最新一篇，取中位数，附机构数、最新发布日期，状态 `sourced`，界面标「机构预测（N 家）」；机构数 <3 时加「样本少」提示；无数据为缺口。
  不把 EPS 乘股本换算成净利（摊薄口径未声明）。同时新增 `forward_pe` = 现价 ÷ 当年 `eps_forecast`（代码计算），作为隐含增速依据。
D4. **估值分位**：五年时点序列目前不可交付（无直接历史 PE/PB；新浪加腾讯拼接缺历史股数与当时可见版本），`valuation_percentile` 保持缺口，界面不显示。
  五档结论依据限同业对比、`forward_pe` 与 TTM PE 的差、机构预测增速；历史分位另立 Task。
D5. **个股页研究结构**（Backend 校验，存储沿用旧 T7 方案：Wiki 研究块 + `GET`/`POST …/page-research`；数据归属迁移时只换存储）：
  `companyType`（generic、commodity_cycle、leveraged_cyclical_utility、scarce_asset_rent、bank）；`thesis`（一句话，≤60 字）；
  `sections`：`business`、`profit_formula`、`variables`、`cash`、`valuation`、`tracking` 各一条 `{summary, details?, fieldIds[], calculationRefs[]}`；
  `pillars` 3–5 条 `{id, text, fieldIds[]}`；`falsifiers` `{pillarId, text, fieldId?, threshold?{value, unit}, window}`；`catalysts` `{date, event, pillarIds[]}`；
  `valuation` `{grade: 明显低估|偏低|合理|偏高|明显高估, basis[], conditions, scenarioRef}`；`researchedAt`、`basisVersion`、`changes{sectionId: 短句}`。
  文字字段不得含阿拉伯数字（日期字段、`threshold` 除外）；`fieldIds` 必须存在于当日数据包；`calculationRefs`、`scenarioRef` 必须可回读。不通过整份拒收并返回逐项原因，模型可改一次。
D6. **研究 SOP**（DSH，按钮任务固定流程）：读数据包 → 判公司类型 → 按模板写各节 → 变量试算用 `calculate_metrics`（`packet_field` 来源）
  → 选利润口径与三档倍数调 `scenario_price` → 五档结论附依据与改变条件 → 支柱、证伪、催化 → 保存。
  替换现有 `company_research` 角色的提示词与工具：新增 `ensure_company_data`、`read_company_data_packet`、`save_company_page_research` 三个工具，保留 `today`、`calculate_metrics`，其余移出。
  不读 Wiki 原样、不做外部检索；`scenario_price` 失败两次后估值节写缺口并保存其余内容。SOP 正文见过程记录「SOP 正文」，执行方照抄进 `consumers.mjs`。
D7. **成本与篇幅**：篇幅由 Backend 结构限长强制，不靠提示词：`thesis` ≤60 字，各节 `summary` ≤80 字、`details` ≤400 字，支柱、证伪、催化每条 ≤80 字；超长整份拒收并指出字段。
  单次研究目标 ≤600K token（提示词运行开放题达 72–126 万，研究只读数据包，不做外部检索，目标可达）。
D8. **触发与更新**：沿用 T7 P4、P6（首次打开无研究时后台研究；新定期报告或公告入库后标过期，下次打开后台更新，期间显示上一版；不设生成按钮；关注不启动研究）。
  打开页面时若数据包无当日 provider 快照，Vibe 在后台调一次 ensure（每股每日一次），完成后重读；研究任务开始前也先 ensure。
D9. **页面**（方法论模板，单页、第一层只放数与一句话）：头部（价格、论点、五档结论）→ 商业模式 → 利润公式（行业驱动公式与变量）→ 变量试算 → 现金
  → 估值（PE、PB、股息率、同业、分位、三档情景表）→ 跟踪（支柱、证伪条件、催化日历；建跟踪项归 T12）→ 关联 → 资料。冲突字段两值并列并写口径；缺口写原因；研究未到时数据照常显示。
D10. **报告运行时**：本 Task 不改 S-04；页面不再出现 Wiki 原样与图文报告入口。验收后另开 Task 裁决 S-04 与 Chromium（`todo.md` §5）。
