## 1. 目标

关注公司的定期报告披露后，不用用户点「重新研究」，系统自动重研一次，模型基数滚动到最新报告；客户端关闭期间错过的，下次打开时补跑。

## 2. 现状（Claude 核实）

- 研究任务记录与自动续跑已有（Vibe `desktop/dsh/finance-ui/host-state.mjs`：createResearchTask、spawnResearchSession、接续说明；同一步连续两次失败即停）。
- 财报日历：Backend `GET /api/v1/market/report-calendar?symbols=`（eastmoney，含 actual 披露日）；研究结果带报告期（数据包 `page_period` / 研究 researchedAt）。
- 定时：DSH 源码 `/Users/apple/ts/src/deepseek-harness/packages/schedule`；运行时有 `@deepseek-ai/cordis-plugin-timer`。现在没有任何定时任务。
- 现状：三季报到达后只出对账卡，基数要用户手动重研。

## 3. 冻结决定

S1 检查节奏：宿主启动时补跑一次；之后每 3 小时一次（10-10 已定本机默认 3 小时）。用已有的计时能力（先核实 `packages/schedule` 或 cordis timer 哪个已在运行时可用，选不需改 DSH 内核的那个）。
S2 每次检查：取关注且已研究的公司，读财报日历；若某公司最近一份已披露定期报告（actual 披露日 ≤ 今天）晚于其研究所用报告期，且该公司没有进行中的研究任务，则创建一次自动研究任务（复用现有研究任务，提示里写明「定期报告已披露，按最新报告重研」）。
S3 并发 1：一次只跑一家，排队；同一公司同一报告期只自动触发一次（记在任务记录里，失败按现有「两次即停」）。
S4 只做定期报告（年报、半年报、一季报、三季报）；业绩预告、快报后续再加。
S5 不做提醒角标与页面（claude2 后做）；任务记录里标明 trigger: "report_arrival" 供前端区分。

## 8.1 修订 1（Claude，2026-10-26）

S6 「是否已是最新」不能只看 `report_period`：旧任务与用户手动发起的研究都没有这个字段，合入后首次启动会把所有关注公司各重研一遍（华友 10-26 刚按三季报重研也会再跑）。改为：该公司最近一次**已完成**研究的完成时间（上海日期）≥ 最新定期报告的 actual 披露日，即视为已是最新、不触发；`report_period` 有值时仍优先用它。补夹具：手动研究在披露后完成不触发；披露前完成触发；旧任务无 report_period 走完成时间。
