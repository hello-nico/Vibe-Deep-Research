## 3. 冻结决定

A1. **七类候选**：
- A 退役功能残留：§2 所列功能仍存在的代码、路由、组件、测试、配置与文档引用。
- B 无人调用：未被任何地方 import 的模块与导出；Vibe 页面、orchestrator 与 DSH 插件都不调用的 Backend 路由；无文档、脚本、CI、package.json 引用的脚本。
- C 重复实现：同一逻辑在两仓或同仓各有一份；同一功能存在两条路径。
- D 兼容层：旧名别名、legacy 读取、fallback 分支、旧格式迁移读取（违反「不做兼容性开发」）；Checklist 明确要求的保留除外。
- E 测试膨胀：被测对象已删除或已退役的测试；只断言源码字符串而不测行为的测试；明显超大的快照；多份测试重复覆盖同一行为。
- F 杂物：根目录或仓内的一次性文件（压缩包、截图、实验脚本、旧 workspace 产物）、`artifacts/`、过时的 skills 副本。
- G 依赖：npm 与 Python 中未被代码使用的依赖。

A2. **证据要求**：每项至少一条可复跑的证据——`rg` 无引用的命令与结果、调用链追踪、契约或 Checklist 的退役原文、git 最后修改日期与提交。只凭「看起来没用」不列入。动态引用（字符串拼名、注册表、入口文件、CLI、CI、Dockerfile、`package.json` scripts、pytest fixture）须专门检查后再判无引用。

A3. **每项字段**：编号、类别、仓库与路径、行数、证据、删除风险（低 / 中 / 高及原因）、建议（删除 / 合并到某处 / 保留及理由）、依赖它的其他候选、若删除需同步改的契约或文档。

A4. **不列入删除的范围**：
- Stock bench 钉住组件、`bench/data/` 旧实验指纹、`bench/releases/` 基线 Owner（AGENTS 规定），只可标注「钉住，需重新冻结才能动」。
- 用户数据与 Backend 知识，Checklist 写明保留的存量（雷达旧快照、Theme/Comparison 存量、旧引用与原件等）的读取路径。
- 旧 T7 未提交改动与 codex1、codex2 当前改动的文件（由 T7.2、T7.1、T5 决定）；只在清单末尾列出这些文件，不判定。
- 归档 Task 与 decisions 文档。

A5. **汇总**：清单按可省行数降序；另给按仓、按类别的小计，以及「低风险可直接删」「需先改契约」「需用户裁决」三组。
