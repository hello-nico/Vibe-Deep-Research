## 1. 问题

- **公司研究没有固定流程**：Vibe 只发一句“继续研究 X：先看已有研究页的内容、缺口和资料时间线，再按缺口补充年报、公告和行情”（`desktop/src/verticals/finance/pages/CompanyWiki.tsx` 约第 390 行），交给深度对话的通用角色（`dsh/src/consumers.mjs` `deep_research` / `DEEP_PROMPT`）和全部工具自由发挥。每次行为不同：中际旭创 10:17 那次只读了 1 次原文，却抓了 4 个网页。相比之下，图文报告有专用角色 `wiki_report`、分步提示 `REPORT_PROMPT` 和收窄的工具集。
- **经营数据只记了组名，没记具体指标**：研究页 `required_metrics` 的每一项本身是一组指标（如“发电量 / 售电量 / 上网电量”）。`industry_metric` 只校验 `metric_name` 等于某一组，所以华能蒙电“经营”块显示成“发电量 / 售电量 / 上网电量：5821842.61 万千瓦时”“营业收入 / 归母净利润 / 投资收益：180.13 亿元”，看不出是哪个指标。后一条也和年报营业收入 210.50 亿元对不上号。
- **显示格式**：大数没有换算、没有千分位（AGENTS.md：金额通常用亿元，显示千分位，原始证据精度不变）。

## 2. 冻结决定

1. **专用角色 `company_research`**（`dsh/src/consumers.mjs`），仿照 `wiki_report`：独立的分步提示与收窄工具集。公司研究任务（Vibe `startResearchRun` 发起的子 Agent）使用这个角色，不再用 `deep_research`。
2. **五个固定步骤**（写进角色提示，按顺序执行；每步开始时发一条简短中文进度说明）：
   1. **读取研究页**：`wiki_read` 绑定公司页，列出现有结论、缺口、`required_metrics`、资料时间线。
   2. **补齐定期报告**：检查最近一期年报和最近一期中报 / 季报是否已入库且解析完成；缺的用 `source_ingest_periodic_report` 入库并等待。不抓新闻网页。
   3. **逐项读取经营数据**：对 `required_metrics` 的每一组、组内每个具体指标，在定期报告原文中定位（`source_get_index` / `source_scan_sections` / `source_read_blocks`）。找到就用 `stage_extraction` 暂存一条，数值和单位照原文抄写、不换算；找不到就跳过并记为缺口。明确跳过定期报告里不会有的项（预测、行业市场规模、外部资本开支）。每组最多暂存 3 条，全次最多 16 条。
   4. **行情与估值**：取最新行情，计算估值（`generate_market_result` / `calculate_market_result` / `calculate_metrics`）。
   5. **形成研究结论**：按固定结构输出——经营模式、本期变化、风险与待核事项。每个数字带块级引用；清单外的重要事件只列入“风险与待核”，不展开。
   - 工具集只保留上述步骤用到的工具，以及 `today`、`query_observation`（执行方以今天真实研究会话 `2f803dd3`、`a3371a9c` 的工具调用为参照，核对后在 §8 列出最终清单）。去掉网页抓取与雷达类工具。
3. **具体指标**：`industry_metric` 的 payload 必须带 `indicator`（具体指标名），且必须是 `metric_name` 那一组按“ / ”（前后带空格）拆开后的某一项；括号里的斜杠不拆，例如“装机容量 / 权益装机（水电/火电/新能源分类）”拆成两项。不符合就拒绝，原因为 `indicator_not_in_group`。严格核对（`strict_metric_source_match`）不变。
4. **显示**：Backend 渲染“经营”块时，每条写成“{indicator}（{报告期}）：{数值}{单位}（查看依据）”。显示时按确定性规则换算并加千分位：元满 1 亿显示为亿元，万千瓦时满 1 万显示为亿千瓦时，其余单位原样，保留 2 位小数。只改显示，Claim 里存的原值不变。没有 `indicator` 的旧事实照旧按组名显示。
5. **知识整理收紧**：整理 persona 不再要求“按清单逐项找原文并暂存”（这件事已移到研究第 3 步）。整理只复核研究已暂存的数据、写研究结论草案、提议题候选与记忆。第 1 条的“整理失败不丢暂存数据”保留。
6. **Vibe**：
   - 发起指令改为只给目标，例如“按公司研究流程研究 {name}（{symbol}）”，步骤由角色提示负责。
   - 研究页进度卡片按五步显示当前步骤（复用 `ResearchLoading` 的分段样式：读取研究页 / 补齐定期报告 / 读取经营数据 / 更新行情估值 / 形成研究结论）。当前步骤从会话里最近一次工具调用推断，推断不出时只显示“研究进行中”，不猜。
7. 深度对话、问助手不受影响，仍用原角色。

## 5. Stop Conditions

- 研究子 Agent 的角色由 DSH 框架决定、无法在宿主或插件侧指定：停止，回填调用链，不改 DSH 内部。
