## 3. 冻结决定

C1. **写法**：组件放在正文的 ```` ```vibe ```` 围栏代码块中，块内为类 JSX 标签，可嵌套布局；块外为普通 Markdown 正文。模型不写 JS、不写样式。
C2. **评测用目录 v0**（只用于本 Task 的实验提示词）：
- `chart ref`（已有行情 / 财务成果）；`stat`（子元素 `item label ref unit`，1–4 项）；`compare`（子元素 `bar label ref`，2–8 项、同单位）；
- `flow note`（子元素 `step`，3–6 步，出现数字须带 ref）；`scenario ref driver outputs title`；`valuation ref show`；
- `suggest type=question|indicator|company`（子元素 `q`）；布局 `section question`、`grid cols`、`row`、`tabs`。
- 规则：组件属性里不写字面数字，数值只能经 `ref` 绑定（`result:`、`claim:`、`evidence:`、`provider:`、计算凭据）；坏一个只丢一个；每个 `section` 的标题即答案。
C3. **实验提示词**：在当前 `DEEP_PROMPT` 之后追加一段面向模型的目录说明（覆盖 C1、C2 的写法、组件与数字规则，补什么时候用、什么时候不用和一个完整示例；全文由 Claude 写定于过程记录），并加一句"本实验中推荐与图表改用组件写法，不调用 `suggest_next`、不写 `![](result:…)`"，消除与基线提示词的两套写法冲突。只经 C9 的实验叠加层注入。提示词全文与哈希写进过程记录。
C4. **运行方式**：用户带 C9 开关重启工作台后，执行方用浏览器自动化在工作台深度对话中运行：每题每次新建会话、发送题目、等到回答结束再进行下一次；记录每次的会话 ID 与开始时间。
先跑一次"今天周几"，核对会话日志中的系统提示确实含实验段，再跑其余。执行方不读取、不打印凭据，不改模型选择；结束后关闭浏览器。
C5. **题目**（每题至少 3 次，新会话）：
- 今天周几（期望不出组件）；
- 华能国际今天走势如何（期望 chart，可带 suggest）；
- 华能蒙电靠什么赚钱、利润看什么（期望 section + stat / compare + scenario）；
- 电解铝利润现在在周期什么位置（期望产业链结构；外部价格未接入时应写明缺口而不编数）；
- 国庆外盘对神火、云铝的影响（期望不在组件里写无出处的数字）。
C6. **度量**（脚本断言，逐次记录）：
- 结构：`vibe` 块数、可解析元素占比、未知组件或属性占比；
- 数据：组件属性中的字面数字个数；`ref` 可解析占比（调用 Backend `/refs/resolve` 与成果读取，只读）；
- 正文：最终回答中块外正文字数，以及正文是否落在最后一步（不被折进过程区）；
- 期望符合：每题是否出现 / 不出现预期组件。
组合是否合理由用户按一页评分表打分（每次 1–3 分），执行方只准备评分表与样例截图位置。
C7. **判定**（同一模型、每题 3 次中稳定出现才算）：可解析元素 ≥ 90%；字面数字 = 0；`ref` 可解析 ≥ 90%；正文完整 100%；"今天周几"不出组件。全部满足建议 S1 采用正文组件；任一不满足，回填失败样例，由用户决定退回"工具生成成果、正文引用"或调整目录。
C8. **渲染核实**：第一轮已完成（可行，证据见过程记录），本轮不再做。
C9. **实验开关**（开发用，默认关闭）：`desktop/dsh-dev.ts` 读取环境变量 `VRA_DSH_EXPERIMENT_PATCH`；设置时须为已存在文件的绝对路径，否则启动失败并说明原因；设置后在产品固定叠加层之后再加一个 `--patch`，并在启动日志打印"已加载实验叠加层：<文件名>"。
未设置时启动参数与现在逐字一致。该变量只由启动器读取，不加入传给 DSH 的环境白名单。不在界面或 Checklist 中作为产品功能出现。
C10. **打分预览页**：评测脚本为每次运行生成一个本地静态 HTML 预览，把 `vibe` 块按组件粗略画出（标题、指标、对比、链条、推荐等用简单方框表示），旁边列出该次的 C6 指标与评分栏；只用于用户打分，不是正式渲染器。

## 5. 验收

**执行方自动检查**
- 评测脚本的固定夹具测试（`node --test`）覆盖：合法块、未知组件、字面数字、未闭合块、块外正文统计、正文不在最后一步；C10 预览对夹具生成且不含脚本执行。
- C9 测试：未设置变量时启动参数与修订前逐字一致；设置有效路径时多一个 `--patch` 且位于固定叠加层之后；路径不存在或非绝对路径时拒绝启动；变量不进入 DSH 环境白名单。
- `node scripts/verify-protocol.mjs`、`verify-docs.mjs`、`verify-invariants.mjs`、`git diff --check` 通过。

**执行方回填**：C4 可行性结论；每题每次的 C6 指标表与汇总；C7 判定建议；C8 渲染路径（文件与行号）与可行性；失败样例（只摘组件块与指标，不贴整段对话）；实验提示词全文与本次运行的模型、日期、耗时、用量。

**用户操作与验收**：按交接中的命令带开关重启工作台；执行方跑完后用不带开关的方式重启恢复；在 C10 预览页打分；阅读 C7 判定与失败样例，决定 S1 方案。

## 7. Stop Conditions

停止范围：只停对应子项，写进交接后继续其余工作。

- C9 无法在不改变未设置时启动参数的前提下实现，或实验段需要修改 Stock 插件才能注入：停该子项，回填原因。
- 首次核对时会话系统提示中没有实验段：停止运行，回填加载路径排查结果。
- 运行中出现不经用户确认、自动生效的 Wiki 写入：停止运行，回填已发生的写入。回答后整理产生的抽取与维护提案属测试环境正常写入，不触发停止。
- 浏览器自动化需要读取或填写凭据、改模型或改权限模式：停该子项。
- 用量明显超出预期（单次运行超过 300K tokens）：停下回填，由用户决定是否继续。
