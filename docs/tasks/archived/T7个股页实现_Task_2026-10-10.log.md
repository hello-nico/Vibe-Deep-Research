## 2026-10-10 · codex1 · 开工读取契约（先于实现）

P5 读口定为 `GET /api/v1/wiki/companies/{symbol}/page-research`，symbol 沿现有 `600863.SH` 格式规范化。纯读取，不调用模型、不刷新 provider、不创建任务。未保存时返回 research:null；Backend 不可用仍为 HTTP 错误，不能当成研究缺失。

回包直接贴合 `CompanyPageResearchRead`（这里有意使用 camelCase，避免 Vibe 为独立页面再复制字段适配）：

```ts
{
  research: null | {
    companyType: 'generic' | 'commodity_cycle' | 'leveraged_cyclical_utility' | 'scarce_asset_rent',
    researchedAt: string, // Backend 保存时的 UTC ISO 时间
    basisVersion: string, // 本次研究读取并冻结的资料版本
    sections: Array<{ id: 0|1|2|3|4|5|6, summary: string,
      details?: string, change?: string, refs?: string[],
      components?: { markdown: string, check: unknown } }>,
    related?: Array<{ topicId: string, title: string }>
  },
  stale: boolean,
  basisVersion: string // 当前已入库资料版本，不是旧研究版本
}
```

每节的 components.check 为 Stock 同一 S1 `checkVibe` 生成的检查结果，路径编号对应该节清理后的 markdown；坏元素实际移除并在保存记录内保留诊断，不让前端只靠隐藏坏元素承担保存校验。各节 summary/details/change 禁止字面数字；数据只在引用绑定的 S1 组件中展示，refs 需 Backend 可回读。缺数据用中文缺口，不补零。

`basisVersion` 是规范化公司身份与三类一级资料（annual_report、quarterly_report、announcement）各最近 200 份入库记录及其 active parse revision/hash 的确定性 SHA-256；范围沿 DocumentStore 每类最大 200 条读取能力。新入库或 active revision 变化即使研究变旧；新闻/研报、行情刷新及 Wiki 重编译不改变此版本。研究缺失时 stale=false；已有研究版本与当前版本不同则 stale=true，仍返回旧版。过期通过资料版本对比派生，不另建 stale 数据写入器、迁移或容器任务。保存发生版本竞争时拒绝覆盖，保留旧版。
