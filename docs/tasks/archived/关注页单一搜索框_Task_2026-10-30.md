## 1. 目标

关注页只留一个框：
- 输入时先筛已关注的公司；
- 同时列出最多 5 个可以加入关注的 A 股候选，点一下就加；
- 名字输错一点（如「山东黄金股份」）也能找到「山东黄金」。

## 3. 冻结决定

**接口约定（两边都以此为准）**

`GET /api/v1/securities/search?q=<文字>&limit=5`（前端经 `/finance-research` 代理，用 `researchRead('/securities/search?...')`）返回：

```json
{ "as_of": "2026-10-30", "items": [
  { "symbol": "600547.SH", "name": "山东黄金", "exchange": "上交所", "match": "name" }
] }
```

- `match` 取 `code`、`name`、`fuzzy` 或 `pinyin`，前端可以不用。
- `q` 为空或只有空白时，返回空 `items`。
- 名单还没拉到、拉取失败时，返回 503 `{code:"securities_unavailable"}`。前端此时只显示已关注的筛选结果，不报错。

**B 后端（codex1）**
- **名单**：A 股全市场（沪、深、北），字段包括代码（带 `.SH`、`.SZ`、`.BJ` 后缀）、名称、交易所。
  - 每天第一次用到时拉一次，存进现有磁盘缓存，沿用 `read_cache` 的规则，不另建一套；
  - 启动预热可以顺带拉一次，但不阻塞启动；
  - 用现有依赖和数据源，不新增依赖。
- **匹配**，按以下顺序打分：
  1. 代码精确或前缀；
  2. 名称包含输入，或输入包含名称；
  3. 容错：先去掉「股份、集团、控股、有限公司、有限责任公司、公司、科技、A、B」等后缀和空白，再匹配；仍然没有，就按字的重合程度排序，阈值由执行方定，并用测试说明理由。
  - 「山东黄金股份」必须返回「山东黄金」，并排在第一。
- **拼音首字母**：现有数据源或依赖里能拿到就做；拿不到就不做，在 §9 说明。不为此新增依赖。
- **测试**：
  - 代码、名称、后缀容错、字重合排序；
  - 空输入；
  - 名单缺失时返回 503；
  - 缓存一天只拉一次；
  - 用户隔离（只读公共名单，不涉及用户数据）。
- 契约写进 Stock `docs/`，按现有风格。

**F 前端（claude1）**
- 去掉页首「添加关注」按钮和下面那块单独的输入框（textarea、`adding`、`add()` 中只为它服务的部分）。
- **搜索框**：仍然筛已关注的列表，行为不变。框里有文字时：
  - 列表上方或下方出一块「加入关注」候选：调用上面的接口（输入停顿约 250ms 再请求，新请求取消旧请求），最多 5 行；
  - 每行写名称、代码 · 交易所，右边灰底全圆胶囊「加入关注」；
  - 已在关注里的不出现。
  - 点「加入关注」后：沿用现有的 `addWatch` + `addToRoster` 逻辑，成功后列表刷新，这家出现在已关注里，搜索框保留文字。失败时在那一行下面写一句灰字。
- **粘贴多个代码**：输入里能用 `addCodes` 解析出 2 个及以上代码时，候选块第一行写「加入这 N 只」，点一下批量加，沿用现有 `add()` 的逻辑和提示文字。这包括港股、美股代码：它们只进自选，不进研究名单，沿用现有提示。
- **只输入 1 个港股或美股代码**（比如 `AAPL`、`00700.HK`）：候选块出一行「加入 AAPL」。
- **没有任何候选、也没有已关注的匹配时**：写「没找到，试试代码或公司全称」。
- **接口 503 或网络失败**：只显示已关注的筛选结果，不出候选块，不弹错。
- 第一次打开（`FirstOpen`）的流程不动。
- **测试**（happy-dom，接口用替身）：
  - 「山东黄金」出候选并能加入；
  - 已关注的不出现在候选里；
  - 粘贴多个代码时出「加入这 N 只」；
  - 503 时不出候选；
  - 输入法拼写期间不发请求（依赖 WorkspaceSearch 已有的行为）；
  - 页面上不再有单独的添加输入框。
- `docs/design.md` 里关注页一段同步改。
- 界面文字只写最小草稿，§9 逐条列出位置，Claude 定稿。

### B 第二轮修订（Claude 10-30 审阅 B 后追加，交 codex1）

**原因**：
- Claude 实测，东财 clist 整份名单分页拉取当前大多返回 502：8 页中 6 页失败，push2、82.push2 也失败。akshare `stock_info_a_code_name` 访问深交所时 SSL 断开。一次性拉全名单在本机不可靠。
- 东财搜索建议接口 `https://searchapi.eastmoney.com/api/suggest/get?input=<q>&type=14&token=D43BF722C8E33BDC906FB84D85E326E8&count=10` 实测稳定。
- 「山东黄金」「sdhj」「600547」「山东黄」都能返回 600547 山东黄金，带 `MktNum`、`SecurityTypeName`、`PinYin`；只有「山东黄金股份」返回空。

**改法（B 第二轮）**
- 数据源改为这个搜索建议接口，按次查询；删掉全名单分页拉取那一套（provider、缓存登记里只为它服务的部分），不保留两套。
- 只保留 A 股：`SecurityTypeName` 为沪A、深A、北A（或 `MktNum` 与代码前缀能判定为沪、深、北）的条目；港股等丢弃。`symbol` 带 `.SH`、`.SZ`、`.BJ` 后缀，`exchange` 写上交所、深交所、北交所。
- 容错按顺序尝试，拿到 A 股结果就停：
  1. 原文；
  2. 去掉后缀和空白后的文字（后缀表沿用第一轮）；
  3. 第 2 步结果的前 4 个字；
  4. 前 3 个字。

  去重后最多查 3 次，每次都走现有的东财限速器。「山东黄金股份」必须返回 600547 第一。
- 每个查询词的结果按 `read_cache` 现有规则缓存一天，失败不缓存。接口失败或超时返回 503 `securities_unavailable`，接口约定不变。
- `match` 字段：代码命中写 `code`；拼音命中（输入是字母且等于 `PinYin` 前缀）写 `pinyin`；原文命中写 `name`；靠第 2 到 4 步才命中写 `fuzzy`。
- 测试改为用 HTTP 替身覆盖：原文命中、去后缀命中、截短命中、只返回港股时为空、失败返回 503、缓存命中不再请求。契约文档同步。
- 回填 §9 B 小节时，追加「第二轮」一段，不删第一轮。
