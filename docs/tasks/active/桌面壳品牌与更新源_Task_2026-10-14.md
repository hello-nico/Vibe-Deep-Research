# 桌面壳品牌与更新源

状态：2026-10-14 Claude 写定（todo §1.5 内测首发打包线；依据可行性报告 `.local/desktop-spike/report.md` Q5、Q6）。执行方在 deepseek-harness 的独立 worktree 中实施，不提交、不 push、不上传、不签名，不读 `.env`、证书与密钥。

## 1. 目标

把 DSH Desktop 壳里写死的 DeepSeek 品牌与更新地址，改为由一份产品配置提供，默认值仍是上游原样。设置为我们的产品时，应用名、图标、关于面板、启动协议与自动更新地址都换成我们的。产品插件的装入不在本 Task（随 DSH 升级合入后另立）。

## 2. 现状（可行性报告 Q5、Q6）

- 配置与资源：`apps/desktop/scripts/electron-builder-config.mjs`（productName、artifactName、protocol、appId、分类、麦克风说明；`:249` generic provider、nightly channel）、`resources/icon-macos.png`、`icon-windows.*`、`tray-windows.ico`、Windows 安装器资源。
- 源码常量：`src/main.ts:932` `applicationName`；`src/locale.ts` 关于、菜单、欢迎、更新文案中的品牌词；`main.ts:1232` 打包版启动时 `setAsDefaultProtocolClient('dsh')`。
- 更新：`scripts/desktop-auto-update-environment.mjs` 的 production origin 固定为 `https://download.deepseek.com`，test origin 才接受配置；版本号受 `src/release.ts`、`runtime-tree.ts` 校验（壳与 dsh 同版本），`--build-version` 可加后缀。

## 3. 冻结决定

R1 **一份品牌配置**：新增 `apps/desktop/branding.json`（或等价的单一入口），字段：`productName`、`appId`、`protocol`、`iconMac`、`iconWindows`、`trayWindows`、`updateOrigin`、`updateChannel`、品牌词（中英）。不提供时用上游原值，上游行为不变。
R2 **替换点**：R1 的字段贯通到 electron-builder 配置、`applicationName`、`locale.ts` 品牌词、协议注册与更新地址；协议注册使用 `protocol` 字段，不再写死 `dsh`。
R3 **更新源**：production 也接受 `updateOrigin`（HTTPS 必须），未配置时保持 `download.deepseek.com`；不改更新校验与签名策略。
R4 **产品配置样例**：在 worktree 里放一份我们的样例配置（名称「Vibe Finance」、appId `com.vibefinance.desktop`、协议 `vibefinance`、更新地址占位 `https://updates.example.invalid/vibe`，图标暂用现有 `desktop/dsh/finance-ui` 的图标转出的 PNG），用它打一个 macOS arm64 未签名目录包验证；不上传。
R5 不做：签名与公证、上传、产品插件装入、Windows 实际构建（只保证配置在 Windows 路径同样生效并有测试）。
