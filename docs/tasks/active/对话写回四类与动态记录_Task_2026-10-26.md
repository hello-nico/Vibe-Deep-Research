## 1. 目标

对话里用户表态或确认后，Agent 能把四类内容写回个股研究，每次写回有版本、可撤回，并在动态留一条记录；不再出现「待授权」更新提议。

- 缺：论点一句话、支柱、证伪条件的写回；候选影响因素（纳入 / 排除 / 观察）；写回在动态里的记录。

## 3. 冻结决定

R1 论点与支柱：新工具（或扩展现有写回）可改 thesis、单条支柱文字、证伪条件；与变量写回共用同一版本链与撤回接口；必须带 reason（≤60 字）与来源会话。
R2 候选因素：新对象「候选因素」（公司、名称、为什么、来源会话、状态：候选 / 纳入 / 排除 / 观察）；Agent 只能创建为「候选」；状态由用户操作改（接口给前端调用）；「纳入」触发该公司研究的下一次重算（复用继续研究或敏感性重算入口，执行方核实最小路径），「排除」记理由进记忆不再推荐。
R3 动态记录：每次写回（变量、论点、候选状态变化）生成一条用户层动态记录：一句话（改了什么、估值档位有无变化）、来源会话、撤回入口所需的版本标识；动态接口返回这类记录。
R4 去掉对话后整理对公司页的 `awaiting_authorization` 研究更新提议；整理只保留记忆与知识类写入。
R5 「开始观察」的观察项文字：查清 `literal_number` 规则在哪一侧（Stock 推荐生成或 Vibe 校验），若可在生成侧把数字放进 metric 字段而非文字则改之；改不了记缺口。
R6 不改提示词与前端（Claude、claude2 另做）；工具描述与 model-surface 快照随改。
