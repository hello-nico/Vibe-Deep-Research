## 3. 冻结决定

C1. **标记**：模型生成成果后，在正文对应段落之后单独写一行 `![图标题](result:<32 位小写十六进制>)`，正文里不再另写成果 ID。
C2. **补丁（2026-10-08 改写）**：只允许改 `dsh-web-frontend` 产物中 Markdown 模块的三处，并合并进现有的 `dsh-web-frontend` 补丁文件（保留 `stock-ref:` 那部分改动）：
  ① **图片**：地址是 `result:`、并且产品已注册渲染函数时，使用该函数返回的元素；函数返回空值或未注册时，保持原行为（显示 alt）。
  ② **段落**：一个段落里只有一张 `result:` 图（不计空白）时，不用 `<p>` 包裹，直接按块渲染；其他段落保持原样。
  ③ **流式末尾**：流式输出时，正文末尾尚未写完的 `![…](result:` 片段不显示，可以显示一个中性占位（例如图标题，或"图表生成中"），写完后直接变成图；已经结束的消息不受影响。
  三处以外的逻辑一律不改。注册入口的形式与名称由执行方确定，并在回填中说明。
C3. **产品注册**：finance 客户端插件激活时注册渲染函数，失效时注销。函数校验 ID 格式，合法时返回 `ResearchResult`：图直接可见，悬停显示数值，图下方有口径说明，不需要点击。ID 不合法时返回空值。

C5. **去重**：本轮最终回答正文里已经用标记嵌入的成果，`resultDefinition` 不再在回答后面重复显示卡片；没有被嵌入的成果照旧显示。
C6. **提示词**：原型跑通后，在 `DEEP_PROMPT` 末尾加一句，说明 C1 的用法（生成成果后在对应段落单独一行写标记，不另写成果 ID）。只刷新 `deep_research.json` 快照。
C7. **数据**：只使用现有成果类型（A 股行情图、年度财务图），不新增 Backend 出图工具。
C8. **登记**：运行时 README 补丁表中 `dsh-web-frontend` 一行补写这一项：类型为「产品功能」；移除条件为"上游 Markdown 支持由插件注册内嵌协议渲染"。执行方在回填中附一段可直接提交给上游的需求描述。
