# 桌面安装包可行性

状态：2026-10-14 Claude 写定，用户同意（todo §1.5 内测首发第 1 步）。这是可行性验证：允许在独立 worktree 里构建，不改 Vibe、Stock 主目录代码，不提交、不 push、不运行 `scripts/start`、不碰用户正在用的工作台与 `DSH_HOME`，不读 `.env` 与密钥。

## 1. 目标

回答一个问题：以 DSH Desktop 为底座，装入我们的插件，能否得到一个在 macOS 上能装、能打开对话页、能连 Backend 做一次问答的安装包；Windows 走同一条路需要什么。并给出正式实施要改的清单。

## 2. 现状（Claude 核实）

- DSH Desktop：`/Users/apple/ts/src/deepseek-harness/apps/desktop`（版本 `0.2.1-alpha.2`，README.zh.md 已读）。
  - Electron 壳 + 打包的 dsh 运行时 + 内置 Node、pnpm、Python；`app.asar/dsh` 携带完整生产依赖树，profile 只安装外部插件。
  - electron-updater 更新，壳与运行时作为一个签名单元。
  - 打包脚本 `package:mac:arm64:dir`、`package:mac:arm64:unsigned`、`package:win:x64:unsigned` 等；上传脚本走对象存储（`desktop-cos.ts`）。
- 该仓库工作区有用户的未提交删除（`vendor/*/LICENSE`），**不要在主目录操作**，用 `git worktree add` 另开一个目录（允许的例外）。
- 我们的产品现在跑在 dsh `0.1.7-alpha.2` 上，带 11 个补丁（`Vibe-Deep-Research/desktop/dsh/runtime/README.md` 有逐条归属与移除条件），由 `npm ci` 的 postinstall 打进 `node_modules`。
- 我们的插件：
  - 界面与宿主：`Vibe-Deep-Research/desktop/dsh/finance-ui`（`package.json` 的 `dsh.bundle.patch` 指向 `cordis.patch.yml`，`dsh.client` 注入 Web 客户端；前端由 `desktop/dsh/build-ui.mjs` 构建）。
  - 研究能力：`Stock-Research/dsh`（`dist/` 为构建产物）。
  - 启动时 `desktop/dsh-dev.ts` 生成 `finance-runtime.patch.yml`（产品预设目录与默认 `vibe` 预设）。
- 本机数据服务 `orchestrator/` 现为独立进程（端口 8765），本 Task 只评估，不迁移。
- Backend 现为本机 `http://127.0.0.1:8700/api/v1`；插件经环境变量 `STOCK_RESEARCH_BACKEND_URL` 指向它。

## 3. 要回答的问题

Q1 **插件怎么装进去**：随包内置（进 `app.asar/dsh` 的 bundle 列表，和运行时一起签名、一起更新）还是首启作为外部插件安装。给出推荐与理由；内测要求离线可启动、插件与运行时版本一起发布。
Q2 **版本差**：Desktop 自带 dsh `0.2.1-alpha.2`，我们在 `0.1.7-alpha.2`。两个插件在 0.2.x 上能否加载；11 个补丁逐条判断：0.2.x 已解决 / 仍需要且能在 Desktop 构建链路里打上 / 需要改插件绕开。
Q3 **界面**：Desktop 从 `dsh-app://app/` 加载打包的 Web 入口；我们的界面是 `finance-ui` 浏览器插件。确认装入后首页即我们的对话页与导航，DSH 自带的头部按钮与预设按产品配置隐藏（现有规则见 Human Checklist「深度对话隐藏 DSH 自带预设」）。
Q4 **产品配置**：`finance-runtime.patch.yml` 与 `cordis.patch.yml` 在 Desktop 里怎么生效（profile patch、bundle patch 或构建时注入），以及 Backend 地址如何做成用户可配置项（不写死）。
Q5 **品牌**：应用名、图标、关于面板、更新源地址需要改哪些文件；能否只用配置与资源覆盖，不改 Desktop 源码。
Q6 **更新**：electron-updater 的发布地址怎么换成我们自己的；版本号规则（Desktop 要求壳与 dsh 同版本）对我们意味着什么。
Q7 **Windows**：在 macOS 上能否出未签名的 Windows 目录包；不能的话需要什么环境。
Q8 **本机数据服务**：`orchestrator/` 改成 DSH 插件需要动哪些地方（只评估，写清工作量与风险）。
