## 1. 目标

模型建敏感性模型时漏掉主要业务段（华友 10-26 漏正极材料、镍中间品），由引擎按数据确定性地退回，并告诉它漏了哪几段；规则对所有公司一致，不写特例。

## 2. 现状（Claude 核实）

- `backend/app/services/sensitivity.py`：`packet["segments"][request.split]` 是东财 F10 主营构成（`providers/company_segments.py`，接口数据，非报告解析），每段有 revenue / cost 字段；`match_segment` 把请求段名对到清单。变量按 var_id 合并，同一商品可同时作产品价格与原料。
- 华友 2026H1 product 口径：正极材料 22.0% 收入 / 毛利 18.8 亿，镍产品 19.4% / 21.1 亿，贸易及其他 17.2% / 15.2 亿，镍中间品 17.1% / 13.8 亿，锂产品 7.2% / 10.6 亿，三元前驱体 6.8% / 6.9 亿，钴产品 6.6% / 14.7 亿，铜产品 3.6% / 7.8 亿。10-26 请求只建镍、钴、铜、锂四段：毛利覆盖 54.2 / 93.7 = 58%（分母去掉「其他」段）。
- 段收入之和 555.7 亿 = 利润表接口 H1 营收 555.68 亿。
- 规则「失败两次即放弃，研究照常保存，不带 sensitivity」已在提示词。

## 3. 冻结决定

V1 前置自检：所选口径各段收入之和与数据包同期总营收（利润表接口字段）相差超过 3%，或大部分段收入缺失，则跳过覆盖检查，只在回执 warnings 写一句，不退回。
V2 覆盖率按毛利（段收入 − 段成本）计；多数段缺成本时改按收入计。名称含「其他」的段不进分母、也不要求建模。
V3 两条门槛，任一不满足即以 `PrimitiveError("segments_coverage_low", …)` 退回：①毛利（或收入）最大的段必须建模；②已建模段覆盖率 ≥ 门槛 T。错误文案列出未覆盖段名与占比、当前覆盖率与 T，并说明「可复用已有目录编号作为产品价格或原料，不增加变量数」。
V4 T 先校准再定：取已研究公司最近一次成功 sensitivity 的请求（凭据可由 read_research_result 或 Backend 研究结果存储读出），按 V1–V2 算各家覆盖率，§9 列表；T 取能让现有正常研究全部通过的整数百分比，建议 50–70% 之间，Claude 审定。
V5 只作用于 sensitivity 操作；valuation_template（银行、保险、volume_pe 等）不受影响。提示词由 Claude 另改，本 Task 不改 consumers.mjs。
