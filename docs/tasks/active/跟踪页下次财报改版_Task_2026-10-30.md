## 1. 目标

跟踪页「下次财报」从一张只写指标名的平铺列表，改成和价格行同一套做法：行上一句有用的状态，可以展开看研究里的证伪条件，以及已出报告的核对结论。

## 2. 现状（Claude 已核实）

- **Backend**：Stock `backend/app/services/tracking_next_reports.py`，路由 `api/v1/tracking.py:112` `GET /tracking/next-reports?symbols=`。
  - `checks_from_research` 只从研究的 `falsifiers` 里取字段名，最多 4 个。
  - 每条 falsifier 本来就带：`text`（一句话）、`fieldId` / `fieldIds`、`threshold`（`kind`、`value`、`unit`、`direction`）、`window`（如「2026年第三季度报告」）。真实样例见 `workspace/research/users/local/company-pages/600309.SH/current.json`。
  - 日期：`pick_next_report` 有预约日就写日期，否则只推出下一份法定报告，写 `date_note: "日期未定"`。
- **Vibe**：`pages/Tracking.tsx` 里的 `NextReports`，`lib/trackingItems.ts` 里的 `loadNextReports` 和 `nextReportWhen`。按关注顺序排，不可点开。价格行的展开样式、「另外 N 项」、展开状态记在本机，这些都可以直接参照 `PriceRow`。
- `docs/design.md` 目前没有这一块的说明。

## 3. 冻结决定

**R1 行上**
- 排序：有日期的按日期从近到远，其后是没有日期的（按法定截止日从近到远），同一天的保持关注顺序。
- 没有预约日时，写法定截止日：「年报 · 最晚 4-30」「一季报 · 最晚 4-30」「半年报 · 最晚 8-31」「三季报 · 最晚 10-31」，不再写「日期未定」。截止日在 Backend 按 A 股法定规则算，一处定义。
- 灰字指标名改短名：「归属于上市公司股东的净利润」写「净利润」，「经营活动产生的现金流量净额」写「经营现金流」，其余同理，短名表放在 Backend 的 `FIELD_NAMES` 一处。最多 3 个，多了写「等 N 项」。

**R2 展开**
- 点整行展开，再点收起，样式与价格行一致（箭头、展开区）；展开状态按行记在本机，沿用价格行的做法。
- 展开里每条证伪条件一行：
  1. 研究原文那一句（`text`）；
  2. 阈值一句，按 `direction` 写「低于 13.6% 就改判断」或「高于 … 就改判断」，金额按现有的亿元格式；没有阈值就不写这一句；
  3. 「看 2026 三季报」，从 `window` 转成短名；
  4. **核对结论**：`window` 对应的报告已经披露、系统能取到那一期这个字段的实际值时，写「已出：13.9%，未触发」或「已出：12.8%，已触发」。
     - 实际值只用现有数据（公司数据包、对账里已有的值），不新增数据源；
     - 取不到就不写这半句，不猜。
     - 判断「触发」只在 Backend 代码里比较，规则是 `threshold.direction` 加 `value`。
- 展开底部放一个灰底全圆胶囊「看{公司}」，进个股页。

**R3 篇幅**
- 默认只显示排序后的前 5 家，其余收进「另外 N 家」，点开显示全部，做法同价格列表的「另外 N 项」。

**其他**
- 不改研究内容和证伪条件本身，不改对账口径。
- 不做兼容：接口按新形状返回（例如 `checks` 改为带 `text / threshold / window / actual / triggered` 的对象数组），前端同步改。
- `docs/design.md` 的跟踪页一节补上这一块的说明，按现有写法。
- 界面文字由 Claude 定稿：执行方写最小草稿，并在 §9 逐条列出位置。
