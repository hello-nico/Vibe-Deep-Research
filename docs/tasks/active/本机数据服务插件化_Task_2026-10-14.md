## 1. 目标

本机数据服务（行情取数、页面查询、自选与偏好等 Client 存储）不再是单独监听 8765 的进程，而是由 DSH 宿主插件挂载的路由，生命周期交给 DSH 管。页面继续访问 `/finance-api/*`，业务接口与行为不变。这样装进 DSH Desktop 时不需要额外的进程与端口。

## 2. 现状（Claude 核实）

- `orchestrator/src/api.ts`：`http.createServer` 监听 8765，Bearer 鉴权，路由处理与业务调用写在同一个文件；业务在 `service.ts`、`client_store.ts`（SQLite）、`snapshot.ts`、`registry.ts`、`productConfig.ts`；`finance/register.ts` 以副作用 import 装配垂类；`data_root.ts` 用 `repoRoot` 与 `VRA_DATA_ROOT` 定位数据根；取数通过子进程调用登记的脚本。
- 前端：`desktop/vite.config.ts:73` 把 `/finance-api` 代理到 8765 并去掉前缀；DSH 的产品路由（`/finance-*`）由 `desktop/dsh-dev.ts` 代理到 DSH。
- 宿主插件：`desktop/dsh/finance-ui/server.mjs` 用 `ctx.webServer.register` 注册路由，`bindPluginRoutes` 统一在插件卸载时释放。

## 3. 冻结决定

R1 **一份业务实现，两种挂载**：把 `api.ts` 的路由处理抽成不依赖 `http.createServer` 的处理函数（入参：请求、响应、上下文）。`api.ts` 保留为独立启动入口（开发与诊断用），`finance-ui` 插件新增前缀路由 `/finance-api` 调用同一处理函数。业务模块不改语义。
R2 **鉴权**：插件路由走 DSH Web Host 已有的认证（与其他 `/finance-*` 路由一致），不再要求 Bearer；独立入口保留 Bearer。请求体上限、Origin 校验、错误码与安全响应头保持现状。
R3 **生命周期**：插件卸载或宿主关闭时关闭 SQLite 连接、终止进行中的取数子进程、清理定时器；重复挂载不泄漏连接。
R4 **路径**：数据根、产品配置、登记表与取数脚本的位置由插件启动时显式传入（从环境变量或产品配置读），不依赖进程当前目录；在仓库目录外启动 DSH 也能找到。打包时脚本与 Python 依赖如何随包分发不在本 Task（另立）。
R5 **入口收敛**：`desktop/vite.config.ts` 的 `/finance-api` 改为与其他 `/finance-*` 一样代理到 DSH；启动脚本不再单独拉起 8765 进程（保留独立入口命令供诊断）。`doctor` 等诊断检查同步。
R6 Client 存储仍只有一个写入方；模型不能读写 Client 文件（不变量）。
