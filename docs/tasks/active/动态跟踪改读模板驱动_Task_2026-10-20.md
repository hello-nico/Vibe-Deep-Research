## 1. 目标

对没有商品价格模型的公司（银行、电力、消费等），动态里的新闻也能标出碰到了它所属行业的哪个估值驱动；跟踪与「接下来盯什么」列出该公司模板的驱动，而不是只有下一次报告。

## 2. 现状（claude2 核实）

- 所属行业与模板：Stock `wiki/business_compiler.py` 写公司 Wiki 页 identity 块 `{industry, industry_code, parent_industry, valuation_template, …}`；数据包 `identity` 也带 `industry_code`（`find_constituent`）。
  - Vibe 此前不读这两处。个股页用数据包的 `identity.industry_code`。
  - 动态与跟踪没有数据包，改读公司页 `/wiki/pages/read?slug=companies/<代码>-<交易所>` 的 identity（比数据包轻）。
- 框架接口真实字段（Stock 主目录 `ValuationTemplates().framework` 的真实输出，已存为 `frameworks_real.json`）：`industry_code/industry_name/template{id,name,method}/drivers[{id,name,kind,source}]/core_questions/chains/companies`。
- 与 Task 假设不同处：`drivers` 来自行业 Profile 的指标，`kind` 是 Profile 里的零散备注（如「季报。」「全部」「估值」），不是分类；**没有逐条「影响什么」的说明**。`drivers` 里混有结果指标（营业收入/归母净利润、PE/EPS 预测、ROE/市净率、毛利率/净利率、PB 与 DDM 假设）。
- 现行 `feedFactor.ts` 只按已存研究里的价格变量名匹配标题；`watchItems` 无价格模型时只取数据包 `industry_drivers` 里有数的字段（华能、农行大多是缺口），所以常只剩「下一次报告」；跟踪页「研究」行只有研究进度与跳档句。

## 3. 冻结决定

G1 驱动来源：有价格模型的公司照旧用研究里的价格变量（含每步影响）；其余按所属行业框架的 `drivers` 列出，没有数值时只写驱动名与一句「这个因素影响什么」，不编数字。
G2 动态：新闻标题命中模板驱动名或其常用说法时，加一句「碰到{驱动}：影响{估值什么}」；命中价格变量的保持原句式。同一条只写一句，价格变量优先。
G3 跟踪与「接下来盯什么」：无价格模型的公司列出模板驱动（最多 3 个）加下一次报告；有价格模型的不变。
G4 不新增内部用语（`ui_wording.test.ts`）；遵守 design.md §1。
G5 测试：农行（bank_pb）、长江电力（infra_yield）、神火（commodity_pe）三家夹具。

   - 个股页的驱动卡没有数值时不画数字，数据包里有数的驱动先列，框架驱动补到共三个。
