状态：2026-10-14 Claude 写定（todo §1.5 内测首发打包线关键路径；依据可行性报告 `.local/desktop-spike/report.md` Q1、Q3、Q4、Q8）。执行方在 deepseek-harness 的独立 worktree 中实施，不提交、不 push、不上传、不签名，不读 `.env`、证书与密钥，不碰用户正在用的工作台与 `DSH_HOME`。

## 1. 目标

打出一个 macOS arm64 未签名目录包：安装后离线首启即是我们的产品（对话首页、六个导航、个股页等），研究插件可用，Backend 按设置里的服务器地址连接。插件与运行时随包内置、一起版本化。

## 2. 现状

- 主目录已在 DSH 0.2.1-alpha.2（Vibe `c9597384`、Stock `a1b4818`），与 DSH Desktop 基线 `d743267388` 同版本，Stock peer 兼容问题已解决。
- 可行性报告 Q1：内置需同时改 `apps/desktop/src/project-manager.ts:134`（内置运行时依赖与 bundle 清单）与 `:178` `createPluginProfile`（首启 profile 的 bundle 列表），并在 `scripts/prepare-dsh.ts`/package-set 装入两个产品包及完整生产依赖闭包；仅放进 ASAR 不会激活。
- Q4：Desktop 不经过 Vibe `desktop/dsh-dev.ts`，不会生成 `finance-runtime.patch.yml`；默认预设 `vibe` 需并入产品 bundle patch。服务器地址已由 `DSH_HOME/research/backend-connection.json` 提供（设置 → 连接）。
- 产品插件：Vibe `desktop/dsh/finance-ui`（`local-data.mjs` 以相对路径引用 `orchestrator/src/*.ts`，打包时 orchestrator 源码要随插件一起带上，或改为插件内的稳定入口）；Stock `dsh`（`dist/` 构建产物）。
- 运行时补丁：Vibe `desktop/dsh/runtime/patches/` 的 9 个 0.2.1 补丁（2026-10-14 Claude 更正：原写 10 个有误，以目录为准），Desktop 的 `scripts/runtime-patch-policy.ts`、`prepare-runtime-patches.ts` 可纳入；前端内联进 Web bundle 的补丁须在 Web 构建前打上。
- 本机取数的 Python 脚本将迁到云端 Backend（另立），本 Task 不处理 Python；包内取数类页面暂时可以失败，但不能让首启或其他页面报错。

## 3. 冻结决定

R1 两个产品包与其生产依赖随包内置；首启 profile 的 bundle 列表包含它们；不走首启联网安装。
R2 产品配置（默认预设 `vibe`、隐藏 DSH 自带入口的现有规则）全部经产品 bundle patch 生效；不依赖开发启动脚本。
R3 9 个运行时补丁经 Desktop 的补丁通道打上，`check-inline-result.mjs` 等价的回归检查在打包流程里运行。Web 补丁改的是构建产物，因此 Desktop 的 Web 使用 npm 发布的 `@deepseek-ai/dsh-web-frontend@0.2.1-alpha.2` 构建产物（与开发工作台同一份），不从 `apps/web` 源码重建；补丁在产物就位后、打包前原样打上（2026-10-14 Claude 裁定，回应 Codex 提问）。
R4 `finance-ui` 对 `orchestrator` 源码的依赖在包内可解析（随包带上或改为插件内入口，择一并说明）；不在用户机器上要求 Node 以外的运行环境。
R5 品牌与更新源由「桌面壳品牌与更新源」另一条线的补丁负责，本 Task 不改品牌；两份补丁最后由 Claude 合成。
R6 不做：签名、公证、上传、Windows 构建、Python 取数。
