# 产业链推荐按主营产品（Stock 后端）

2026-10-26 claude 写定，交 pi3。Stock worktree `.worktrees/pi3-chainreco`（基于 HEAD，已带入主目录未提交改动）；不提交、不重启、不读凭据。
依据：claude3 验收探测（8700 只读）：紫金 601899.SH 的 recommendations 返回「煤—电—铝」；Checklist 2026-10-20「产业链是用户对象」（申万成分只用于生成与推荐，不能错挂）。

## 1. 目标

个股页「推荐所在链」与「同环节还可关注」只出现主营确实属于该环节的公司；紫金不再被推荐到煤—电—铝。公共链说明不露内部词。

## 2. 现状（Claude 核实）

- `backend/app/services/user_chains.py` `recommendations()` 与 `candidates()` 直接用公共链节点的 `companies`，即申万二级成分；紫金属「工业金属」，与电解铝同一个申万二级，所以被挂上。
- 数据包同业选取已有按主营产品判断的做法：`company_data_packet.py` 用 provider 主营构成，取有效正收入最大的产品（`select_product_peers`），不按申万成员或公司名称。
- 公共链驱动说明里露出 `infra_yield`、`commodity_pe` 这类模板 id（claude3 截图所见），来源在公共链生成或 `app/data/valuation_templates.json` 的说明文字。

## 3. 冻结决定

Q1 节点公司 = 申万成分 ∩ 主营最大产品与该节点产品相符；判断复用数据包同业选取同一套主营产品规则，不新写关键词表，不写公司特例。
Q2 主营产品数据缺失的公司不推荐、不进候选（宁缺勿错），并在接口里给出 `reason`。
Q3 推荐与候选同一过滤；公共链 `GET /wiki/chains` 的成分展示同步改，避免页面与推荐不一致。
Q4 面向用户的说明文字不出现模板 id 或英文内部名，改用中文估值方法名。

## 4. 范围

Stock `user_chains.py`、公共链生成或读取处、相关说明文字、测试、`docs/user-chains-contract.md`。
