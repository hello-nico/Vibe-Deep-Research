## 3. 冻结决定

### 3.1 Backend：今天的估值

**D1 接口。** `GET /api/v1/tracking/valuation-today?symbols=A,B`，按用户隔离。只读：不写库、不写结果、不调用模型、不改已存研究。单家失败只影响该家。

**D2 每家返回。**
```
{ symbol, status: "sourced" | "gap" | "not_researched", reason,
  as_of,            // 判定所用收盘日
  close,            // 该日股价收盘
  prices: [{ var_id, name, unit, value, date }],
  research: { grade, base_grade, researched_at },
  grade_base,       // 今天的基准档
  grade,            // 今天的档位 = 基准档 + 偏移
  changed_on,       // 当前档位连续成立的第一天；与研究档相同时为 null
  history: [{ day, grade }],  // 研究日起每个交易日，供测试与排查
  targets: { 悲观, 中性, 乐观 } | null,
  near: { var_id, name, unit, value, gap_pct, to_grade } | null }
```

**D3 只认收盘价。** 股价和商品价都用日线收盘，判定日是不晚于今天、股价已有收盘的最近交易日；商品取该日及之前的最近收盘。盘中报价不参与。

**D4 敏感性模型公司的算法。** 模型取研究时 `sensitivity.resultRef`，倍数取 `valuation.scenarioRef`。对判定日：
```
shift  = Σ coef_per_unit × (当日收盘 − 研究时 current)，只算有日线行情的变量；没有行情的按研究时取值（shift 贡献 0）
target = max(0, (档位 profit + shift) × 档位 multiple ÷ shares)
zone   = reference_position(close, 悲观, 中性, 乐观)；grade_base = GRADE_BASE[zone]
```

**D5 其他模板公司（股息率、银行、保险、同业）。** 用该模板现有的纯计算函数，按判定日收盘价算 `grade_base`，不走会写结果的 `calculate_template`。输入缺失返回 `status: "gap"`，`reason` 写清缺什么。历史收盘如无法便宜地重算，`history` 只给判定日，`changed_on` 回退到「最近一次档位不同于研究档的已知日」或 null，并在 §9 写明。

**D6 偏移。** `偏移 = 研究档序号 − 研究时基准档序号`，序号按五档顺序。研究时基准档优先取已存的 `grade_base`；没有就用研究日及之前最近收盘按同一算法重算。`grade` 为今天基准档加偏移，越界时夹到五档两端。例：华能国际研究基准档明显低估、研究档偏低，偏移 +1。 已存基准档与收盘重算不一致时不算错，直接用已存的（研究时用的是报价，收盘本来可能不同）；不能让公司因此变成 gap。

**D7 `changed_on`。** 从判定日往回逐日算，取 `grade` 连续不变的第一天，最早到研究日。`grade` 等于研究档时为 null。

**D8 `near`。** 只算主价格（`variables[0]`），用判定日股价和其余变量的今日值，解出下一个让档位改变的主价格；距现价 3% 以内才返回（沿用前端 `FLIP_NEAR`，如其值不同以其为准并在 §9 写明）。方向相反、超出系数范围或档位不变的边界不返回。

**D9 性能。** 复用 `read_cache`，同一收盘日内同用户同模型结果可复用。每家行情失败只让该家 gap。不向外部接口做高频请求：同一轮相同标的只取一次。

### 3.2 前端

**D10 一个来源。** 新增 `lib/valuationToday.ts`，读一次接口，动态、跟踪、公司页共用。不再用价格比对跳档价来判断档位：删除 `flipCards` 的 crossed 分支，`flipLines` 改用 `near` 与接口结果。

**D11 估值卡（类型「估值」）。** 只在 `status=sourced` 且 `grade ≠ research.grade` 时出现，股价和商品价引起的用同一种卡。
- 第一句：`<公司>现在估值<grade>（研究时<research.grade>）`
- 第二行：`<公司> · 股价 <close>，<主价格名> <价格>`；没有主价格时只写股价。
- 底行日期：`changed_on`；为 null（D5 只知判定日）时用 `as_of`，且这种卡不置顶。
- key：`valuation:<symbol>:<changed_on>:<research.grade>><grade>`。档位再变就是新 key，重新置顶。
- 用户可见文字不出现「跳档价」。

**D12 接近提醒。** `near` 存在且档位未变时出一张不置顶的「估值」卡：`<主价格名>距 <价格> 只差 <x>%，越过后<公司>估值变为<to_grade>`，日期为判定日。key 不含日期，每个交易日不重新点亮小圆点。

**D13 财报卡回归事件。** 不再置顶；按日期排序。第三行写成 `研究时估值从 A 变为 B`，今天的档位不同时补 `，现在 C`；`gap` 时不补。`估值没变（X）` 和新资料提示保持原样。 财报卡第三行不等今天的估值：估值读得慢时先显示研究时那句，读到后再补「现在 C」。

**D14 对话调整卡。** 档位变化时仍置顶，并服从 D15。

**D15 一条置顶规则。** 置顶卡只有估值卡（D11）和档位变化的对话调整卡（D14）。卡片日期起算满 3 个自然日（`今天 − 日期 >= 3`）或被用户取消，就不再置顶，按日期排入普通流。日期由 Backend 给的判定用，「今天」取北京时间。

**D16 取消置顶。** 仍在置顶的卡片底行显示按钮「取消置顶」。点击立刻生效，存到 Client 偏好键 `finance.feed-unpinned`，值是 card key 数组的 JSON 字符串，手机和电脑共用。`orchestrator/src/client_store.ts` 的 `PREF_KEYS` 与 `lib/prefs.ts` 的 `PERSISTED` 都登记此键；只有这个键的值上限放宽到 16384 字符，其余键仍是 64。超限时丢弃最早的 key，最多留 200 个。不提供重新置顶。写失败时恢复原状并给出提示。新 key 不受旧记录影响。

**D17 小圆点。** `feedAttention.ts` 改用估值卡 key，复用已有已看逻辑。同一 key 只亮一次。

**D18 跟踪页。** 走势图的线改读接口：`near` 画线，文字沿用 D12。没有 `near` 不画。

**D19 公司页页首。** 档位读今天的估值：`估值<grade>（研究时<research.grade>，<as_of 月-日>收盘）`，相同时只写 `估值<grade>`，`gap` 或未读到时退回已存研究档，并在同行标 `研究时`。隐含价部分（`verdictLine` 其余逻辑）不改。滑块试算不改。

**D20 助手快照。** 动态与公司页的助手页面快照使用同一套今天的档位与研究档，不再把旧结论说成现在的判断。

**D21 失败。** 接口失败只影响估值卡和页首：动态其他卡片照常，页首退回 D19 的写法，不白屏、不静默写成今天的结论。

**D23 不复权日线主备。** `providers/dividend_history.py` 的不复权日线改为腾讯为主（`web.ifzq.gtimg.cn/appstock/app/fqkline/get`，`param=<sh|sz><code>,day,<start>,<end>,2000,`，读 `data.<sym>.day`，第 1 列日期、第 3 列收盘）、东财为备；三年历史校验、`sources` 如实写实际来源。分红仍用东财 `BONUS_URL`。11-06 实测东财 `push2his` 持续 TLS 失败、腾讯与分红接口正常。

**D22 不变的。** 不写回研究；`page-research` 的 `grade` 仍是研究结论；重新研究只由用户发起。
