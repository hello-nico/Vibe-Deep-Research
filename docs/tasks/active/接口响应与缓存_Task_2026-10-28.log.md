### 本轮修复与 Owner

- 共用读取层 `lib/readRequest.ts` 按公司研究、关注列表、写回记录维护版本；写入结束（包括结果不确定）推进对应版本，写入不重放。同版本、URL、参数及身份请求头才合并。迟到的响应或错误若版本已变即丢弃重读，已缓冲但延后解析的 text/json/arrayBuffer 同样检查并同步新 HTTP status/ok/headers。
- `CompanyPageStore` 不再用私有 reading 跨版本合并；合并迁至同一共用层的 `shareObjectRead`。旧 Store promise 与写后 promise 不同，旧输入不能发布给页面。`readObject` 只用于公司研究后续任务补读、写回记录名称补读、关注列表驱动的组合读取；research/api/localService 不再重复包版本循环。
- Backend `invalidate_company` 只失效 workspace 内依赖该公司的条目；其他用户的数据仍分别分键，不跨用户共享私有结果。同行 packet 的 key 登记依赖公司，因此有关同行可失效；无关公司的独立缓存保留。主营构成为共享全库快照，含该公司的聚合条目重读，其他行情/序列不全清。
- 新增 `workspace/cache/epochs/<symbol>.json` 原子保存公司代次，代次同时进入内存 key 与磁盘 digest，且只取一次，避免跨 epoch 拼接。先持久化新代次再清旧文件；旧文件删不掉也无法被当前 key 命中。重启恢复代次后可继续用当前磁盘缓存。损坏代次进入新命名空间；代次持久化失败报错，不能默默声称失效完成。
- 失效的 Backend 计算不能用仍持有旧研究/packet 的闭包原地重算：`InvalidatedRead` 不落缓存，统一转成既有 retryable 503 形态与 Retry-After:0，经前端一次 GET 重试重新进入正式入口。page-research 在整次入口开始和完整返回前检查公司代次；material 读取不吞这类异常。研究保存/写回/撤回都经既有 `publish_research_record` 触发局部失效；coverage ensure 的 finally 只失效本公司。
- 数据包成果版本戳由全库结果条数改为本公司 market 结果查询，避免别家公司保存成果打冷 packet；不改数据库结构。相应 SQLite 夹具补上真实 schema 已有的 payload 列，版本戳断言改为检查公司条件。
- 返回按钮从取名焦点捕获区域移出，只有切换器聚焦才补其他关注公司名称；离页取消该批读取。动态对账及结果读取的部分错误上送统一 ReadFailure，保留成功卡片，手动重试能恢复；读取失败时不显示“没有动态”。
- Stock `.gitignore` 增加 workspace/cache/，避免新私有派生缓存进入后续提交。没有清理研究或迁移数据。
