## 3. 冻结决定

**G2：对话 HTML 图**

- **V1**：组件目录新增一个 `html` 组件，写成 ```vibe 围栏里的 `<html title="…">…</html>`，或者等价的单独围栏，由执行方选一种。规则一处定义：图上的数字都来自核对过的 ref，和报告的 `data-ref` 规矩相同。
- **V2**：校验全部复用报告底子，不另写一套：
  - 先过 `validate_report_html` 的安全和格式检查，对话用的大小上限可以更小；
  - ref 必须是本轮工具真实返回过的；对话没有「页面快照」，允许集合取本会话里工具返回过的 ref，由执行方确定实现；
  - 每个 `data-ref` 元素里的数字，要和 ref 解析出的值一致。这里要把 `check_citation_numbers` 扩展到 `provider:` 和 `result:`：用 `strict_metric_source_match` 或等价办法，按单位换算后比较，比如元和亿元，两位小数以内算一致；
  - `data-ref` 之外的正文不许出现数值字面量。年份、季度名（Q1–Q4）、轴刻度除外，轴刻度由脚本按数据生成。
  - 不合格就整块丢掉，正文照常显示，丢掉的原因记进会话记录。行为和现有组件的 `drop` 一致。
- **V3**：渲染复用 `WikiReportPane` 的 iframe 方式：`sandbox="allow-scripts"`、`srcDoc`、CSP 由 `wrap_report_html` 这类封装加上。此外参考 t3code，加三点：
  - 宿主注入主题 CSS 变量，页面只用变量取色，深浅主题自动跟随；
  - 页面用 postMessage 回报内容高度，iframe 按高度自适应；
  - 版式规则写进提示词：不加外框和标题横幅，不用 vh 和 `height:100%`，图表用固定像素高，宽度跟随回答栏，390px 不出现横向滚动。
- **V4**：提示词写进 `VIBE_CATALOG_PROMPT`：图只在比文字更快说明问题时用，按问题和数据本身的特点决定，不强行出图（Owner 10-28：「在对话里适当的使用就好……而不是强行出可视化」）；`html` 用于逐季、同行、去年对今年、利润桥这类简单 `compare` 画不了的图，一个回答最多一张；数据先用工具取到 ref，再画。字级、零基线、共享刻度、配色这些规矩，抽成报告和对话共用的一段，不复制两份。
- **V5**：不做 t3code 的 `html_preview` 截图预览工具，校验和自适应高度已经够用。

**T：计算工具降摩擦**

- **T1**：接受以下写法，在 Backend 入口统一规范化，只做一次：
  - 数值带千分位逗号，以及全角数字和全角符号；
  - `block_id` 只写 `p11:b1`，由同一 `parse_revision_id` 补全前缀；
  - 期间写成 `2026Q3累计`、`2026年前三季度`、`2026-09-30` 这类常见形式，规范化成现有格式。
- **T2**：仍然被拒时，报错信息里给出「改成这样就能过」的具体例子，用模型这次传入的字段改写，而不是只列规则。
- **T3**：`evidence_required`（只给 refs）的报错里，直接写出正确的 `source` 结构示例。
- **T4**：不改计算公式，不放宽「数字必须有出处」这条规矩。

**共同**：不做兼容；契约与 `docs/contracts` 同步。
