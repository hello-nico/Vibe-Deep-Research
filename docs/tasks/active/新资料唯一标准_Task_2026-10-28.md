# 新资料唯一标准

2026-10-28 claude 写定，交 codex1。worktree 由 Claude 按两仓主目录当前状态新建（Stock、Vibe 各一个 `.worktrees/codex1-material`）。不提交、不重启、不读凭据、不写真实研究数据。
依据：Checklist 2026-10-28「研究都由用户点了才开始」（共享块）；Checklist 2026-10-27「一项能力只有一个来源」。前置：[研究记录所用报告期](研究记录所用报告期_Task_2026-10-27.md)（已合入）。

## 1. 目标

「这家公司研究之后有没有新资料」全系统只有一个判断，关注页、动态财报卡、个股页页首都读它，写出资料名加「重新研究」；研究一律用户点了才开始。

## 2. 现状（Claude 核实）

- 现有两套：
  - ① Backend `services/company_page_research.py:224 basis_version`：对已入库的定期报告与四类公告（含 `parse_revision_id`、内容哈希）算指纹，`:322` 与研究记录比对得到 `stale`。关注页「有新资料」（`lib/companyPage.ts:235 researchCell`）、页首「有新资料」（`lib/companyNarrative.ts:590 newMaterialText`）读它。重新解析也会改指纹。
  - ② `report_period` 与 `/market/report-periods` 比较（`lib/reportArrival.ts`、`lib/reconResult.ts`），动态财报卡与页首「三季报已出」读它。
- 还有第三处：`lib/objectStatus.ts:50`、`lib/pendingResearch.ts:37` 的 `refresh.state === 'candidate'`「有新资料 / 有新资料待确认」。
- 四类公告的定义已在 `company_announcements.py:22 BASIS_ANNOUNCEMENT_TYPES` 与 `counts_toward_research_basis`。
- 自动研究：`lib/companyPage.ts:168` 打开从未研究过的个股页自动 `begin()`。关注页「未研究」行也显示「重新研究」按钮（`researchCell` 的 `rerun: true`）。

## 3. 冻结决定

M1 新资料只认两类：
- (a) 比研究 `report_period` 更新的定期报告，最新期取 `services/report_periods.py`，与现在相同；
- (b) 四类公告（业绩预告、业绩快报、减值、收购出售），发布时间晚于研究保存时间。

重新解析、内容哈希变化、其他公告都不算。

M2 Backend 一处计算、一个接口字段。研究回读接口把 `stale` 换成 `new_material`：`null`，或者 `{ kind: 'report' | 'announcement', name, date }`。有多份时取最新一份。
- `name` 写短名：`三季报 / 年报 / 半年报 / 一季报`，`业绩预告 / 业绩快报 / 减值公告 / 收购出售公告`。
- 四类公告用现在动态「公告」卡的同一实时来源（`/feed/announcements` 背后的 provider），不要求已入库，并用现有 `announcement_type` 分类。
- 只有日期、没有时刻的公告，若与研究保存在同一天，算作研究已覆盖。

M3 前端所有「有新资料 / 三季报已出」都读 M2 这一个字段：
- 关注页研究列写「10-13 研究 · 估值合理 · 三季报已出」加「重新研究」；
- 页首写「三季报已出 · 重新研究」；
- 动态财报卡写「三季报已出」加「重新研究」；
- `objectStatus` / `pendingResearch` 的 `refresh candidate` 同样改读 M2。

`reportArrival.ts` 里与 M2 重复的取数删除。

M4 `basis_version` 只保留开始研究时的并发校验用途，不再参与「过期」判断。研究记录里不再需要的字段按「不做兼容」删除。

M5 研究只在用户点击时开始：
- 删掉 `companyPage.ts` 打开即自动开始的逻辑；
- 没研究过的公司：关注页研究列写「未研究」加「研究」按钮，页首在原自动开始的位置显示「研究」按钮；
- 研究过的公司仍用「重新研究」。

M6 文案按 design.md 原则 8：只写资料名加按钮，不解释机制。
M7 不做兼容。

## 5. 验收

两仓全量门禁，同 §9 惯例。测试覆盖以下情况：
- 定期报告新一期 → 有；
- 四类公告晚于研究 → 有；
- 同日只有日期 → 无；
- 其他公告 → 无；
- 仅重新解析 → 无；
- 三处界面同一文案；
- 打开没研究过的个股页不发起研究，点「研究」才发起。

§9 附本机关注公司的只读结果表：公司、研究日、研究期、`new_material`。

## 6. Out of Scope

- 后台定时入库；
- 研究内容；
- 存量 `report_period` 回填的真实执行（脚本已有，等用户授权）；
- 文案第二批（另一条线做，勿改 companyNarrative 其他句子）。

## 7. Stop Conditions

- 实时公告来源拿不到发布日期或无法分类时，停下回报；
- `basis_version` 的并发校验无法与「过期」拆开时，停下回报。
