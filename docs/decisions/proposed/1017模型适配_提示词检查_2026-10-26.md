# 1017 模型适配：提示词检查（2026-10-26）

背景：现用模型 DeepSeek-v4.1-Flash-1017。社区实测（karminski 等，10-24）指出四类 Agent 问题：①「抠门」，做事有代价就倾向不做（少调或不调工具）；②在思考里自己计数会出错（让它跑 10 次，它脑补成结果）；③提示词要求「先查一次状态」，它要么忘查，要么把第一次查的结果当权威；④歧义理解差，不会追问。共识的解法：计数、循环、状态都由外层框架钉死或注入，不靠提示词喊话。

检查范围：Stock `dsh/src/consumers.mjs`（公司研究、深度对话、页面助手、我的研究）、`dsh/src/background-review.mjs`（整理）、Vibe `desktop/dsh/finance-ui/host-state.mjs`（接续说明）。

## 建议（按收益排序）

1. **计数交给框架**（A1、A2）：宿主统计本次研究的工具调用数，到 20 次时由工具回执直接告诉模型「已到收尾点，现在保存」；失败与拒收次数同样写进回执（「这是第 2 次，不再重试」）。提示词删掉自己数数的说法。
2. **页面快照由宿主注入**（B1、B2）：每轮把页面快照随用户消息一起给模型，不再要求它先调 read_page_context / topic_basis_changes。
3. **必做步骤由保存工具校验**（C2）：save 时检查本次研究是否读过数据包、读过报告原文、做过敏感性或估值模板计算；缺了就拒收并说缺哪步。提示词里必做的写成「必须」，删掉与必做步骤相邻的省钱措辞（C1），只保留真正防发散的禁止项（外部检索、读 Wiki 原文）。
4. **解开 D1 冲突**：某节确实取不到数据时，允许 summary 只写「暂时取不到某某」而不带占位；保存校验同步放开这一种情况。
5. **删 D3 兼容段、改清 D4**；公司研究提示词按模板分支拆开，只给模型它所属模板的那一段（D2），由宿主按数据包的 valuation_template 选段注入。
6. **先拿证据**：派 pi 统计近两周公司研究会话的实际工具调用（每次研究调了哪些步、多少次、有无跳过读报告或敏感性、20 步收尾是否触发），用数据确认 C 类问题有多严重，再定第 3 条的力度。

1–2 改框架代码，3–5 改提示词与保存校验；提示词部分由 Claude 自己改。

## 实测证据（2026-10-26，公司研究工具调用统计）

- 1017 期 16 场公司研究：必做步骤无跳过，20 步收尾无触发，save 重试未超次数——公司研究里未见「抠门」。
- 5 场（31%）在生成 `save_company_page_research` 时中断：参数是完整合法 JSON，末尾多一个 `}`；DSH `@deepseek-ai/dsh-llm-deepseek` 对工具参数直接 `JSON.parse`，失败即整轮报 `MALFORMED_RESPONSE`。
- 修正建议排序：
  0. （新增，最高）运行时补丁：工具参数解析失败时，若「最长合法前缀 + 剩余仅为多余的 `}` / `]` 与空白」，用该前缀继续；其余情况仍报错。修完后工具自身的参数校验照常把关。
  建议 1（计数交给框架）仍做，但优先级降为预防；建议 3 的「抠门放大」暂无证据，先不动，等对话场景取证。
