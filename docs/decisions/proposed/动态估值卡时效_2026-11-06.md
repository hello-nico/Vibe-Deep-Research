# 动态估值卡的时效

状态：2026-11-06 Claude 起草；Owner 当天裁决（见 §6）。实施见 [今天的估值 Task](../../tasks/active/今天的估值_Task_2026-11-06.md)。

Owner 11-06 原话：「今天已经 11 月 6 号了，这几个影响判断的日期还比较滞后」「它们的内容并没有根据这段时间的行情自动调整，体验上明显存在偏差」。

## 1. 结论

这四张卡的数字没有算错，问题在于：**动态里没有「今天的估值」这个数**。卡片写的是研究当时的结论，却以「置顶」的样子摆在最前面，读起来像现在的判断。

这也没有做到 Checklist 2026-10-20 的规则：「估值档位变化时提醒用户，无论来自基本面（影响利润的价格、消息、财报）还是股价本身」。现在只有商品价格能触发提醒，股价不能。

## 2. 现在的实现

| 卡片 | 日期取什么 | 结论从哪来 | 什么时候变 |
|---|---|---|---|
| 财报卡 | 财报披露日 | 最新一次研究与上一次研究的档位对比 | 重新研究才变 |
| 价格跳档卡 | 日线连续停在跳档价另一侧的第一天 | 拿现在的商品价比研究时存下的跳档价 | 商品价回到跳档价另一侧，或重新研究 |

三个缺口：

1. **置顶没有期限。** 排序规则是置顶优先、再按日期（`feedStream.ts` 的 `streamOf`），所以 10-24 的卡排在 11-06 的公告前面。
2. **财报卡到期直接消失。** 披露超过 14 天，Backend 返回「无新季报」（`quarter_reconciliation.py`）。卡片从不更新结论，只会到期消失：紫金 11-08 起消失，两家华能 11-12 起消失。
3. **跳档价冻结了研究时的股价。** Backend 算跳档价时注明「其余变量、倍数和现价固定」，之后股价再怎么动，跳档价也不变。股息率模板的公司（两家华能）没有跳档价，不会有任何自动变化。

## 4. 选项

| | A. 加「今天的估值」（推荐） | B. 只改置顶和日期 | C. 每天自动重新研究 |
|---|---|---|---|
| 做法 | Backend 用今天的股价和商品价，代入已存模型，算出当前档位；动态、跟踪、公司页都读它 | 置顶设期限，过期按日期排序 | 定时重跑研究 |
| 解决日期问题 | 是 | 是 | 是 |
| 解决内容不随行情变 | 是 | 否，卡片仍是旧结论 | 是 |
| 消耗模型额度 | 不消耗 | 不消耗 | 持续消耗，违反「研究都由用户点了才开始」 |
| 工作量 | 一个跨两仓的 Task | 小改 | 不建议做 |

## 5. 方案 A 的规则

1. **一个来源：** 每家公司只有一个「今天的估值」接口，页面不各算各的。
2. **模型判断保留：** 今天的基准档来自代码，再加上研究时模型的偏移。华能国际的基准是明显低估，模型下调一档到偏低，这一档偏移继续沿用。
3. **一张卡只说现状：** 档位变了才出卡，例如「紫金矿业现在估值偏高（研究时合理）」，并写出股价与商品价；不管是股价还是商品价引起的，都用这一种卡。
4. **财报卡回归事件：** 不再置顶，按日期排序；结论写明是当时的，如果和今天不同，补一句现在的档位。
5. **算不出就直说：** 缺数据的公司写「估值依据缺数据」，不沿用旧档位冒充今天的结论。华能蒙电属于这种情况，先查它的历史分红与日线为什么取不到。
