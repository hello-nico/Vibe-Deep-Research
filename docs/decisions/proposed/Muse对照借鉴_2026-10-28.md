## 2. 追问阶段 Muse 做对的事

1. **先校准用户的前提。** 用户说「三家营收降幅几乎相同」，Muse 先指出：前三季度累计降幅并不一样，真正接近的是 Q3 单季；问题应改成「营收挨的打差不多，利润为什么差两三倍」。
2. **拆成独立原因，并主动去掉重复计算。** 先给出三个原因：燃料成本方向、利润总额到归母的留存率、去年利润垫。用户追问后，它自己更正：「利润垫不是第三个独立原因，它是前两个在利润率上的合计体现。」
3. **可视化和通俗说法同时给（用户点名喜欢）。**
   - 用成对条形图比较去年和今年（灰条是去年，彩条是今年）；
   - 配一句白话类比：「利润总额是整块蛋糕，到股东手里前先切两刀：所得税、子公司小股东」「净利率就是每 100 块营收能留下几块」；
   - 卡片底部给一句结论。
4. **验证用户的猜想，而不是附和。**
   - 「你的理解基本对，但要打两个补丁」：自供煤比例约六成；对冲是双向熨平，不是单向利好；
   - 估算的假设写在明处：「按 300 克/度估算」；
   - 用户说「电价普遍都跌了」，它纠正：「电价不是普遍跌，水电是涨的。」
5. **临时把对比范围扩大到第四家。** 用户问到华能水电，它把这家现取进来，放进同一张图，比较水电和火电。
6. **事件时间线 + 诚实归因。**
   - 时间线：路透 10/25 15:36（北京时间）、10/26 公告与收盘价、10/27 收盘价；
   - 归因：「两天的涨幅不能单独算在收购头上」「目前只是收购公告，还不是完成交割」。
7. **纠正常识误区，并给出制度时间线。** 用户以为全国电价统一，Muse 讲清「统一市场 ≠ 统一价格」，配上 2025、2030、2035 三个时间点和两套定价机制的对照卡。
8. **复盘坦诚、可修正。**
   - 先说 Vibe 的链接是「硬伤」，用户纠正后完全收回，反过来算成 Vibe 的优势：本地库加段落级引用，速度快；
   - 最后总结：「最好的形态是证据系统加可视化解释，密度和易懂可以同时要。」

## 3. 能借鉴什么

| # | 借鉴点 | 落到 Vibe 的哪里 | 判断 |
|---|---|---|---|
| A | 回答自检：文字里的趋势、比较说法，必须和自己列出的数字一致 | 研究方法与对话提示词，加一条「定性词对照数字」的收尾核对；能机器检查的（单调性、大小比较）考虑进收尾校验 | **直接用**，修的是真实错误 |
| B | 财报类问题用固定字段：每家写披露日、盘前或盘后、是否未审计、事前有无业绩预告，最后一行加粗「预期判断」 | 研究方法里「财报解读」模板；工具层要给出**实际发布时刻**（有时刻的公告源，如雪球、交易所公告时间），不能只给数据源的「次日」记录日 | **直接用**。日期这一条要改工具，不能只靠提示词 |
| C | 预期锚的顺序：业绩预告 → 研报前瞻或一致预期 → 流传的机构预测 → 讨论区预判；都没有才写「无锚」 | 同上 | **直接用**，这本来就是 Vibe 的长处，写成规矩 |
| D | 先校准用户的前提：用户问题里带了数字或判断，先核对口径再回答 | 对话提示词 | **直接用**，与护城河提纲「拟合不等于讨好」一致 |
| E | 归因时拆成独立原因，主动去掉重复计算；估算时写明假设 | 对话提示词，加上利润桥工具 | **直接用** |
| F | 利润桥加一项「归母留存率」：利润总额到归母这一步（所得税加少数股东） | 财报卡「最大的一项…」和个股页的利润拆解；数从数据包取，代码计算 | **改造后用**。新增一个计算项，需要单独的 Task |
| G | 对比图「去年对今年」配一句白话类比；用户要求时一定画，财报对比类问题默认画一张 | 对话里现有 `vibe` 的 chart、compare 块；图表要先由工具算出结果，缺「成对条形图」这一种 | **改造后用**：先查现有块能不能表达，不够就补一种图 |

| I | 事件时间线：消息、公告、收盘价按时间排，区分「公告」和「完成」 | 对话提示词 | 视需要，优先级低 |

| K | 记下用户认知的变化，比如「原以为全国电价统一」 | 记忆与画像 | 放进护城河讨论（「懂你」的素材），现在不做 |
| L | 临场派浏览器去爬雪球 | — | **不采用**：Exa 加 Jina 已经够用；看全部评论的需求等真正出现再说 |

## 4. Claude 的推荐

**第一批，只改提示词和研究方法，便宜、马上见效**：A、B、C、D、E。
- 这几条都是表达和核对的规矩，不动数据结构，一份 Task 就能做完。
- 用同一个问题重跑一次作对照，检查三点：是否还有「逐季走低」这类自相矛盾；披露日是否逐家写准；每家是否有加粗的预期判断。

**第二批，需要代码**：F（归母留存率）和 G（对比图）。
- F 让财报卡直接回答「营收差不多、利润差很多」这类问题。
- G 是用户点名喜欢的形式。

**H、I 跟着财报卡的迭代顺带做。K 放进护城河讨论。**

一句话：Muse 赢在「一眼看懂」和「追问时的教学感」，Vibe 赢在「证据密度和速度」。按 Muse 自己的总结，两者可以兼得；我们缺的主要是表达规矩和一种图，不缺数据。
