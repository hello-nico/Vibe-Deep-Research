## 2. 追问阶段 Muse 做对的事

1. **先校准用户的前提。** 用户说「三家营收降幅几乎相同」，Muse 先指出：前三季度累计降幅并不一样，真正接近的是 Q3 单季；问题应改成「营收挨的打差不多，利润为什么差两三倍」。
2. **拆成独立原因，并主动去掉重复计算。** 先给出三个原因：燃料成本方向、利润总额到归母的留存率、去年利润垫。用户追问后，它自己更正：「利润垫不是第三个独立原因，它是前两个在利润率上的合计体现。」
3. **可视化和通俗说法同时给（用户点名喜欢）。**
   - 用成对条形图比较去年和今年（灰条是去年，彩条是今年）；
   - 配一句白话类比：「利润总额是整块蛋糕，到股东手里前先切两刀：所得税、子公司小股东」「净利率就是每 100 块营收能留下几块」；
   - 卡片底部给一句结论。
4. **验证用户的猜想，而不是附和。**
   - 「你的理解基本对，但要打两个补丁」：自供煤比例约六成；对冲是双向熨平，不是单向利好；
   - 估算的假设写在明处：「按 300 克/度估算」；
   - 用户说「电价普遍都跌了」，它纠正：「电价不是普遍跌，水电是涨的。」
5. **临时把对比范围扩大到第四家。** 用户问到华能水电，它把这家现取进来，放进同一张图，比较水电和火电。
6. **事件时间线 + 诚实归因。**
   - 时间线：路透 10/25 15:36（北京时间）、10/26 公告与收盘价、10/27 收盘价；
   - 归因：「两天的涨幅不能单独算在收购头上」「目前只是收购公告，还不是完成交割」。
7. **纠正常识误区，并给出制度时间线。** 用户以为全国电价统一，Muse 讲清「统一市场 ≠ 统一价格」，配上 2025、2030、2035 三个时间点和两套定价机制的对照卡。
8. **复盘坦诚、可修正。**
   - 先说 Vibe 的链接是「硬伤」，用户纠正后完全收回，反过来算成 Vibe 的优势：本地库加段落级引用，速度快；
   - 最后总结：「最好的形态是证据系统加可视化解释，密度和易懂可以同时要。」

## 4. 第二个样本：海螺三季报（10-28 晚，经典场景「财报出了，网上的说法对不对」）

材料：Vibe 会话 `session-1b8fcb98`，2 轮 24 步（第一轮 2 分 55 秒，追问 1 分 23 秒）；Muse 同题回答截图（Owner 提供）。用户问题：「扣非 1 亿、利息收入 2 亿」这条帖子说得合不合理；追问「要看同行业对比，才能给出非情绪上的理性判断」。

**Vibe 做得好的**
- 取数准：在原文里核到单季扣非 1.06 亿；再用三季报减半年报，算出单季利息收入 2.16 亿，并指出帖子用的口径其实是一致的。
- 抓到真正的要点：利息收入已经算在扣非里，扣非比利息收入还少，说明主业的经营利润是负的。Muse 这一点是从雪球评论里推出来的，没有核对。
- 原因引用公司原话（「水泥、熟料销价、销量下降以及成本上升」）。Muse 说三季报里没有原因段，这一条 Vibe 更准。
- 每个数字都能点开看原文；开工和换办法时各说了一句（J 这次生效了）。
- 追问时找到了同行，结论落在「行业最好的一档，但这是周期里的防守，不是反转」，判断理性。

**Vibe 的问题**
1. **论证自相矛盾**：「三处硬伤」第一条说「税前科目不能和税后归母数比」，第二条自己又拿扣非 1.06 和利息 2.16 比出「主业为负」。而且帖子的结论方向本身是对的，Vibe 在结尾也承认了，开头却说成「会把结论带偏」，纠正过了头。
2. **和自己算的数矛盾**：结尾写「主业吨毛利接近于零」，可它自己算出的单季毛利有 28.8 亿，毛利率约 14.9%。这就是 A 要防的错误。
3. **没出处的断言**：「上一次出现这种情况是 2015—2016 年那轮底部」「天山、冀东的亏损里有折旧摊销和减值」，都没有查证。
4. **同行对比口径不齐**：用户问的是三季度单季，表里却是前三季度累计；华新混进的是半年度数；上峰「存疑」也照样留在表里。Muse 用的是单季归母，还查清了上峰 19.48 亿里 94.56% 是股权投资浮盈。
5. **能画图却没画**：对话本来就有 `compare` 对比条和 `chart` 块，两轮都没用。最直观的「Q1 14.68 → Q2 10.59 → Q3 2.16」逐季走势一次都没出现。Muse 给了一张卡：关键数字、逐季条形图、同行单季对比、一句市场口径。
6. **缺市场和估值位置**：Muse 写了「10/28 约 16:55 盘后上架，今天 -2.87% 不算财报反应」，以及 PB 0.49、股息率 4.14%；Vibe 都没有。资料库把披露日记成 10-29，模型看到了，但没有处理。
7. **工具摩擦大**：单季拆分前后调用 20 次，其中 15 次失败，原因依次是「只给 refs 不行」「数字带千分位逗号」「段落 id 要带版本前缀」「期间不能写成『2026Q3累计』」。半数以上的步数和时间耗在格式上。

8. **没读出帖子真正想说什么（Owner 10-28 指出，最要紧）**：帖子的意思是「连水泥最黄金的秋季都只赚这么点」，核心是一个季节前提。这个前提本身就错了：三季度主要是 7、8 月高温雨季淡季，价格在全年最低点；秋季旺季主要落在四季度（10、11 月），评论区也有人指出「三季度水泥价格最低点，没有黄金秋季」。Vibe 先花大篇幅挑「扣非与利息不同层级」的比法，季节问题放在第三节，而且写成「这个前提**今年**不成立」，等于默认前提一般成立，只是今年行业差。数据包里本来就能查：海螺单季营收 2024 年 Q2 242.38 亿、Q3 225.85 亿，2025 年 Q2 223.78 亿、Q3 200.63 亿，Q3 都低于 Q2；单季归母 2025 年 Q2 26.03 亿、Q3 19.48 亿（provider 历史只到 2024 年）。Muse 也没有点破这一点。正确的顺序是：先复述对方想说什么，核对他的前提，再谈数字。

|---|---|---|

| 推理严谨 | 3 | 3.5 |
| 同行对比 | 3 | 4 |

**动态财报卡（Owner 10-28 指出）**：展开后是 13 行「本季、上季、影响」的文字。数没有问题，但看的人要自己在脑子里排一遍。这正是一座「利润桥」：上季 10.59 亿，经过各项增减，到本季 2.16 亿，应该画成瀑布图。

## 5. Claude 的推荐（10-28 晚修订，以本节为准）

**第一批：提示词与研究方法，一个 Task**
- A 自检：文字里的定性说法要和自己列的数字一致；不许批评别人的比法、自己又用同一种比法；历史类比没有出处就不写。
- B 财报字段：每家写披露日与盘前盘后、是否未审计、事前有无业绩预告；最后加粗一句预期判断；再写市场口径和估值位置（PB、股息率，从数据包取）。
- C 预期锚的顺序；D 先读懂、再校准前提：用户转来别人的说法时，先用一句话复述对方想表达什么（包括言外之意，比如「连旺季都这么差」），再核对其中的前提，比如季节、口径、可比对象，能用数据核对的就用数据核对；先说对方的结论成不成立，再说方法上的问题，不夸大成「硬伤」；E 去重归因、写明估算假设。
- 新增 M 同行同口径：单季对单季、同一期对同一期；有异常值先查原因，查不清就移出表，在表下注明。
- 新增 N 能画就画：财报、对比类回答默认用已有的 `compare` 块；逐季走势、同行对比至少给一张。

**可视化的路线（参考 t3code，`/Users/apple/ts/src/t3code`）**

t3code 给模型两个工具：`html_preview` 用无头浏览器渲染，返回截图和内容高度；`html_render` 把一整页自包含的 HTML 放进对话，用沙箱 iframe 加 CSP 隔离，主题颜色由宿主通过 CSS 变量注入，页面通过 postMessage 回报高度。版式规则写在工具说明里：不加外框、不用 vh、图表用固定高度、颜色只用主题变量。好处是轻：模型想画什么就画什么。坏处是 HTML 里的数字没有经过任何核对，这和我们「页面上的数都能追到出处、由工具算出」的规矩冲突。

| 方案 | 做法 | 好处 | 代价 |
|---|---|---|---|
| A 照搬 | 模型直接写整页 HTML | 最灵活，最快上线 | 图上的数没有核对，可能编数，破坏证据规矩 |
| B 固定图块 | 在现有 `compare` 之外补瀑布图、成对条形、逐季条形三种块，数都来自 ref | 最严，和现在一致 | 每多一种图都要写代码，表达受限 |
| C 数据绑定的 HTML（推荐） | 模型写 HTML 版式，数字只能通过 `data` 传入，每个数带 ref，由宿主核对后注入 `window.DATA`；HTML 正文里不允许出现成段的数字字面量；渲染照搬 t3code 的沙箱、主题变量和自动高度 | 和 A 一样灵活，和 B 一样每个数都可查；规则只有一条：图上的数都来自核对过的 ref | 要做 ref 核对注入，以及「正文禁止数字」检查，复杂度中等 |

动态财报卡不需要模型参与，直接用代码画利润桥瀑布图（B 的做法）。

**第二批：代码，一个 Task，最多 3 个可见改动**
- G1 动态财报卡展开改为利润桥瀑布图，原来的逐项文字收进「看数据」。这是 Owner 点名的。
- G2 对话可视化按上表 C 方案做：数据绑定的 HTML 块（替代逐种补图）。
- T 计算工具降摩擦：数字接受千分位逗号，段落 id 接受短写，期间接受「2026Q3累计」这类写法，或者报错时直接给出正确格式。目标是同一个计算最多失败一次。

**第三批：F 归母留存率、H 披露前后几天的股价，跟着财报卡迭代顺带做。**

验收方法：用「海螺三季报 + 这条帖子」和「华能三家」两个问题重跑，对照上面 7 个问题逐条检查。

## 6. Claude 的推荐（原版，已被第 5 节替代）

**第一批，只改提示词和研究方法，便宜、马上见效**：A、B、C、D、E。
- 这几条都是表达和核对的规矩，不动数据结构，一份 Task 就能做完。
- 用同一个问题重跑一次作对照，检查三点：是否还有「逐季走低」这类自相矛盾；披露日是否逐家写准；每家是否有加粗的预期判断。

**第二批，需要代码**：F（归母留存率）和 G（对比图）。
- F 让财报卡直接回答「营收差不多、利润差很多」这类问题。
- G 是用户点名喜欢的形式。

**H、I 跟着财报卡的迭代顺带做。K 放进护城河讨论。**

一句话：Muse 赢在「一眼看懂」和「追问时的教学感」，Vibe 赢在「证据密度和速度」。按 Muse 自己的总结，两者可以兼得；我们缺的主要是表达规矩和一种图，不缺数据。
