## 1. 问题

- 导航按系统分工切分，没有按用户要做的事切分。用户分不清哪些内容是自己的、哪些是系统提供的、哪些其实是给 Agent 用的背景材料。具体表现：
  - 产业研究（申万 Profile）用户看不懂；
  - 个股页直接平铺事实；
  - "我的研究"有五个标签，"议题"讲了多遍仍然没人理解；
  - 资讯分类是固定的。
- 判断：技术实现没有问题。问题在于展示层直接搬用了存储结构，以及整个产品没有从"智能体给用户带来什么"出发。
- 讨论过程中的一次纠偏：Claude 曾以"研究问题"这个对象（页面、表格、生命周期）为中心做设计，仍然是从系统内部往外看。用户纠正为：**从智能体的行为和用户体验出发，对象完全退到幕后。**

## 2. 我们的特色（对外要表达的）

> 你说一句话，它挖出背后的产业链和个股，给出判断；它越用越懂你；值得盯的事它替你盯着，有变化主动告诉你。

| 特色 | 用户感受到的 | 背后支撑（不展示） |
|---|---|---|
| 一句话引出深挖 | 一个问题或一句话，引出背后的产业链（周期、上下游、当前位置、趋势）和个股（受影响的标的、共识与一致预期、已经计入多少、预期差） | 行业 Wiki、申万产业研究（作为注意力）、硬关系、公司 Wiki |
| 懂你 | 表达方式和措辞贴合用户的水平；记得用户持有什么、关心什么 | 用户画像与记忆 |
| 主动 | 关注的公司、观察的指标出现相关变化时，智能体判断后主动推送影响 | 跟踪、动态匹配、影响判断、自动写入 Wiki |

为什么需要我们：知识预编译，积累发生在各个环节，所以几分钟的分析就有深度；每个数字都能点回出处；跟踪时记得上次的判断，说得出"变了什么"。用户不需要知道这些机制，它们应该是透明的。

## 3. 用户能看到和使用的

- **深度对话**是主场。回答结束时只给三类推荐：
  1. **相关问题**：点击后在当前对话里继续追问，一次探索就是一条连续的对话；
  2. **纳入观察的指标**：点击后开始跟踪，后台由 Topic 的 Tracking 项承载；
  3. **关注 X 公司**：点击后加入关注，后台自动开始公司研究，并纳入主动推送的范围。
- **两条分析路径**：个股研究、产业研究。它们是深挖时的展开方向，结果在对话中图文呈现；面向用户的展示（单独页面的形态）待重新设计。
- **个股页**：点开一家公司，看到的是重新设计过的个股研究成果（图文判断 + 证据墙 + 资料时间线），底层 Wiki 不原样展示。图文要做到精准：每张图回答一个问题，标题就是答案；图注只写口径和来源；关键比率用工具算出后写进判断；不平铺事实。
- **不再直接展示的**：公司与行业 Wiki 的原始结构、产业研究、主题与对比 Wiki、议题（Topic 成为纯后台容器）、知识整理、记忆的内部结构。"任务"只放跟踪。

## 4. 用户画像

- 两个来源结合：一是用户在设置里主动填写的"关于我"；二是系统从对话中推断并维护的部分。
- 用户修改后，对应的记忆随之更新。这与现有的 M9.3 决定一致：推断与明确表达分开记录；用户可以查看、纠正、删除；旧的后台结果不能覆盖用户的新纠正。
- 用途：调整表达的深浅和措辞（新手讲人话，专业用户讲估值隐含的增速）；影响推荐内容和推送范围。
- 记忆的具体规则见研究记忆 v2 设计 §7：用户填写的内容系统不改，删除留墓碑，写入必须有据并经复核，记忆只关于用户。

## 6. 主动推送与商业模式（方向）

- **Web 端**：用户可以自己接入模型，产品本身不靠这一块收费。
- **收费点**：主动推送需要 7×24 小时运行的云端 Agent，持续盯着用户关注的公司和观察的指标，判断影响后推送。以后可能推出自己的模型。
- **推送流程**：先用对象匹配做低成本筛选（关注的标的、它们的硬关系、所属行业；不使用 Jev，因为 Jev 第二轮的结论是"相关性筛选不产品化"）→ 匹配上的交给 Agent 判断影响 → 有实质影响的才做研究、自动写入 Wiki、发出推送。
- **对部署规划的影响**：部署规划里原来建议默认纯 SaaS；现在的方向更接近"本机或 Web 免费，云端常驻 Agent 收费"的组合形态，规划需要按这个方向重新评估（待决）。

## 7. 底座不变；写入改为自动、事后透明

Agent 层（核心 Wiki、行业 Wiki、Topic、硬关系、成果、记忆）的机制不调整。Wiki 写入改为自动写入、事后透明、可以撤回，前提是 Agent 能区分事实与判断（见 Checklist 与不变量 4、5）。
