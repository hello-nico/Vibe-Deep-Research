# 部署形态与云端配置规划（纯 SaaS / 客户端 + 云端）

状态：2026-09-24 Claude 规划，供用户决策；**不构成实施授权**。启动前需先改 AGENTS.md「当前只交付 Web 工作台」并逐项确认 todo §8 待决事项。已定方向：Stock Backend 云端实现（Human Checklist「远期方向：Backend 云端实现」）。

## 1. 现状基线（2026-09-24 本机实测，单用户）

| 组件 | 职责 | 实测 |
|---|---|---|
| Stock Backend（FastAPI） | 研究页、证据、事实、议题、报告、Jev 隔离 | 空闲约 110 MB 内存 |
| PostgreSQL + pgvector | 事实、关系、文档索引 | 数据约 490 MB |
| 资料原件与解析（`workspace/documents`） | 年报、公告、研报 | 约 1,880 份、2.7 GB（均约 1.4 MB/份） |
| 研究工作区（Wiki、议题、报告、记忆） | 文件存储 | 约 25 MB |
| DSH 运行时 | Agent 执行、会话、工具调用 | 空闲约 90 MB；会话文件约 360 个、35 MB |
| 本机数据服务（orchestrator） | 行情抓取、自选、界面偏好 | 约 60 MB |
| 前端工作台 | 浏览器 | 静态资源 |
| 模型 / Jev | 外部 API | 单轮深度对话实测 0.4M–2.3M tokens，**成本主要在这里** |

没有 GPU 需求；CPU 主要花在资料解析（PDF → 块）和 Agent 并发。

## 2. 两种形态

| | A. 纯 SaaS（只用浏览器） | B. 客户端 + 云端 |
|---|---|---|
| 用户端 | 浏览器（桌面 / 手机网页，可装为 PWA） | 桌面客户端（macOS / Windows，Electron，参考 DSH 桌面版） |
| 云端跑什么 | Backend + DB + 存储 + **DSH 运行时 + 数据服务** + 登录 / 账号 | Backend + DB + 存储 + 登录 / 账号 |
| 用户机器跑什么 | 无 | DSH 运行时 + 数据服务 + 前端 |
| 模型与运行成本 | 由你承担（可做额度 / 计费） | 模型可用用户自己的 Key，运行成本在用户机器 |
| 行情取数 | 从云端机房取（**需实测是否被限 / 封**） | 从用户网络取，最接近现状 |
| 手机端 | 天然支持 | 仍需另做云端 DSH（等于再做一遍 A） |
| 分发与更新 | 发布即生效 | 签名、公证、自动更新、多平台打包 |
| 主要难点 | DSH 多用户隔离与弹性、取数出口 | 打包分发、客户端与云端版本兼容 |

## 3. 计划

### A. 纯 SaaS

| 阶段 | 内容 | 出口标准 |
|---|---|---|
| A0 验证 | 云主机实测东财 / 同花顺 / 巨潮取数（含 push2）；DSH 多用户隔离方案原型（每用户一个运行时容器 vs 单进程多工作区） | 取数可用或确定代理方案；隔离方案选定 |
| A1 Backend 上云 | 部署 Backend + PG + 对象存储；个人数据按用户隔离、公共资料共享（待决 ⑥）；请求鉴权替代 hook token；凭据只在服务端 | 同一套数据两个测试账号互不可见 |
| A2 DSH 上云 | 运行时容器化，按用户隔离会话与暂存（含 `read_page_context`）；空闲回收、按需拉起；会话存储迁到云盘 / 对象存储 | 10 个并发用户各自深度对话互不串 |
| A3 数据服务上云 | 行情取数服务 + 取数出口（必要时代理 / 固定出口 IP）；自选、研究名单、界面偏好按用户存云端 | 行情、雷达、自选在云端可用 |
| A4 账号与计费 | 登录（Google / 手机号 / 微信，按用户地域）、用量计量与额度、模型网关持有供应商 Key | 用户可登录、看到用量、超额受限 |
| A5 运维 | 备份（PG 每日 + 对象存储版本）、监控告警、日志与审计、限流 | 演练一次恢复 |
| A6 移动端 | 响应式与 PWA | 手机完成一次问助手与议题浏览 |

### B. 客户端 + 云端

| 阶段 | 内容 | 出口标准 |
|---|---|---|
| B0 验证 | 客户端到云 Backend 的鉴权与延迟；本机取数保持现状 | 客户端连云 Backend 跑通一次公司研究 |
| B1 Backend 上云 | 同 A1 | 同 A1 |
| B2 桌面壳 | Electron 打包前端 + DSH 运行时 + 数据服务（参考 DSH 桌面版组合）；本地会话与偏好目录迁到系统用户目录 | 安装包在干净的 macOS / Windows 上可用 |
| B3 登录 | 系统浏览器授权（PKCE），令牌存本机凭据库（参考 `dsh-deepseek-account-platform`） | 登录 / 登出、令牌不进前端 |
| B4 分发 | 代码签名、Apple 公证、自动更新、版本兼容（客户端版本 ↔ Backend API 版本） | 旧版客户端收到升级提示 |
| B5 沙箱（按需） | 若开放命令 / 文件执行，启用 DSH 三平台本机沙箱 | 仅在开放该能力时 |
| B6 手机端 | 仍需云端 DSH → 回到 A2–A3 | — |

## 4. 云端配置推荐（国内公有云按量估算口径，按阶段升级）

> 规格为起步建议，实际按压测调整。模型调用费另计且通常远大于机器费用；取数若需代理另计。

### A. 纯 SaaS

| 规模 | 应用与 DSH | 数据库 | 存储 | 其他 |
|---|---|---|---|---|
| 内测（≤ 20 用户，≤ 5 路并发对话） | 1 台 4 vCPU / 16 GB：Backend 2–4 进程、数据服务、DSH 运行时（每活跃用户约 0.5 vCPU / 1 GB） | 托管 PG 2 vCPU / 8 GB，100 GB SSD（需 pgvector） | 对象存储 100 GB | 资料解析与应用同机；带宽 10 Mbps；前端走 CDN |
| 小规模（≤ 500 注册，≤ 50 路并发） | 容器集群 3 台 8 vCPU / 32 GB；Backend 2–3 副本（2 vCPU / 4 GB）；DSH 每用户容器 1 vCPU / 1 GB、空闲回收 | 托管 PG 4 vCPU / 16 GB 高可用，500 GB | 对象存储 1 TB | Redis 2 GB（限流、队列、会话索引）；解析队列 2 个 4 vCPU / 8 GB 工作节点可伸缩；负载均衡；带宽 50 Mbps |
| 增长（≤ 5,000 注册，≤ 300 路并发） | 容器集群 6–10 台 16 vCPU / 64 GB，按并发自动伸缩 | PG 8 vCPU / 32 GB + 只读副本，1–2 TB | 对象存储数 TB，冷热分层 | 独立取数服务与出口；日志 / 监控平台；多可用区 |

### B. 客户端 + 云端

| 规模 | 应用 | 数据库 | 存储 | 其他 |
|---|---|---|---|---|
| 内测 | 1 台 2 vCPU / 8 GB（Backend + 解析） | 托管 PG 2 vCPU / 4 GB，100 GB | 对象存储 100 GB | 带宽 5–10 Mbps；账号服务可用托管认证 |
| 小规模 | Backend 2 副本 2 vCPU / 4 GB + 解析工作节点 1–2 个 4 vCPU / 8 GB | PG 4 vCPU / 16 GB 高可用，500 GB | 对象存储 1 TB | 负载均衡、Redis 1 GB；客户端更新包放 CDN |
| 增长 | Backend 3–6 副本 | PG 8 vCPU / 32 GB + 只读副本 | 数 TB | 同 A 的运维要求 |

**用户电脑要求（B）**：macOS 12+ / Windows 10+；内存 8 GB（建议 16 GB）；磁盘预留 2 GB + 会话与缓存增长；需能直连行情源与云 Backend。

## 5. 地域与合规要点

- 数据源和目标用户在大陆：服务器放大陆区域取数最稳，但对外服务需域名 ICP 备案；放香港无需备案，需实测大陆行情源访问（尤其东财 push2）与延迟。
- 登录：Google 在大陆不可用，大陆用户需手机号 / 微信；上架 iOS 需同时提供“通过 Apple 登录”。
- 公告、年报是公开资料，可全员共享；用户上传资料、记录、议题是个人数据，必须按用户隔离与加密存储。

## 6. 建议

默认走 **A 纯 SaaS**：产品本来就是网页工作台，手机端顺带解决，分发零成本；主要工作是 DSH 上云（多用户隔离与弹性）和取数出口。**B 作为后续可选**，只有在“模型费用由用户承担”“必须读本机文件 / 执行命令”“行情源封禁云 IP 且代理不可行”之一成立时再做。第一步都是 A0 / B0 的取数与隔离验证，花费小、结论决定路线。
