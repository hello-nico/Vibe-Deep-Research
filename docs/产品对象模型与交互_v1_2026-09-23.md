# 产品对象模型与交互 v1

状态：2026-09-23 设计稿；同日用户审阅并裁决 §8 待决项（结果已并入正文），可按 §7 拆 Task 交 Codex / Cursor 实施；本文不授权改代码。权威：[Human Checklist](../human-checklist.md)「产品对象模型与交互方向（2026-09-23）」；与既有决定的关系见 §6。

## 1. 一句话

**对象是主角，页面和助手都是进入它的门。** 同一个对象在对话、列表、页面里长得一样、点起来一样、能做的动作一样；对话从任何对象旁边的右侧滑出，背后是同一套对象与会话系统。

两条设计线互相约束：**对象线**（是什么、状态、版本、归谁管）决定能做什么；**界面线**（动作、零件、布局、样式）决定怎么呈现。

- 主题 / 对比 Wiki：按 2026-09-22 决定收敛为议题内技能产出，存量只读，不再作为独立对象扩展。存量引用点开时用右侧只读抽屉展示正文，不再保留独立路由（见 §5 研究材料页下线）。
- 行情、大盘、日期、公告、新闻、网页：是**数据视图或来源**，不是核心对象；不进 @，已发出的旧引用照常显示与读取。
- 硬关系是 Backend 内部事实拓扑，不作为用户可见对象；用户可见的是“研究关联”。证据墙以只读连线展示硬关系（用户 2026-09-23 决定，见 §6）。

### 2.2 统一对象登记层（产品侧一处实现）

每种对象只登记一次，登记项：身份解析、显示名、主页路由、悬停预览、可用动作、状态来源。@ 下拉、消息标签折叠、标签点击、问助手绑定、页头、面包屑都从这里取。

现状缺口（2026-09-23 核对）：
- 身份解析、打开、显示名、折叠、问助手取数、Stock 读取工具分散在约 8 处（`dsh/research-input.ts`、`dsh/client.tsx` 的 `openResearchTarget`、`lib/library.ts` 的 `mentionLabel`、`lib/researchMentions.ts`、`assistant/prompt.ts` 等），新增一类对象要改一圈。
- 显示名只存在浏览器内存，刷新页面后标签退化为代码或“研究材料”。需要 Backend 提供**对象显示名批量解析**（现有 `/wiki/refs/resolve` 只解析依据类引用，不覆盖公司 / 行业 / 资料 / 议题）。
- 点击只对资料、网页、议题、研究页生效；研究页标签跳到 `/my-research/material` 通用阅读页，而不是该对象的主页。**用户已定：标签点击一律进对象主页**（公司进公司研究页，行业进行业研究页），通用阅读页下线。
- 实施前先核对 DSH 0.1.7 已有的引用与显示名机制（输入框引用的 codec / 标签持久化、`chatFileMentions` 解析、会话引用 SessionReference 等），能复用就复用，不从头设计。

### 2.3 生命周期与状态

以公司 / 行业为例，状态由两部分组成：**存在状态**（未建 → 建立中 → 已发布）＋ **叠加状态**（资料检查中 / 有新资料可确认 / 有待确认维护提案 / 有草案待发布 / 图文报告对应旧版本）。

- 状态由 Stock Backend 统一给出（新增按对象批量查询状态的接口），前端只展示；不在浏览器或 Client SQLite 保存第二份。
- 状态变化只来自动作（§3）；所有写入沿既有协议：提案 → 用户在原生选项中确认 → 执行回执 → 审计。
- 草案与“待授权”状态由 **Stock Backend 持久化**（用户 2026-09-23 决定，关闭 Checklist 2026-09-21 未决项）：替代现状中“Backend 只返回草案编号与过期时间、待授权由 DSH 研究插件在会话内临时拼出、草案存临时目录会过期”的做法；插件只读取与展示。

### 2.4 版本与差异

- 现有三套版本口径：Wiki `input_hash`、资料 `parse_revision_id + sha256`、议题 revision。
- 界面需求：议题页对每个依据对象显示“自上次判断以来有变化 / 无变化”，可展开看具体差异；报告显示“基于哪个版本、是否已过期”。
- 统一标识与 diff 接口是内核设计，另立决策（§7 T5），本稿只定义界面需要什么。

## 3. 动作线

### 3.1 统一动作

| 动作 | 适用对象 | 入口 | 是否写入 |
|---|---|---|---|
| 打开 | 全部 | 点击对象标签、列表项 | 否 |
| 预览 | 全部 | 悬停对象标签 | 否 |
| 讨论 | 全部 | 对象页右上「问助手」/ 议题页「继续研究」→ 右侧对话面板，自动带上当前对象 | 否 |
| 引用 | 公司、行业、资料 | 对话里 @，或对象页「引用到对话」 | 否 |
| 加入研究 / 自选 | 公司 | 对象页头 | Client 选择 |
| 刷新资料 | 公司、行业、议题材料 | 页头按钮或「更多」 | 有差异才确认后写入 |
| 生成图文报告 | 公司、行业、议题 | 「图文报告」分段内主按钮 | 是（报告成果） |
| 维护（建对象、关系、时间线） | 公司、行业 | Agent 提案 → 原生选项确认 | 确认后写入 |
| 修订判断 | 议题绑定的对象 | 仅议题会话 | 确认后写入 |
| 归档 / 移出 | 议题、公司 | 「更多」菜单 | 是 / Client 选择 |

### 3.2 一个动作模式

所有“刷新 / 生成 / 新建”类动作同一模式：**按钮只负责触发 → 对象内容区域进入统一的更新或生成效果（旧内容保留，显示当前步骤）→ 完成后原地换成新内容 → 失败原地提示并可重试**。有写入就先走确认；无差异不弹确认，只给轻提示。完整过程留在「我的研究 · 任务」供排查，页面上不再放“生成过程”按钮。

## 4. 界面线

### 4.1 原则（2026-09-23 用户确认的 12 条）

1. 对象是主角，页面为对象服务。2. 助手只是入口，系统同一套；任务过程与问助手是同一对话视图的只读 / 交互两种模式。3. 对象呈现由 Wiki 数据结构驱动（每块内容对应一张卡片）。4. 等待效果落在对象内容上，不落在按钮上。5. 同类控件只有一种样式。6. 所有 Wiki 图文报告共用一套渲染与生成效果。7. 去掉多余入口。8. 对话统一从右侧滑出。9. 对话面板重做样式，贴合整体风格。10. 左侧导航不动。11. 集合页保留「我的资料」风格：搜索 + 筛选 + 卡片 / 列表两种视图。12. 页头动作少而主次分明。

### 4.2 界面零件（统一规格，已有实现优先复用）

| 零件 | 规格 | 现有可复用 |
|---|---|---|
| 对象标签 | 类型图标 + 名称，处处同一外观；悬停预览，点击进主页 | 对话内折叠标签 `finance-citation` |
| 预览卡 | 见 §4.4；统一底部动作：打开 · 引用到对话 · 问助手 | 依据卡的悬停形式 |
| 对象页头 | 返回 · 对象切换下拉 · 研究页 / 图文报告分段 · 一个主按钮 · 「更多」 | 个股页工具栏、`WikiViewTabs` |
| 内容卡片 | 按 Wiki 块类型：图标 + 标题 + 正文；公司、行业、议题共用 | 个股 / 行业研究页卡片 |
| 集合视图 | 搜索、筛选下拉、卡片 / 列表切换、计数 | 我的资料页 |
| 可搜索下拉 | 搜索框 + 勾选 + 名称与代码对齐 | `WorkspaceSelect` |
| 加载 / 生成效果 | 扫描动画 + 章节轮换 + 当前步骤文字，保留旧内容 | `ResearchLoading`（已验收，保留） |
| 报告渲染器 | 四类 Wiki 共用一套，含生成中效果 | Lieflat 报告渲染 |
| 确认 | DSH 原生选项组件，展示目标、变更、依据 | 维护确认框 |
| 状态徽标 | 统一颜色与文案：建立中、有新资料、待确认、草案、报告已过期 | 无，新增 |
| 对话视图（面板） | **一个零件、两种模式**：交互（有输入框：问助手、深度对话、议题研究）与只读（无输入框、系统自动触发：报告生成、公司研究、后台整理的任务过程）。均用 DSH 原生对话渲染（升级后的整轮折叠、过程分组、中文工具行），替代自绘的 `TaskTranscript` 轨迹列表。右侧滑出，默认宽度 + 左边缘拖拽调宽（记住宽度），可收起、可全屏；全屏即深度对话页 | 问助手面板、`ConversationWorkspace`、2026-09-09 聊天窗口拖拽；DSH 原生子 Agent / 会话引用能力 |

**工具栏规范。** 对象页头用左右两组、统一 40px 高：左组只做定位（返回、对象切换、研究页 / 图文报告分段），右组只做动作（次要状态、当前分段的主动作、「更多」）。动作随分段替换，不并排堆两套主按钮——研究页右组是「已自选 / 刷新资料 / 更多」（行业无自选），图文报告右组换成「重新生成」，报告正文左上不再放按钮；刷新组件切分段时只隐藏不卸载，避免中断进行中的检查。「更多」弹出菜单与 `WorkspaceSelect` 下拉同配色、同面板与选项样式，不另做一套。

### 4.3 布局

- 左侧导航维持现状。主区：集合页或对象主页。
- 对话：所有对象页右上角同一个「问助手」入口，点开从右侧滑出，带上当前对象；深度对话页是它的全屏形态。议题页取消常驻左右分栏，改为同一滑出面板（「继续研究」即打开它）。
- 在对话里点对象标签：主区切到对象主页，对话面板保持打开、同一会话继续。
- 面板尺寸：默认约 440px；左边缘拖拽调宽（最小约 360px，最大约主区 60%），宽度作为持久界面偏好保存在 Client；全屏切到深度对话页。窄屏（主区不足约 1024px）时面板覆盖主区全宽，可一键收起。具体数值实施时按真实页面微调。

### 4.4 预览卡字段（按对象，设计判断）

原则：**悬停只读已有知识，不触发外部取数**；不显示需要时点的实时数字（行情、估值），这些留在对象主页并带取数时点。每张卡：类型图标 + 名称 + 1 行关键信息 + 1–2 行摘要 + 状态徽标 + “资料截至”日期。

| 对象 | 关键信息 | 摘要 |
|---|---|---|
| 公司 | 代码 · 所属行业 | 研究页“经营”块的一句话商业模式；无则显示“资料待补充” |
| 行业 | 统计局行业 · 成员公司数 | 行业页一句话机制（行业列表卡片同源） |
| 资料 | 类型 · 来源 / 上传时间 · 处理状态 | 正文开头摘要 |
| 议题 | 关联对象数 · 最近更新 | 当前判断一句话；无则显示议题问题 |
| 研究成果 | 指标 · 区间 · 截至 | 图表标题（不渲染缩略图） |

### 4.5 议题证据墙

议题是对象的容器与空间。证据墙把议题内的对象和它们之间的关联画出来，像侦探电影里的证据墙，一眼看清“这个问题牵涉谁、谁和谁有关、依据是什么”。

- 节点：议题引用的公司、行业、资料、研究记录、研究成果，用对象标签同一视觉；点击节点即打开对象（主区切换，对话面板不变），悬停即预览卡。
- 连线三种，视觉区分：**硬关系**（Backend 事实拓扑，只读，如供应 / 股权 / 行业归属，带依据可点开，不可在墙上编辑）、**研究关联**（软链接，经提案确认后写入）、**用户假设**（用户手动连线并写一句说明，标明未核验）。连线可点开看依据。
- 判断钉在墙上：议题当前判断与跟踪项显示为便签，指向其依据对象；依据对象“自上次以来有变化”时在节点上提示（依赖 T5）。
- 写入仍走维护协议：新建研究关联、改判断都经确认；拖动与布局只是展示偏好。
- 议题也可生成图文报告，与公司 / 行业共用报告渲染器。
- 这重启了 2026-09-17 暂停的 M9.4 研究画布方向，范围收敛为“议题内的对象关系墙”，不做跨议题全局画布与复杂编辑；视觉贴合产品，允许适度动效。

## 5. 页面现状与差距

| 页面 | 现状 | 目标 |
|---|---|---|
| 深度对话 | 部分标签点不动；研究页标签跳通用阅读页 | 标签统一走登记层，进对象主页；对话可收为右侧面板 |
| 个股研究 | 基本符合；刷新时按钮自转；报告空态有多余「生成过程」 | 刷新与生成走 §3.2 模式；去掉「生成过程」 |
| 行业研究 | 与个股基本一致 | 同个股 |
| 议题研究 | 页头 5 个按钮；右侧常驻对话；最近对话卡片排版错乱（文字竖排）；内容是纵向卡片列表 | 页头：分段切换（研究页 / 证据墙 / 图文报告）+ 主按钮「继续研究」+「更多」（刷新材料、归档）；新会话移进面板；对话右侧滑出；新增**证据墙**（§4.5） |
| 我的资料 | 符合原则 11 | 保持，作为集合页样板 |
| 研究材料页 `/my-research/material` | 所有研究页标签的落点 | **下线**（用户已定）：公司 / 行业进主页；主题 / 对比存量用只读抽屉 |
| 问助手面板 | 样式与整体不搭；与深度对话观感割裂 | 重做样式，与深度对话共用对象标签、引用与确认 |

## 6. 与既有决定的关系

- **替代** 2026-09-21「问助手独立设计，不从深度对话派生」在**界面与系统层面**的约束：对象、标签、引用、会话、确认只有一套。**保留**各页面助手按角色区分工具与提示词（当前对象决定可用能力，而不是两套系统）。
- 沿用：2026-09-22 维护协议（所有写入二次确认、判断只在议题会话修订）；主题 / 对比收敛为议题技能；2026-09-23 @ 只保留公司、行业、资料；引用写法全产品一种。
- **替代** 2026-09-10「核心硬关系不在产品界面暴露，由研究内部使用」：硬关系可在议题证据墙以只读连线展示，带依据；仍不在其他页面单独暴露，不能在界面上编辑，准入与写入沿 Backend 原契约。
- 本稿不改变 Backend 的存储、准入与发布权限。
