## 产品结构与交互草案

本节是待用户审阅的呈现方案；先用真实内容做可见页面验证，再固定细节。

1. **我的研究首页**：统一入口内区分「议题」「记录」；议题展示实际问题、相关行业/公司、最近研究进展和可继续动作；独立记录可以直接阅读，无需先分类。支持搜索与有界加载，避免再做无限长侧栏。
2. **议题工作区**：议题内容与 DSH 对话并排可用；展示核心对象、相关记录、Theme/Comparison 等材料及真实 Link。以问题和可复用材料组织页面，不用一张全量关系图占满空间；可局部展开关联和继续遍历。
3. **记录关联**：保存先成功，再展示 Agent 已判断的关联或未关联状态；失败明确且可重试。用户能理解为什么关联、能纠正错误；纠错动作消费 M7 契约，不在前端另存一份 Link。
4. **行业入口**：板块中心列出 41 个标准行业，点击读各自 Industry Wiki 和相关材料。申万 Profile 进入研究材料路径供 Theme 使用，不混为同一套行业身份。
5. **研究与发布**：议题内明确当前研究对象和材料；草案、发布成功、失败区分。若按 M7 采用显式发布，用户能审阅实际草案后发布；禁止将生成中或只验证成功显示为已积累。
6. **导航与返回**：对象 → 证据卡 → 原文 → 返回仍保留议题、选中对象和阅读位置；关闭阅读不丢研究会话。引用移除只影响待发送内容，不删除证据或历史消息。

## 验证与验收

确定性：`npm --prefix desktop run build`、相应行为测试、facade 白名单与 ID 编码测试、`git diff --check`。既有四项测试债单独记录，既不能归罪本轮也不能作为跳过新回归的理由。

| 真实操作 | 必须看到的结果 |
| --- | --- |
| 保存一次大盘问答 | 独立记录出现，无强造 Topic；刷新后仍在 |
| 深度对话形成行业议题 | 我的研究能找到同一 Topic；手动再建不同同业议题不被合并 |
| 超过旧容量后搜索与续接 | 所有议题仍可找到，不因新增被自动归档；分页无重复遗漏 |
| 两个 Topic 来回切换，前一个仍在运行 | 消息、待引用、工具作用域与写入目标不串；返回恢复原会话 |
| 行业研究读取 Profile 并形成 Theme | 实际 DSH 工具轨迹可回溯，草案/发布清晰；发布后在议题和相关行业入口读到同一材料，无 Dreaming 前置 |
| 行业入口 | 正好 41 个身份，无两个汇总行、无申万 Profile 冒充；缺正文明确，已发布正文正常读回 |
| 从 Topic 沿 Link 打开 Wiki/记录/证据，再返回 | 关联有真实目标，来源可核验，返回恢复上下文；失效目标可解释，不转错对象 |
| 新会话继续研究 | 读取持久 Topic/Wiki/Link 就能继续，不靠复制旧 Session 全文 |
| 普通页面问助手与我的研究同时存在 | 前者仍轻量，后者为 DSH；无第二套 Agent 运行或凭据泄漏 |
| 故障与呈现 | Note 已存而关联失败不显示保存失败；发布冲突能重读；桌面/窄屏/主题无裁切，对话与材料可同时操作 |

Agent 自行进行真实提问与浏览器验证，使用获授权可用的服务；模型/数据不可用时明确待验收，不用 mock 截图替代。保存截图、实际工具轨迹、对象 ID 和持久读回结果；用户验收视觉与研究体验。
