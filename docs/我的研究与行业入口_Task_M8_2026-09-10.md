## 产品结构与交互草案

2026-09-12 用户确认补充：产品入口统一称「行业研究」。DSH 与 Wiki 共用依据解析和卡片；依据仅分可定位的文档片段与可回读的 API 数据，Wiki/Topic 链接是研究对象导航，不能当作本机文件或伪装成原始证据。`@` 选择议题、公司、行业、专题和对比材料，不展示工作目录；`/` 提供研究端实际支持的 Skills。目录、接口地址、版本/hash 不进入用户文案。验收需覆盖对话及 Wiki 两种入口、选择对象后真实发送、技能真实读取、依据追问和返回。

本节是待用户审阅的呈现方案；先用真实内容做可见页面验证，再固定细节。

1. **我的研究首页**：统一入口内区分「议题」「记录」；议题展示实际问题、相关行业/公司、最近研究进展和可继续动作；独立记录可以直接阅读，无需先分类。支持搜索与有界加载，避免再做无限长侧栏。
2. **议题工作区**：议题内容与 DSH 对话并排可用；展示核心对象、相关记录、Theme/Comparison 等材料及真实 Link。以问题和可复用材料组织页面，不用一张全量关系图占满空间；可局部展开关联和继续遍历。
3. **记录关联**：保存先独立成功并保留来源上下文，不启动 DSH。用户在我的研究开始研究对话时，沉淀记录默认进入有界可读取上下文，Agent 按问题补读并主动提出相关记录、目标 Topic 与理由；用户确认后才写入关联。未确认或拒绝时保留独立记录；确认失败明确且可重试。切换议题不得让旧确认写入新目标；纠错动作消费 M7 契约，不在前端另存一份 Link。
4. **行业入口**：板块中心列出 41 个标准行业，点击读各自 Industry Wiki 和相关材料。申万 Profile 进入研究材料路径供 Theme 使用，不混为同一套行业身份。
5. **研究与发布**：议题内明确当前研究对象和材料；草案、发布成功、失败区分。若按 M7 采用显式发布，用户能审阅实际草案后发布；禁止将生成中或只验证成功显示为已积累。
6. **导航与返回**：对象 → 证据卡 → 原文 → 返回仍保留议题、选中对象和阅读位置；关闭阅读不丢研究会话。引用移除只影响待发送内容，不删除证据或历史消息。

## 状态与失败契约

- 开聊：带当前 Topic/Wiki 摘要和有界记录上下文（标明已提供范围），允许按需补读；不把旧 Session 全文自动转成研究记忆，不因记录中出现公司名就自动关联。
- 关联：Agent 提议具体记录、目标 Topic/对象及理由；用户确认前无持久 Link。确认固定记录 ID、目标 ID 与原提议，切页/晚到响应不能换目标。重复确认幂等，拒绝仍保留记录；关联失败不撤销正文，删除记录后的引用失效需可解释。
- 会话：一个 Topic 可有多次 Session；切换选中对象只改变阅读上下文，不重绑定运行中的研究。运行始终归原 Session/Topic；取消后不自动发布。关闭 Dock 不删除持久内容，待引用可单独移除。
- 发布：生成草案→用户审阅→明确确认→Backend 校验并发布→重新读取。确认必须对应所见草案；版本冲突要求重读，不静默覆盖。失败保留草案及原因，生成成功不显示为已发布。
- Link：允许四类 Wiki、Topic、核心对象及记录按研究内容关联；只保存真实可解析目标。默认展示相关材料，按需遍历，去重防环且有界；不以全图枚举替代相关性选择。
