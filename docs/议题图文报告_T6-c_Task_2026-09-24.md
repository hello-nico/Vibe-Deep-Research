## 1. 目标

议题页「图文报告」分段与公司 / 行业一样：点「生成图文报告」由后台报告任务按 Lieflat 模板生成一份交互报告，绑定议题当时的版本；议题之后有变化时显示“报告对应旧版本”，可重新生成。

## 2. 现状（2026-09-24 Claude 核实）

- 公司 / 行业 / 主题 / 对比报告：Stock `backend/app/services/wiki_reports.py`（`SLUG_RE` 只认四类 Wiki slug；报告绑定页面 `input_hash`；`allowed_refs` 取页面 spec 的全部 ref）；`POST/GET /wiki/reports`（`backend/app/api/v1/wiki.py`）。DSH 报告任务：`dsh/src/report-tools.mjs` `wiki_report_publish`（只接受绑定 slug + 钉住的 `input_hash` + 已加载模板），报告任务提示词与各类叙事 `dsh/src/consumers.mjs` `REPORT_NARRATIVES`；报告任务中 `wiki_read` 只允许读绑定 slug（`research-material-tools.mjs`）。
- 前端：公司 / 行业报告分段 `components/WikiReportPane.tsx`（列表、生成、过期提示、与公司研究互斥）；报告任务启动 `dsh/finance-ui/host-state.mjs` `startReportRun`（按 slug 绑定）。议题页「图文报告」目前是前端直接拼的静态 `ObjectReport`（`pages/TopicWorkspace.tsx` `reportBody`），不是生成报告。
- 议题有 `revision`（整数，CAS），没有内容哈希。

## 3. 冻结决定

### 3.1 版本与绑定

- 报告目标增加议题：`topic:<12hex>`。议题版本用 Backend 计算的**议题快照哈希**（对议题文档的研究内容字段做规范化 JSON 后 sha256，排除 `last_touched_at`、`pool_state` 等非内容字段），作为报告的 `input_hash`，沿用现有“报告绑定版本、过期提示”模型。新增只读 `GET /wiki/research-topics/{id}/snapshot` 返回 `{ topic, input_hash }`。
- `allowed_refs` = 议题自身引用（`observation.fact_refs / source_refs / relation_refs`、`judgment.basis_refs` 中可被依据面板解析的 `claim:` / `evidence:` / `source:` / `lookup:` / `provider:`）∪ 议题依据研究页（`page:<slug>@…`）**当前版本** spec 的 ref。报告只能引用这些。
- `wiki_reports.py` 的目标校验、存储路径与列表按目标类型扩展；不改公司 / 行业报告行为。

### 3.2 报告任务（Stock DSH）

- 报告任务可绑定议题：`reportTask.slug = topic:<hex>`、`inputHash` = 议题快照哈希。议题报告任务可用工具：`read_research_method`（模板）、读议题快照（新增只读工具或复用 `topic_get` 并钉住哈希）、读证据墙（T6-a 接口，只读）、`wiki_read` 读议题依据研究页（只读，限议题 `basis_refs` 中的页）、`wiki_report_publish`（`slug` 为议题 ID，`input_hash` 为钉住的议题快照哈希）。其他工具不开放。
- `REPORT_NARRATIVES.topics`：研究问题 → 当前判断与状态（判断时间）→ 依据对象与关系（可用内联 SVG 画简化关系图，只画墙接口返回的硬关系 / 研究关联 / 假设，假设标“未核验”）→ 判断之后的依据变化（有则列，无则写“依据无变化”）→ 继续核实 → 缺口。不得把假设写成结论，不得补造判断。
- 报告纪律、字级、`data-ref` 规则沿用现有报告任务提示；模板从现有 `lieflat-r01`–`r12` 中选，不新增模板。

### 3.3 前端（Vibe）

- 议题页「图文报告」分段改用与公司 / 行业相同的报告面板（复用 `WikiReportPane` 或抽出共享零件）：已有报告列表、生成 / 重新生成、“报告对应旧版本”提示（按议题当前快照哈希比较）、生成中状态与任务过程入口。原静态 `ObjectReport` 删除，不保留兼容。
- 报告任务启动走 `startReportRun`，目标为议题 ID；同一议题同时只允许一个报告任务。任务列表标题“图文报告 · <议题标题>”，状态沿用已生成 / 未保存规则。
- 议题 Agent 修订判断期间（议题会话运行中）仍可生成报告：报告钉住开始时的快照；保存时版本已变即按“未保存”处理，可重新生成（与公司报告一致）。

## 4. 范围

- Stock Backend：`app/services/wiki_reports.py`、`app/services/research_topics.py`（快照哈希）、`app/api/v1/wiki.py`（快照接口、报告目标扩展）、测试。
- Stock DSH：`dsh/src/report-tools.mjs`、`dsh/src/research-material-tools.mjs`（议题报告任务的读取范围）、`dsh/src/consumers.mjs`（`topics` 叙事与报告任务目标说明）、`dsh/src/topic-tools.mjs`（如复用）、测试。
- Vibe：`pages/TopicWorkspace.tsx`、`components/WikiReportPane.tsx`（或共享零件）、`dsh/finance-ui/host-state.mjs`、`dsh/finance-ui/research.mjs`（代理放行快照接口与议题报告列表）、`pages/MyResearch.tsx`（任务标题）、测试。

## 5. 验收

- **执行方（自动）**：Backend `uv run pytest -q`（已知环境类失败同 T5-a §9）；Stock DSH `pnpm run test` 与构建；Vibe `npm run typecheck && env -u NODE_ENV node --test test/*.test.ts`、`node dsh/build-ui.mjs`；三仓 `git diff --check`；重建 Backend 容器，重启工作台。新增测试：
  - 快照哈希确定性、非内容字段变化不改哈希、判断变化改哈希；
  - 议题报告 `allowed_refs` 只含议题引用与依据页当前 ref，越界引用被拒；
  - 议题版本变化后保存返回 409；报告列表按议题目标返回并能判断过期；
  - 议题报告任务只能读绑定议题、其墙与其依据页；发布只接受钉住哈希；
  - 公司 / 行业报告原有测试全部通过；
  - 前端：议题报告分段状态（无报告 / 有报告 / 已过期 / 生成中）、同议题互斥、任务标题。
- **用户验收**：
  1. “电力行业公司结构”议题 → 图文报告 → 生成：任务完成后显示报告，包含研究问题、当前判断、依据对象与关系图、继续核实与缺口；引用可点开依据。
  2. 在议题会话里修订判断后回到图文报告：显示“报告对应旧版本”，重新生成得到新报告。

## 6. Out of Scope

- 新增报告模板；议题报告导出 PDF；多议题合并报告；报告编辑；Jev。

## 7. Stop Conditions

- 议题依据研究页的旧版本引用无法与当前版本对齐，导致报告无法可靠校验引用：停止，回填样例与方案。
- 报告存储按目标类型扩展需要迁移现有报告文件：停止回填（不做迁移）。
- 议题报告任务的读取范围无法在不放宽公司 / 行业报告任务限制的前提下实现：停止回填。
- 与其他工具同时修改同一文件：先看 git 状态，冲突时停下告知用户。
