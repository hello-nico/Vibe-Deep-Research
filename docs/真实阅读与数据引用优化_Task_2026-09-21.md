### B. 单页阅读：Jina Reader 优先，现有 Fetcher 兜底

- 入口：Stock `backend/app/services/url_fetch.py`、其调用方及现有 Document/入库路径。保持外部工具语义，不增设模型可见的 Jina 工具。
- 默认无密钥调用 `https://r.jina.ai/<完整原始URL>`；采用官方支持的 Markdown 输出方式，开工核对当前接口与响应。普通阅读不要求注册、配置 API key 或付费；免费服务不等于无额度限制。
- 首选请求失败、超时、限流、空正文、可识别的错误/验证页时，自动进入现有 HTTP Fetcher 一次；两路都失败时返回可诊断错误，不能以 HTTP 200 或非空错误页当阅读成功。
- 明确每路超时、响应大小及总耗时上限；不无限重试。保留现有上限时核对 Jina Markdown 的实际需要；在实施回填中记录最终值及依据。
- Reader 与兜底共享一个 Backend 入口和结果契约。原始 URL、实际返回的来源 URL、标题、正文格式、抓取时间、截断/完整状态及内容 hash 均保持真实；未返回最终来源 URL 时不得猜造。Provider 状态放在内部轨迹，不写进正文。
- Jina 是内容转换服务，不是新闻发布来源；引用指向原始来源或产品依据入口，不能把 `r.jina.ai` 当文章来源。
- 收敛现有 DNS 黑名单与固定 IP transport，让 Reader 请求和直接抓取均使用可工作的网络/代理路径，不继续因 Fake-IP 被提前拒绝。按用户确认的本机需求执行，不另建 SSRF 框架；保留 HTTP(S) 格式检查、超时、大小与重定向上限。
- 只把本次明确读取的公开 URL 发给 Reader，不上传本地资料，不转发本机 Cookie、认证头或密钥。已有带认证信息的 URL 拒绝语义保持不变。
- `persist=false` 仍只读、不入库。`persist=true` 复用正式入库链；Jina Markdown 是转换文本，不能冒充原始 PDF 字节、PDF 页码或已有解析版本。需要原件的现有调用仍获取并保存真实原件；不得制造证据定位。
- PDF 也验证首选 Reader 与直接抓取路径；原件获取属于持久化职责，不把单页阅读升级成抓取站点或批量爬虫。
- 官方参考（2026-09-21 核对）：[Reader](https://jina.ai/reader/)、[官方实现与接口说明](https://github.com/jina-ai/reader)。接口参数以当前官方文档和实际响应为准。

## 6. Stop Conditions

- 需要改变 Backend 对象身份、持久化/迁移、原件或版本绑定语义，先报告具体冲突，不自行改契约。
- 某类引用没有现成可复用身份/入口，或标准地址必须引入新的公共部署与认证方式，先给出证据与最小选项，不伪造 URL。
- Reader 返回验证页/错误页而无法可靠判定、原始 URL 确已失效、免费接口不可用：保留失败与兜底证据，不通过放宽成功判定伪装通过。
- 同一行为两次有证据的修补仍失败，停止补丁循环，回看 Owner 与实际调用链；不借此引入浏览器或另一执行器。
