## 目标与依据

以现有 DSH Agent Harness 为主力，直接复用 Stock-Research 研究能力；保留 fork 的行情与开箱即用能力，形成真实研究闭环。首页承接当前 Pi workspace 的研究能力需要逐项验证，不以聊天接通或少量文档工具替代研究能力接入。

决定见 [Human Checklist](../human-checklist.md)；运行架构、版本、隔离与启动沿用 [M3](默认Agent与DSH模型配置_M3_2026-09-08.md)。本文件替代旧 M4 调研初稿的模块映射与首页/抽屉共用 DSH 会话建议；不替代 Stock-Research 的业务和写入契约。

## 执行路径与 Owner

```text
首页问题 / 自选股「加入研究」
  → DSH Agent + 复用的研究指导、Skills、tools
  → Stock-Research 服务
  → 文档与证据 / Topic / 受控 Wiki 维护
  → 公司研究、行业卡片、研报与研究记录展示

页面「问助手」（路径：页面直连 / 旧称「问模型」）+ 当前页面上下文
  → 服务端使用 DSH Provider 的模型调用能力
  → 直接回答（无 Agent 循环、无研究工具、无知识写入）

专题研究（前端 /research/legacy，旧业务 API /research）
  → 原六阶段 orchestrator → /finance-stage-model → DSH Provider
  → 原编排器执行工具、推进阶段与校验旧产物
```

- **DSH**：Agent 执行与交互、模型配置、凭据解析、原生会话生命周期；不再串联启动另一套 Pi 对话循环。
- **Stock-Research**：研究业务、文档/revision/证据、Topic、Wiki schema、草案校验及正式写入。复用当前内容与规则，不重新设计意图分类和强制长研究流程。
- **产品插件**：页面、对象上下文、研究触发、状态与引用展示；服务端适配接入既有服务，不复制一套研究数据库或业务 validator。
- **原业务服务**：继续拥有自选、持仓和行情等未迁移业务；自选仍只有一个清单 Owner。
- **Provider**：在 DSH 配置；服务端消费凭据，浏览器不获取密钥。页面直连已通过产品 `/finance-model` 接缝调用当前模型，不是 DSH Agent；旧研报 `/tasks` 尚不能视为已迁移。
- **旧六阶段编排器**：保留原流程、工具和校验，只复用 DSH 模型传输；不是在 DSH 内启动另一套 Agent，不等同 Stock-Research Wiki 发布。前端 `/research` 当前为公司 Wiki，不能与旧业务 API 同名路径混淆。

## 页面闭环与状态

- **首页历史对话**：在「对话」「轨迹」旁增加「历史对话」tab，把原先隐藏的 DSH 项目/session 浏览能力呈现在这里；只显示配置指定的当前研究工作区会话，点击恢复原生 session。工作区与 Stock-Research 对齐，由环境变量/配置确定，不显示项目或目录选择器。会话列表与持久化仍由 DSH 拥有，不复制到 Note/Topic；切换会话不等于取消任务或重新运行研究。
- **对话界面微调**：历史列表沿用现有设计语言和 DSH 原生能力；截图框出的 `/` 指令菜单尚未说明要调整文案、样式还是条目，本轮不擅自删除命令、隐藏权限功能或改变权限默认值。

- **公司**：自选行「加入研究」→ 显示研究中 → 展示可读取的公司 Wiki。重复点击不能重复启动同一公司正在运行的任务；失败可见且可重试。有 Wiki 时可进入查看，移除自选不删除知识。草案不能冒充已发布 Wiki。
- **研报**：上传 → 处理状态 → 可检索 → 首页携带文档标识研究 → 点击引用回读。上传成功不等于解析/索引成功；失败保留原因。新上传沿 Stock-Research 单一路径处理，不同时写入两套知识库。
- **积累**：研究记录分 Topic 与 Theme / Comparison 展示；读取现有积累与维护产物，不为填满页面制造内容。普通页面问答不额外归档到这里。
- **行业**：卡片读取真实申万 Profile，保留分类标识与来源，不将旧赛道静态名称强行等同申万行业。
- **问助手**（路径仍为页面直连）：复用现有抽屉、上下文和停止/错误显示；请求携带发送时的页面内容，不因切页换成另一对象。保留现有 session 存储行为，本轮不新增归档，也不强制删除历史。表面交互以下节为准。

## 验收与演示交接

用户负责手动启动和最终体验验收；Agent 做必要的定点测试、构建和差异核对，不自行长时间运行整套 UI 验收或驻留测试服务。继续使用 `./scripts/setup` / `./scripts/start`；不以重新打包为演示前提。

- 首页用真实问题调用已接入研究能力，能读已有知识、按需补资料并回读证据；记录与 Pi 的已实现对应项和未覆盖差异，不能宣称所有能力等价。
- 首页历史 tab 只列当前配置工作区的 DSH 会话，选择后恢复原记录，刷新不复制/丢失会话；不展示其他工作区，不将 Pi 历史自动转换为 DSH session。
- 神火股份从自选加入研究，看到真实状态与公司 Wiki；失败或维护尚未结束时如实展示，不以固定样例冒充生成。
- 上传一份用户选定研报，处理后可被检索和引用；仅上传接口成功不足以验收。
- 研究记录展示真实 Topic / Theme / Comparison，重新进入页面仍能读到已保存内容；不能用聊天上下文冒充积累。
- 页面「问助手」实际使用 DSH Provider，回答当前页面问题且不调用 Agent 工具；缺配置明确提示，不回退旧 CLI。表面为顶栏「问助手」，路径仍是页面直连。

## Stop Conditions

- 当前 Pi workspace、Backend 服务或真实工具装配与预期不同，先核对来源；缺能力明确报告，不用同名空工具冒充复用。

- DSH 事件不足以承接维护语义时先隔离写入风险，不绕过校验或通过 turn/end 强行发布。
- 页面替换会删除旧内容、接入会改变持仓/行情 Owner 或需要大规模迁移时，停止扩大范围。
