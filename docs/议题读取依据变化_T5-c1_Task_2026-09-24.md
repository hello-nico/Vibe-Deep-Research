# 议题 Agent 读取依据变化（T5-c1）

状态：2026-09-24 用户确认，待实施。Claude Code 规划，Codex 实施并回填 §9。**执行方只跑自动检查**，效果由用户验收。不提交、不 push。实施仓库为 Stock-Research `dsh/`（Backend 接口已有，不改）。

权威：[版本与差异 T5 设计](版本与差异_T5_设计_2026-09-23.md) §2 第 5 点、§4（议题 Agent 读取 `basis-changes` 作为续研输入）；[T5-a](研究页版本差异_T5-a_Task_2026-09-23.md)（`/wiki/pages/diff`）；[T5-b](判断依据带版本_T5-b_Task_2026-09-23.md)（`page:<slug>@<hash>` 依据与 `basis-changes`）。页面展示归 T5-c2（依赖 T3-b）。

## 1. 目标

用户在“我的研究”续研一个已有判断的议题时，Agent 先知道“这条判断依据的研究页，自上次判断以来变了什么”，再决定要不要调整判断；不需要用户手工描述变化。

## 2. 现状（2026-09-24 Claude 核实）

- Backend 已有：`GET /api/v1/wiki/research-topics/{topic_id}/basis-changes`（每个依据研究页 `status: unchanged|changed|version_unknown|page_missing` 与三类计数）；`GET /api/v1/wiki/pages/diff?slug=&from=&to=current`（块级增删改与前后正文）。
- DSH 议题会话（`my_research`）工具清单无读取这两个接口的工具；`MY_RESEARCH_PROMPT`（`dsh/src/consumers.mjs:84`）已要求判断依据研究页时写 `page:<slug>`，但没有续研时先查变化的步骤。

## 3. 冻结决定

- 新增两个**只读**工具，仅注册给 `my_research`：
  - `topic_basis_changes`：参数 `topicId`（只允许当前绑定议题，沿用现有议题访问守卫）；返回接口原样结构。
  - `wiki_page_diff`：参数 `slug`、`from`（64 位版本号）、`to`（默认 `current`）；返回差异块。`slug` 必须出现在该议题 `basis-changes` 的依据页中（防止借机读任意页面差异），不在则拒绝并说明。
- 提示词（`MY_RESEARCH_PROMPT`）增加一句：续研已有判断的议题时，先调用 `topic_basis_changes`；有 `changed` 的依据页，用 `wiki_page_diff` 读具体变化，再判断原结论是否需要调整；用中文向用户简述变化（研究结论 / 数据更新 / 资料时间线各有什么），**不自动改判断**，是否修改仍按现有议题写入流程由用户与 Agent 决定；`version_unknown` / `page_missing` 如实说明为“无法对比”。
- 工具中文名加入 Vibe `lib/taskTrajectory.ts` `TOOL_LABELS`：`topic_basis_changes` →“查看依据变化”，`wiki_page_diff` →“读取研究页变化”（若 Cursor 同期在改该文件，由 Cursor 合入；本 Task 只在 §9 回填需要加的两行）。
- 差异正文可能较长：`wiki_page_diff` 对每块 `before` / `after` 截断到各 4000 字符并标 `truncated: true`，不做摘要改写。

## 4. 范围

- `dsh/src/topic-tools.mjs`（或 `my-research-tools.mjs`，择一与现有议题工具同处）：两个工具与守卫。
- `dsh/src/consumers.mjs`：`MY_RESEARCH_TOOLS` 加两个工具名；`MY_RESEARCH_PROMPT` 加 §3 一句。
- 测试：`dsh/test/tool-scope.test.mjs` 等。

## 5. 验收

- **执行方（自动）**：`cd dsh && pnpm run test`；`git diff --check`；重建 `dsh/dist`，重启工作台。新增测试：两工具只在 `my_research` 注册；`topic_basis_changes` 只允许绑定议题；`wiki_page_diff` 拒绝不在依据中的 slug、非法版本号；截断标记；提示词含续研先查变化的指引。
- **用户验收（用户自己走）**：
  1. 在一个议题里让 Agent 读某公司研究页并更新判断（T5-b 已支持，依据带版本）。
  2. 对该公司点「刷新资料」或做一次公司研究，使研究页出新版本并发布。
  3. 回到该议题点「继续研究」，Agent 开头用中文说明该研究页自上次判断以来的变化（哪类、改了什么），并询问或说明是否需要调整判断，而不是直接改掉。

## 6. Out of Scope

- 议题页展示变化（T5-c2）；证据墙“有变化”角标（T6）；资料 / 事实依据的版本比较；Jev 连续性判断（M9.7，以本工具结果为输入之一，另立）；任务提醒“影响 N 个议题”。

## 7. Stop Conditions

- 需要改 Backend 接口：停止说明。
- 与其他工具同时修改同一文件（T4-a 同期改 `dsh/src/background-review.mjs`，本 Task 不应触及；若需改 `consumers.mjs` 与他人冲突）：先看 git 状态，冲突时停下告知用户。
