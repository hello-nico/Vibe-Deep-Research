# 状态徽标、待处理入口与草案失效处理（T4-b）

状态：2026-09-24 待 Codex 实施并回填 §9。**执行方只跑自动检查**；真实界面由用户验收，视觉收尾由 Claude 做。不提交、不 push。实施仓库：Vibe `desktop/`（Backend 接口已由 T4-a 提供，不改 Stock）。

权威：[产品对象模型与交互 v1](产品对象模型与交互_v1_2026-09-23.md) §2.3、§3、§4（状态徽标行）；[T4-a Task](对象状态与草案持久化_T4-a_Task_2026-09-24.md) §3（接口与字段）；[Human Checklist](../human-checklist.md)「知识整理草案失效处理（2026-09-23）」：草案 24 小时过期或研究页底稿变化即作废；任务记录与提醒卡显示“草案已失效”并提供「重新整理」；不自动重做、不延长保存。

## 1. 目标

1. 对象的状态（建立中、有新资料、草案待确认、待确认维护、报告已过期）在对象页头和研究列表上一眼可见，点一下就到能处理的地方。
2. 「我的研究」有一个“待处理”入口，集中列出需要用户动手的事。
3. 公司研究任务的草案状态以 Backend 台账为准；失效时显示原因并可「重新整理」。

## 2. 现状（2026-09-24 Claude 核实）

- 状态接口：`POST /wiki/objects/status`（1–50 个公司 / 行业 slug），代理已放行（`dsh/finance-ui/research.mjs`）。前端只有悬停预览卡在用：`lib/objectStatus.ts` `statusBadges` / `loadObjectBadges`（单个 slug、60 秒缓存）。
- 草案台账：`GET /wiki/page-drafts?slug=&status=`、`POST /wiki/page-drafts/{draft_id}/discard`，**代理尚未放行**；任务记录已带 `draft_id`（T4-a DSH 接线）。
- 任务列表：`pages/MyResearch.tsx` 公司研究状态由 `lib/reportTasks.ts` `researchTaskStatus` 从本机任务记录推出（`awaiting_authorization` → “待审阅”），不看 Backend 台账。
- 任务提醒：`lib/taskNotices.ts` 只覆盖图文报告与刷新资料，公司研究完成没有提醒。

## 3. 冻结决定

### 3.1 状态徽标

- 新增共享零件 `ObjectStatusBadges`（文案沿用 `statusBadges`，最多显示 2 个，其余收为“+N”并在悬停列出），预览卡改用同一零件。
- 显示位置：公司页、行业页页头（对象工具栏标题旁）；「个股研究」「行业研究」列表每行。列表按页批量请求（每批 ≤ 50，一个列表一次请求为宜），不逐行请求；共享 `lib/objectStatus.ts` 缓存。
- 点击去处：有新资料 → 该对象页的刷新确认（`?refresh=confirm`，与现有提醒一致）；草案待确认 → 对应公司研究任务的审阅处（任务记录或其来源对话中的草案卡）；报告已过期 → 该对象图文报告分段；建立中 / 待确认维护 → 该对象页。没有可去处的徽标不可点。
- 状态只读 Backend，不在浏览器或 Client SQLite 另存。

### 3.2 “待处理”入口

- 「我的研究」加「待处理」分段（放在「议题」之前），列出：草案待确认、草案已失效（近 7 天）、有新资料待确认、待确认维护。对象范围：个股研究名单中的公司（Client 选择）+ 已发布的行业页；按 3.1 批量读取状态，草案来自 `GET /wiki/page-drafts`。
- 每行：对象名（对象标签）、事项、时间、一个主操作（审阅 / 重新整理 / 确认新资料 / 查看）。
- 左侧导航「我的研究」在有待处理事项时显示数字（不含已失效项）。读取失败时不显示数字，不报错打扰。

### 3.3 公司研究任务的草案状态

- 任务行有 `draft_id` 时，状态按台账：`pending` → 待审阅；`published` → 已发布；`invalid` → 草案已失效，原因用人话：`expired` “超过 24 小时未确认”、`base_changed` “研究页已更新”、`discarded` “已放弃”。无 `draft_id` 的旧任务维持现状。
- 失效行提供「重新整理」：对该公司发起现有公司研究任务（同研究页入口的启动方式），不自动触发、不延长旧草案。待审阅行可「放弃」（调用 discard，二次确认）。
- 公司研究任务完成时推送提醒（沿用 `taskNotices` 机制与样式）：出草案 → “「X」· 研究完成，草案待你审阅”；无新增 → “「X」· 研究完成，没有需要更新的内容”；失败 → 沿用现有失败文案。草案状态以台账为准。
- 代理放行：GET `/wiki/page-drafts`（查询参数 `slug`、`status`）；POST `/wiki/page-drafts/{draft_id}/discard`（`draft-<24hex>`，注意与现有 `DRAFT_TOKEN` 正则区分）。

## 5. 验收

- **执行方（自动）**：`cd desktop && npm run typecheck && env -u NODE_ENV node --test test/*.test.ts`；`git diff --check`；`node dsh/build-ui.mjs`；重启工作台。新增测试：徽标排序与“+N”；批量分批（>50）；徽标去处映射；台账状态 → 任务状态与失效原因文案；待处理汇总与导航计数（失效项不计数）；代理放行两条新路径且 `draft-` 与 token 不串。
- **用户验收**：
  1. 个股研究列表与公司页头能看到徽标（如“有新资料”“报告已过期”）；点徽标到对应处理位置。
  2. 发起一次公司研究并出草案：收到“草案待你审阅”提醒；「我的研究 · 待处理」出现该条，导航有数字；审阅发布后该条消失、任务显示“已发布”。
  3. 让一条草案失效（不处理超过 24 小时，或刷新该公司资料使研究页更新）：任务显示“草案已失效 · 研究页已更新”；点「重新整理」开始新的公司研究。

## 7. Stop Conditions

- 状态接口字段不足以决定徽标去处或待处理事项（例如无法从草案定位审阅位置）：停止，回填缺口，不在前端拼第二份状态。
- 个股研究名单 + 行业页数量导致状态请求明显拖慢页面（> 1 秒）：停止回填实测数据与方案。
- 与其他工具同时修改同一文件（T3-b 同期改 `Layout.tsx`、`dsh/client.tsx`；验收问题修复改 `MyResearch.tsx`）：先看 git 状态，冲突时停下告知用户。
