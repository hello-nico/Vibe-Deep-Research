## 3. 唯一试验闭环

已有公司问题 → 现有检索定位对象并召回候选 → Backend 返回有界关系/材料 → Jev 选择相关分支 → 研究 Agent 阅读原文并回答。

- 首期仅只读，一到两层；以现有对象、关系和证据为基础。
- Jev 只选择检索方向，不生成新关系，不判断财务数字是否真实，不作投资结论。
- 关系路径是调查线索，不自动成为因果证明。
- 原有全文/语义检索负责无关系材料的初始召回；新上传文件不能依赖已有图边完成冷启动。
- 优先作为现有检索内部试验，不增加主模型常驻工具或第二套研究执行器。
- 第一阶段仅离线回放或旁路记录，不改变线上回答、后台触发及持久知识。

## 4. Owner 与输入输出约束

| Owner | 职责 |
|---|---|
| Backend | 实体、关系、证据、时间与权限过滤、持久数据及校验 |
| Jev | 有界候选的语义相关性判断与排序 |
| DSH / 研究 Agent | 执行、预算、中止、轨迹、证据阅读与回答 |
| 既有后台 subagent | 后续知识修订，沿用版本、来源、纠正与审计契约 |
| 用户 | 是否推进接入、验收标准、产品取舍与最终判断 |

输入须包含当前问题、目标对象、当前路径及候选的身份、关系类型/方向、有效时间、来源和争议状态；只发送判断所需信息。
输出只允许引用本次候选身份；必须允许无匹配和信息不足。多分支相关不等于强制单选归类。
路径身份须保留边/Claim：相同两个节点间的持股、供应、担保不能合并为同一关系。
候选截断及覆盖不足须可见；不得把未召回解释为不存在。
选择概率、路径排序分数和事实可信度分开；阈值须由真实样本校准，不能照搬默认 0.5。
低置信度、超时或接口错误退回现有检索，不阻塞主线；不得把接口失败归为“无关联”。
试验调用深度、候选数、次数、时延和费用设硬上限；具体值在试验开始前确定并记录。
接入前确认服务端凭据 Owner 与向新增外部服务发送数据的范围；不复用用户全局 CLI 认证，不在浏览器放密钥。

## 5. 试验步骤与验证

1. 审计少量真实公司的关系、证据与材料覆盖，区分检索缺陷和知识缺失。
2. 从历史 sessions 选问题，覆盖公司比较、产业传导、历史问题续问、无相关关系、冲突及过期证据。
3. 先固定人工核对的关键证据集与判分规则；标注可接受缺口，不只以历史模型答案为真值。
4. 同一数据快照、问题与阅读预算比较现有检索、确定性有界扩展、Jev 分支选择；校准样本与验收样本分开。
5. 检查关键证据召回率、无关材料比例、关键反证漏召回、耗时分布、调用费用及退回比例。
6. 覆盖无匹配、候选截断、循环、平行关系、时间过滤、低置信度及 API 失败。
7. 最后再评估真实 DSH 回答是否改善；检索评分不能替代回答质量与引用核验。

复用现有轨迹/验证记录，记录模型与问题版本、输入快照标识、候选与截断、选择分布、实际路径、终止原因、耗时费用与退回原因。
保留足以回放的证据，但不另建持久知识副本或第二执行台账。
通过标准的数值门槛待试验前确认；当前不预先声称性能、成本或研究质量提升。

## 7. Stop Conditions

- 关键关系或身份覆盖不足：先报告数据缺口，不靠分类器补造。
- 需要改变数据出境范围、凭据归属、公共接口或写入权限：提交具体选择给用户。
- 相比基线没有稳定收益，或漏掉关键反证、时延费用超预算：停止扩大试验，保留结果。
- 两轮调整仍无改善：复核候选召回、知识覆盖及评价标准，不继续叠加阈值和规则。
