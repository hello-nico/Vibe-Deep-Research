## 1. 目标

验证 Jev 能否可靠判断“一句带引用的结论”与“它引用的原文”是否一致，特别是规则查不出的**语义错位**，并和现有办法对比，决定是否做成产品功能。

题目 `citation_check`（choice）：只根据所给原文，判断它与待核验结论的关系，不补充外部事实。

- `support`：原文明确支持结论。
- `conflict`：结论与原文含义矛盾。
- `insufficient`：现有材料无法确认。

重点错位类型（按研究纪律）：

| 类型 | 例子 |
|---|---|
| `modality` 预计写成已实现 | 原文“预计下季度收入 8 亿元” → 结论“本季度收入已达 8 亿元” |
| `speaker` 提问写成陈述 | 原文分析师问“取消订单是否增加”、管理层答“保持稳定” → 结论“公司确认取消订单增加” |
| `period` 期间错配 | 原文“2026 年上半年” → 结论“2026 年全年”；单季写成累计 |
| `scope` 口径错配 | 原文“归母净利润” → 结论“净利润”；“母公司” → “合并” |

数字本身对不对由代码比对（沿用第 2 轮 `number_match`），不在 Jev 的题目里。

## 2. 发送边界

只发公开内容（沿用现有 Jev 边界，不适用 2026-09-25 为记忆放宽的规则）：结论句 + 已接受的定期报告 / 公告原文摘录。跳过上传资料、我的资料、研究记录、`provider:`（结构化数据，无原文）、`lookup:`（缺口）、`taxonomy:` 引用。

## 3. 样本

### 3.1 真实样本（“原样”，预期多为 `support`）

- **来源 A**：已保存的图文报告（`workspace/wiki-reports/**`，约 30 份），抽取带 `data-ref` 的元素文本作为结论，引用为 `claim:` / `evidence:` / `source:` / `page:` 时，经 `app/services/ref_resolver.py`（或 `POST /wiki/refs/resolve`）解析出原文摘录。
- **来源 B**：深度对话回答中带引用的句子（沿用第 2 轮 `claim_before_citation` 的抽句与去重）。
- 结论先按句拆成单一事实（沿用第 2 轮做法）；原文摘录保留章节标题、报告期与相邻上下文，≤ 1,500 字。
- 上限 200 条；两个来源各不超过 120 条。

### 3.2 改写样本（有标准答案，不需人工盲标）

从 §3.1 中 Claude 复核确认为 `support` 的样本出发，用**确定性规则**生成：

- `conflict`：按 §1 四种类型改写结论一处（词表替换：预计 ↔ 已实现 / 实现、上半年 ↔ 全年、第 X 季度 ↔ 前三季度 / 全年、归母 ↔ 全部 / 合并、母公司 ↔ 合并 等；改写后数字保持不变）。每种类型各 ≥ 30 条；不适用的样本跳过。
- `insufficient`：从原文摘录中删去包含结论关键信息（报告期、指标名或数值）的句子，保留其余上下文。≥ 40 条。
- 改写规则写成代码并单测；每条记录 `origin_id`、`mutation`、`expected`。
- `speaker` 类在本地公告中很少出现，允许 Claude 编写 ≤ 20 条合成样本（投资者关系活动记录体例），单独标 `synthetic`、单独统计。

### 3.3 Claude 复核

- 运行前，Claude 抽查全部原样样本与 ≥ 30% 改写样本，确认预期答案成立（改写后仍可能恰好被原文支持，或删句后仍能确认）；不成立的剔除，写理由。
- 运行后，对所有与预期不一致的样本逐条复核，区分“Jev 错”与“样本错”。原样样本被判为 `conflict` / `insufficient` 时，复核是否发现了**真实引用错误**（单列统计，这是额外收获）。

## 4. 变体

- 变体 A：原文摘录含章节标题与报告期元数据。
- 变体 B：只有摘录正文。
- 比较两者，确定产品接入时必须带哪些上下文（帖子与第 2 轮都提示缺上下文会误判）。

## 5. 对照（现有办法）

对同一批样本计算现有办法的结果：报告生成时的引用约束（`data-ref` 须在允许集合内）+ 第 2 轮 `number_match` 数字比对。报告“现有办法抓出 / Jev 额外抓出 / 两者都漏”的条数。

## 6. 运行

- 脚本：新增 `backend/scripts/jev_eval/evaluate_r4.py`（`prepare` / `run` / `render`），传输复用 `app/services/jev_gateway.py`；在 Backend 容器内运行，密钥只从环境读取，不打印。
- 输出：`workspace/research/jev-eval/r4/`（已忽略）：`samples.jsonl`、`results.jsonl`（选项、三类概率、延迟、用量）、`review.md`。
- 上限：总请求 ≤ 1,200 次（样本约 450 × 两个变体，外加重试）；失败最多重试 2 次，单独计数。

## 7. 通过标准（Claude 裁决）

| 指标 | 标准 |
|---|---|
| 改写 `conflict` 被判为 `conflict`（按类型分别算） | 召回 ≥ 0.9；未达标的类型不进入产品 |
| 删句 `insufficient` 被判为 `insufficient` 或 `conflict`（即“没有误判为支持”） | ≥ 0.9；其中判为 `insufficient` 的占比另报 |
| 真实原样样本被误报（经复核确为正确，却被判为 `conflict` / `insufficient`） | ≤ 5% |
| 延迟 | p95 ≤ 2.5 秒 |

另报：各类混淆矩阵、阈值–精确率表（0.05 步长）、变体 A / B 差异、对照结果、单次平均费用、复核中发现的真实引用错误清单。

## 8. Out of Scope

产品接线（报告 / 草案后台核对、疑点标记、交回 Agent 修改）；数字正确性（代码比对）；新闻去重与新事件判断；回答中投资动作建议检查；上传资料与研究记录。

## Stop Conditions

- 可解析出原文的真实引用少于 60 条：停止，回报分布。
- 改写规则产生的样本在 Claude 抽查中错误率 > 20%：停止，先修规则。
- `ref_resolver` 无法稳定取回原文摘录（大量 404 / 解析版本缺失）：停止，回填样例。
- 预算或 Jev 不可用：停止，记录已完成部分。

## 9. 执行回填与裁决

### 9.1 第一次 prepare 复核（2026-09-25 Claude）

Codex 已完成 `evaluate_r4.py` 与单测，按 Stop Conditions 在真实样本 40 条（<60）时停止，停得正确；但原因是样本构造方式，不是数据不足。**修后重跑 prepare**：

1. **结论取整句 / 整行**：现在只取 `data-ref` 元素本身文字（如“51.00%”“90.3 亿元”），1,064 条因不足 15 字被丢，留下的也是无主语片段（“三峡电能（湖北）间接 51.00%”）。改为：取该元素所在的最近句子；在表格里取整行，并拼上列标题；前面加报告名与报告期（如“长江电力 2026 年半年度报告，2026H1：……”）。
2. **数字比对**：原文表格数字多无单位（“51.00”），第 2 轮 `number_match` 要求单位一致，导致 30/40 “不匹配”。缺单位时按数值本身比对（容差同原规则），或从表头读取单位；两种都失败才记“不匹配”。对照（§5）用修正后的比对。
3. **改写词表补本产品的写法**：期间 `FY2025 ↔ 2026H1`、`2026H1 ↔ 2026 全年`、`Q1 ↔ 前三季度`；口径 `直接持股 ↔ 间接持股`、`归母 ↔ 合并`；语气“拟 / 预计 ↔ 已”。改写后仍须保持数字不变。
4. **原文摘录收窄**：表格只保留表头与包含结论实体或数字的行（上下各 1 行上下文），整段 ≤ 1,500 字；报告名与期间放进 metadata。
5. 重跑 prepare 后回复：真实样本条数与来源分布、各改写类型条数、跳过原因计数、数字比对分布；Claude 抽查后再运行 `run`。

### 9.2 第二次 prepare 复核（2026-09-25 Claude）

真实样本 62 条逐条复核，结论写在 `workspace/research/jev-eval/r4/review-claude.jsonl`（`expected` 为 support / insufficient / drop，附理由）：**支持 11、证据不足 26、剔除 25**。

**重要发现（产品问题，不只是评估样本问题）**：37 条有效结论里有 **13 条引用错块**，占 35%：结论本身多半正确，但 `data-ref` 指向的原文块与结论无关（例如“水电总装机 7179.5 万千瓦”引用的 p8:b7 是“新增重要非主营业务 □适用 √不适用”，实际内容在相邻的 p8:b6）。集中在两份议题图文报告（电力公司结构、华能资本开支与分红）；深度对话里的引用基本正确。现有报告发布只检查引用 ID 在允许集合内，不检查内容。已记入 todo，另行处理。

**脚本修正（修后重跑 prepare，仍不执行 run）**：

1. 结论文本去掉引用标签文字（如“2026 半年报 p181·b15”“2025 年报 p206·b6”）。
2. 剔除非事实结论：只有块编号列表、报告开头 / 研究问题整段、标题与缺主语的片段（如“2025 年见 2025年年度报告·分产品毛利率”）。规则写成代码并单测。
3. 表格行结论按“主体，期间，列名 数值”重组（如“三峡电能有限公司，2026 年上半年，营业收入 2.21 亿元，净利润 −0.05 亿元”），不要把表头与数值直接拼在一起。
4. 摘录收窄修正：匹配前先去掉表格单元格里的换行与空格（原文“湖南攸县抽水蓄 能有限公司”因此没匹配上）；一行都匹配不到时保留原块前 1,500 字，不得只剩表头。
5. 真实样本的预期答案**以 `review-claude.jsonl` 为准**，`drop` 的不进入样本；改写与删句样本**只从 `expected = support` 的样本生成**（§3.2 原要求），现有由“证据不足”样本改写出的 mutation 全部作废。
6. 由于可用的“支持”样本只有约 11 条，改写后每类不足 30 条属预期，不作为停止条件；`modality`（预计 ↔ 已实现）与 `speaker`（提问 ↔ 陈述）在真实结论里没有素材，改由 Claude 编写合成样本（各 ≤ 20 条，单独统计）。Claude 收到重跑结果后提供合成样本文件。
