## 1. 问题与证据（2026-09-23 实测）

用户反馈：新建公司研究页、刷新行业研究页非常慢；期间行业研究列表显示“Error: 资料正在更新，请稍后重试”。三个原因叠加：

1. **gbrain 每次调用固定多等 5 秒**。`docker-compose.yml:88` 与 `backend/wiki/gbrain_adapter.py:118,421` 设置 `GBRAIN_FLUSH_GRACE_MS=5000`，gbrain 按此值在退出前固定等待（源码 `src/core/cli-force-exit.ts`，默认 250ms）。容器内 `gbrain --version` 实测：5000→5251ms、500→747ms、0→270ms。一次 `publish()` 调用 sync、extract links、每条变动链接一次、`list_pages` 分页核对 1–4 次（每页 20，现 64 页）、`--version`，共 5–8+ 次，约 25–40s，实际工作不足 2s。
   - 5 秒由提交 385c220（2026-08-25）引入，用于规避 gbrain 退出过快导致 stdout 截断。gbrain 0.46.23 起以 `writeStdoutFinal` 在退出前完整送达输出；容器固定为 0.43.0.0（`backend/Dockerfile:2`、`PINNED_GBRAIN_VERSION`），不含该修复。
2. **全站一把锁，读等 2 秒即失败**。`wiki_publish_lock.py` 用同一 advisory lock：写者独占整个发布周期，读者 `READ_LOCK_WAIT_MS=2000` 后抛 `WikiPublishBusy` → 503“资料正在更新”。日志：06:15:54 行业刷新确认期间，06:15:18–06:15:51 `GET /wiki/industries/nbs` 连续 5 次 503。
3. **新建公司页在锁内联网**。`ensure_company_page` → `_refresh_company_page_unlocked` 在独占锁内 `initialize_page(providers=…)` 请求同花顺/腾讯，并同时发布公司页与所属行业页。公司“刷新资料”（`_refresh_company_api_locked`）已是锁外取数，可作对照。
4. 工作台对可重试 503 直接显示 `Error: …`（如 `pages/IndustryCenter.tsx`），无自动重试。

## 2. 目标

- 单次 Wiki 发布（行业时间线追加、公司字段更新）从数十秒降到数秒内；新建公司页锁持有时间不含外部取数。
- 写入期间读取不因锁直接失败：短暂等待后正常返回；仍超时时页面自动重试，不显示原始错误文本。
- 不牺牲现有保证：gbrain 输出完整性校验、发布幂等与 pending 恢复、页面完整性校验、读写一致性（读到的是某个完整已发布版本）。

## 3. 范围（按步骤）

### A. gbrain 调用提速（P1）

1. 在隔离环境（测试库 / 独立 wiki 根）评估 gbrain 升级到 ≥0.46.23（优先当前上游稳定版本）：`init / sources / sync / extract / list_pages / get` 等适配器用到的命令与输出结构、schema pack、已发布 64 页的读取与再发布兼容。
2. 兼容则升级 `Dockerfile` 与 `PINNED_GBRAIN_VERSION`，`GBRAIN_FLUSH_GRACE_MS` 改回 gbrain 默认（移除覆盖，或显式 250）。
3. 不兼容或需另行迁移：停止升级（§7），改为逐命令测量输出体量，只对确有大输出的命令保留较长等待，其余降至默认；以现有“完整 JSON 文档”校验兜底。不得无测量地统一调低。
4. 记录每条 gbrain 命令耗时与一次 publish 总耗时（改造前后对照），写入 §8。

### B. 新建公司页锁外取数（P2）

- 仿照 `_refresh_company_api_locked`：锁外先取 Provider 数据，锁内只做存在性复核、编译与发布；锁内发现页面已被他人创建则返回 `exists`，不重复发布。

### C. 读取不因写入直接失败（P2）

- A 完成后按实测 publish 耗时上调 `READ_LOCK_WAIT_MS`，使一次常规发布内的读取等待而非失败；等待上限仍有界。
- 工作台对 Backend `retryable: true` 的 503 做有界自动重试（沿用现有取数层，不新增平行请求链），重试耗尽再显示人话提示与重试按钮，不显示 `Error:` 前缀。
- 评估是否需要“读已发布快照不加锁”：仅当 A、C 后仍有明显失败时另立决定，本 Task 不做读路径重构。

## 8. Stop Conditions

- 新版 gbrain 命令或输出结构与适配器不兼容、需数据迁移，或已发布页面读取/再发布校验失败：停止升级，走 §3 A.3，记录差异。

- 锁外取数导致同一公司并发创建出现重复发布或版本错乱：停止 B，保留原路径。
- 自动重试造成请求风暴（同页并发重试超过上限）：停止 C 的前端部分，改为手动重试。
