## 1. 权威、目标与范围

产品决定见 [Human Checklist](../human-checklist.md) 顶部；证据与覆盖限制见 [工具审查 §9](五页问助手工具与对象能力审查_Task_2026-09-22.md)。本 Task 拥有五页实现闭环；M9.7 的 Jev 协议和 Topic Task 为上层/后续依赖，旧冲突条款不用于实施。

目标：页面提供正确对象与上下文；Agent 用场景所需的单一职责工具；每轮评估维护需要，具体提案经用户选项确认后由 Backend 写入，并可审计回读。

- 五页为 market / intel / industry_wiki / industry_profile / company_wiki；深度对话、我的研究执行行为不在改动范围。
- 五页不得修订研究主张、判断、成立/失效条件；只能提议新建对象、更新资料/数据、实体与关系。任何创建不得夹带生成经营判断。
- 硬关系只承载核心对象间直接关系；按 Stock standard 的端点、类型、方向、原文与双时间准入。软关系不得冒充硬关系；因果/受益判断交 Topic。
- 用户按维护意图选择一批具体变更；逐项执行/回执，无新增不弹框，部分失败不冒充成功。
- 确定性刷新不调用 Agent/Jev，保留明确范围的确认与动作审计；不改研究块。

## 2. 实施设计

### 2.1 对象上下文先补齐

- 资讯子栏目保留场景身份；公告带公司 symbol、URL、日期；事件实际条目可见，有 URL 时复用 URL 引用，无 URL 不编造可读正文。
- 个股详情补齐真实已加载 companyQuotes；未加载则准确说明缺口，不为填快照新增隐式取数。
- Profile 传递准确身份、版本、evidence_docs 正式身份；target 支持 Profile 身份但不因此授予改 Profile 正文权限。
- 列表/详情与多引用不混同绑定目标；引用他人对象不自动改绑。截断标签依据实际 clipped，保留来源/版本和继续读取路径。
- 宿主每轮提供当前日期与数据业务日，完整落地前保留 today；公告身份完整落地前保留 wiki_search 兜底。

### 2.2 工具组件与页面配置

组件是代码/契约复用单位，不做通用 action 工具或新动态加载器。注册按现有角色机制；每个工具只完成一个业务动作。下列为本包配置方向，变更前逐项核对真实输入可达性。

| 场景 | 保留/补齐 | 移出默认或禁止 |
|---|---|---|
| 大盘 | Wiki/公司既有事实、引用、外部检索与URL阅读、Topic发现；按公司/行业发现并读Profile | 默认财报遍历、通用成果/方法、市场多窗口研究；不因模型自行展开而加行情计算 |
| 资讯 | URL读、Wiki/公司事实、引用、定向雷达、资料发现/index/scan/read、必要确定性计算、Topic发现、Profile发现/读 | 直接入库、固定四渠道90天扫描、无关成果/方法 |
| 行业 | Wiki、硬关系与研究链接读、行业资料发现/index/scan/read、Profile发现/读、外部补证、公司事实、计算、Topic发现 | 默认个股行情/雷达、无可达成果的区间计算、直接stage准入 |
| 产业 | Profile、来源资料index/scan/read、Wiki/关系、外部补证、公司事实、计算、Topic发现 | 重复公司资料遍历、无关成果/方法、改Profile正文 |
| 个股 | Wiki/公司事实、关系、公司资料list/index/scan/read、Profile、定向雷达、指定行情、计算、外部补证、Topic发现 | 全库常规遍历；直接fetch-data/refresh/ingest/stage写入 |

- 公共不再一律装17工具；resolve_refs 与必要身份发现保留。wiki_list_pages 只在有明确目录外发现需求且 search 不覆盖时保留，不用搜索故障证明其必需。
- 资料发现复用已有 Backend 读取能力，补公司之外的筛选/来源关联；不能把“无symbol列全库”直接称为行业资料检索。
- query_observation 保留公司已有事实快照职责，明确无主动取数与知识写入；关系专用读取分别指向事实图和研究链接。
- fetch_source_url 在五页仅允许只读；入库为独立提案动作。深度对话现有行为不顺带改动。
- observe_radar 显式 channels、since、limit；获取报告工具只提交明确的资料任务，轮询/唤醒复用现有生命周期。
- 计算只产生可追溯计算凭据，不写研究知识。是否保留 calculate_market_result 以成果输入可达性判断，不凭没有生成工具就直接删共享实现。

### 2.3 读取与授权写入彻底分开

- 按 PAGE_ASSISTANT_ROLES + Agent 模式隔离：source_read_blocks / resolve_refs / query_observation 的读记录不能被轮末 finalize 自动提升为 Claim、关联或 Wiki 刷新。
- 保留读取审计、版本和引用；不整体删除 hook token，不改变 deep_research / my_research /发布角色既有路径。
- 五页后台只能准备维护候选，不能绕路入库、改知识、写研究块草案；现有执行生命周期保留，不新增第二整理器。记忆系统改造另议，本包不得借记忆写入绕过对象维护门。
- DSH server 插件验证角色、场景、实际用户选择与提案绑定；Backend 验证内容、版本、幂等与正式写入。模型提供的 confirmed=true 不构成授权。

### 2.4 一套提案，复用各对象写入 Owner

工程方案：扩展现有 research-candidates 作为维护提案记录入口；research-links 继续拥有已确认研究关联，page-drafts 继续拥有既有草案发布，不把它们改成万能写入器。

兼容方案：缺 kind 仍为旧 Topic 候选；旧 list/去重/adopt/dispose 仅操作 Topic，maintenance 独立保留且不参与40条裁剪。全部 candidates 写入复用锁与原子替换，不迁移旧候选。下游执行结果未知时先回读，无法归属则停止该项自动重试并保留回执。

- 新维护提案与旧Topic候选按明确kind区分；包含来源session/turn/role、目标身份/版本、稳定item ID、具体动作/参数、原文依据、Jev结果、用户选择及逐项执行回执。
- 动作采用闭集：公司对象创建、Topic创建、指定资料入库、资料时间线/数据刷新、事实候选准入、研究链接维护。接口不接受任意路径、代码或方法名。
- 已有下游接口能完成则直接复用；不存在时补单一业务服务，不让提交提案接口执行检索、研究或写知识。
- 选项展示用户可理解的变更，不显示内部ID。选择绑定服务端固定提案版本；更改目标/参数、证据漂移或过期版本必须重新确认。
- 持久化记录用户选择后才执行，逐项幂等；重试不重复成功项，未知执行结果先回读，拒绝/取消不写知识。
- 异步入库显示已提交/处理中，最终完成另记；关闭面板不伪称回滚已提交任务。失败保留可回查原因，不仅notify后清空。

### 2.5 DSH 确认与 Jev

- 挂载现有 ask_user_question；多选绑定提案item ID与显示标签，拒绝/取消/自定义答案按明确语义处理，不将自定义文本自动当批准。
- 首期五页维护提案在主会话承接确认；受委派子Agent返回候选，不直接问用户。不得向下一轮用户问题插入过期提案或重开已结束轮次。
- Jev 在 Backend 内做有限分类：已有对象/需新建/不足；关系类型/方向/支持状态；重复/补充/冲突。候选与改写文本由Agent生成，Jev不生成长文、不自行写入。
- 每轮在既有交接处评估本轮涉及对象与增量；无维护素材可确定性记无候选，不扫描全库。Jev请求失败与“无须维护/证据不足”分开；服务失败不得永久记业务rejected。
- Jev只在充分上下文上分类，不预裁研究材料。限额、超时、重试、Provider与允许发送的数据范围须在真实调用前记录；不读全局CLI密钥、不用CLI子进程代替Backend适配。
- 先完成适配与错误路径，再用获准真实样本验收。未获实际数据发送/费用授权前不调用外部Jev；mock通过不称闭环完成。

## 5. Out of Scope

- 深度对话重构、Topic完整工作区、主张修订实现、记忆设计、Theme/Comparison迁移、全图/画布、统一Git式对象版本。
- 默认为大盘加入半年历史研究、全市场后台扫描、全类型关系抽取、Jev替代生成式研究。
- 通用工作流引擎、通用写入工具、平行知识库、凭据复用或自动发布。

## 6. Stop Conditions

- candidates不能在不破坏旧采用语义的前提下可靠记录提案/回执，或需要持久化迁移：停止D包写入设计，提交具体兼容方案，不新建第四套绕过。
- 实际DSH版本无法把用户回答可靠绑定提案，或只能由子Agent直接询问：停止授权执行，保留只读能力，不用模型自述授权。
- 工具收敛导致问题所需资料无法到达、需改深度对话或Topic权限：暂停该项，拿实际反例重审，不扩大范围。
- 外部Jev缺凭据/发送与费用授权：不调用，不以假结果放行写入；继续无外部请求的工程工作。
- 同一行为两次修补仍失败：保存证据重审Owner/契约，不叠加兜底。版本冲突不静默覆盖新对象。
