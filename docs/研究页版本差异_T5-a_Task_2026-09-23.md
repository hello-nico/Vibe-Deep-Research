## 1. 目标

提供只读接口：给出同一研究页两个版本（按 `input_hash`）之间按内容块的差异，分“研究结论 / 数据更新 / 资料时间线”三类。供 T5-b（判断依据带版本）与后续议题页、证据墙、议题 Agent 使用。

## 2. 现状核实（2026-09-23，Claude 只读）

- gbrain `page_versions.frontmatter` 含完整 `compiled_spec`（万华化学 3 个版本），但**不含 `input_hash`**。
- Wiki 根目录是 Git 仓库，每次发布提交一次（现 39 个提交），Markdown 首部含 `compiled_spec`，**不含 `input_hash`**。
- `.stock-research-wiki/pages.json` 有 `input_hash / markdown_sha256 / recipe_id`，但只存当前版本，且被 Wiki 仓库 `.gitignore` 忽略。
- `input_hash` 由 `wiki/compiler.py` `page_input_hash(recipe, spec, slug)` 计算，含渲染契约版本与 recipe；历史版本反推仅在契约未变时成立。

结论：需要一份 **Backend 自有的发布台账**，把 `input_hash` 与当时的内容指纹对应起来；内容本身从 Wiki Git 历史取。

## 3. 冻结决定

- **发布台账**：在发布成功、提交 `pages.json` 的同一步（`gbrain_adapter.py` `_commit_index`，持有发布锁）按页追加一行到 `.stock-research-wiki/history.jsonl`：`{ slug, input_hash, markdown_sha256, recipe_id, published_at }`。只追加、不改写；写入失败按发布失败处理（与 `pages.json` 同等对待）。
- **取版本内容**：按台账的 `markdown_sha256` 在 Wiki Git 历史中找到对应文件内容（逐提交计算该路径内容的 sha256 匹配），解析首部 `compiled_spec`。不读 gbrain 历史表作主来源（其无 hash 对应），可作核对。
- **历史补录**：一次性只读脚本（可重复运行，幂等）遍历 Wiki Git 历史，对每个历史版本用当时首部 spec 与 `pages.json` 当前 `recipe_id` 反推 `input_hash`；台账中不存在的补一行并标 `"source": "recomputed"`。反推不出的不写（查询时视为未知）。不改任何研究页或 gbrain 数据。
- **分类规则**（第一版）：`research_blocks` 的块 → `research`；`source_timeline` → `timeline`；其余 `blocks` → `data`。
- **对比粒度**：按块 `kind` 对齐，给出 `added / removed / modified`；`modified` 附前后内容。数据类块若内容含 `items`，另给按 `(metric, period)` 对齐的 `items_added / items_removed / items_changed`。资料时间线给新增 / 移除的条目。附 `refs_added / refs_removed`。
- 未知版本返回 404 `{ code: "version_unknown" }`，调用方按“无基线”处理；不猜测。

## 4. 接口

`GET /api/v1/wiki/pages/diff?slug=<slug>&from=<input_hash>&to=<input_hash|current>`

```json
{ "slug": "companies/600309-sh", "from": "…", "to": "…",
  "from_published_at": "…", "to_published_at": "…",
  "blocks": [ { "kind": "operating_model", "category": "research", "change": "added",
               "before": null, "after": "…", "refs_added": ["source:…"], "refs_removed": [] } ],
  "summary": { "research": 1, "data": 0, "timeline": 0 } }
```

- 只读，走现有共享读锁；`from == to` 返回空 `blocks`。
- 放在 `backend/app/api/v1/wiki.py`，对比逻辑放独立模块（如 `backend/wiki/page_diff.py`），便于 T5-b 复用。

## 6. Out of Scope

- 议题判断依据带版本、`basis-changes` 接口（T5-b）；任何界面（T5-c / T6）。
- 资料（Document）版本对比；主题 / 对比 Wiki 的特殊结构（按同一分类规则处理，不专门适配）。
- 回滚、版本清理。

## 7. Stop Conditions

- Wiki Git 历史存在无法按内容指纹定位的发布（例如发布未提交 Git）：停止补录该部分，回填数量与原因。
- 台账写入需要改变发布锁或发布顺序语义：停止，回填方案。
- 与其他工具同时修改同一文件：停下告知用户。

## 8. 回滚

还原代码；`history.jsonl` 为新增文件，可保留或删除，不影响现有读取与发布。
