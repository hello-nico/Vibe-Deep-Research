## 1. 目标

议题判断记录“依据的是哪一版研究页”，并提供只读接口回答“这些研究页自该判断以来变了什么”。供 T5-c（议题页展示、议题 Agent 续研输入）使用。

## 2. 现状核实（2026-09-23，Claude 只读）

- 议题只有一条 `judgment { text, state, basis_refs }`（`backend/app/services/research_topics.py` `update`，约第 548 行）；无判断时间。`basis_refs` 前缀限 `claim: / evidence: / source: / lookup:`（`BASIS_REF_PREFIXES`），**不能引用研究页**。
- `source:` 引用本身含 `document_id : parse_revision_id : parsed_content_sha256 : block_id`，已是固定版本；`claim:` / `evidence:` 同为不可变身份。因此这类依据**无需再记版本**。
- `tracking_items` 已有 `baseline { as_of, known_at, basis_refs }` 与 `last_assessment`；Stock Checklist 明确不存 `evidence_version` / `ref_snapshot` / `stale`。本 Task **不改 tracking_items**。
- Stock DSH 插件 `state.maintenance.readPages`（`dsh/src/native-research-tools.mjs` `boundPageVersion`）已记录本会话读过的研究页及其 `input_hash`。
- 议题写入路径：DSH `topic_update`（`dsh/src/topic-tools.mjs` 约第 166 行）→ `POST /api/v1/wiki/research-topics/{topic_id}` → `ResearchTopicPool.update`；引用校验 `_verify_topic_ref`（`backend/app/api/v1/wiki.py` 约第 842 行）。

## 3. 冻结决定

1. **新增研究页引用**：`page:<slug>@<input_hash>`，只允许出现在 `judgment.basis_refs`；不进 `tracking_items`、`observation`（跟踪基线仍只认证据，延续 Stock Checklist）。
2. **版本由工具钉，不由模型抄**：Agent 在 `topic_update.judgment.basisRefs` 中写 `page:<slug>`（不带版本）；DSH 工具从 `state.maintenance.readPages` 取本会话读到的该页 `input_hash`，改写为 `page:<slug>@<hash>` 后再提交。未读过该页则拒绝，报错提示“先读取该研究页”。模型直接写带 `@hash` 的形式同样按 readPages 核对，不一致拒绝。
3. **Backend 校验**：`_verify_topic_ref` 对 `page:` 引用要求 `<slug>@<input_hash>` 在发布台账（`wiki.page_diff.read_history`）中存在；不存在返回 422。
4. **同页只留一个版本**：合并 `basis_refs` 时，新的 `page:<slug>@…` 替换同 slug 的旧版本（最新判断以最新阅读为准）；其他前缀保持现有合并语义。
5. **判断时间**：`judgment.judged_at` 由 Backend 在 `text`、`state` 或 `basis_refs` 实际变化时写为当前时间；未变不动。旧议题无此字段读取为 `null`。
6. **无基线**：判断中没有 `page:` 引用即“无基线”，接口如实返回，不回填、不推测。现有 4 个议题不迁移。
7. **资料依据不做“有新解析版本”检查**（相对 T5 设计 §3 收窄）：新材料按 T5 设计第 4 点经刷新进入研究页资料时间线，已由研究页差异覆盖；`source:` 等固定版本依据在接口中只计数，不查询。
8. 更新 Stock `docs/human-checklist.md` 对应条目：记录 judgment 允许 `page:` 研究页引用与 `judged_at`，注明 tracking_items 约束不变，依据本 Task 与 T5 设计（用户 2026-09-23 确认）。

## 4. 接口

`GET /api/v1/wiki/research-topics/{topic_id}/basis-changes`

```json
{ "topic_id": "topic:…", "revision": 7, "judged_at": "…" ,
  "baseline": true,
  "pages": [ { "ref": "page:companies/600309-sh@<hash>", "slug": "companies/600309-sh",
               "pinned": "<hash>", "current": "<hash>|null",
               "status": "unchanged|changed|version_unknown|page_missing",
               "summary": { "research": 1, "data": 0, "timeline": 0 } } ],
  "pinned_refs": 5 }
```

- `changed` 时 `summary` 取自 T5-a `compare_specs`；细节由调用方再调 `/wiki/pages/diff`。其余状态 `summary` 为 `null`。
- `pinned_refs`：`judgment.basis_refs` 中非 `page:` 的固定版本依据数量。
- 只读，走现有共享读锁；活跃与归档议题均可查。
- **路由顺序**：`GET /research-topics/{topic_id:path}` 是贪婪匹配，本路由须注册在它之前（同现有 archive / restore）。
