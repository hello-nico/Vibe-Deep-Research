## 2. 冻结决定

- **A1 重试**：整理与纠正子会话结束时，若失败原因为模型输出格式错误（错误码 `MALFORMED_RESPONSE`），用同一快照、同一模型**自动重试一次**；其他失败不重试。重试计入同一条任务，不新建任务行。不在本轮自动换模型。
  - **错误码的取法（2026-09-25 Claude 核实，解除 §5 A 停止条件）**：`SubagentResult` 只有通用的 `stopReason: 'error'` 与可选的 `diagnostic`；本地整理子会话不保证填 `diagnostic`。宿主已通过正式钩子 `ctx.on('session/event', (session, event) => …)`（`research-tools.mjs` 约 423 行）收到每个会话的 `turn/end`，其中 `event.data.reason.kind === 'error'` 时 `event.data.reason.error.code` 即错误码。做法：该钩子对 `reviewAgents` 中的整理会话不再直接 `return`，而是在 `turn/end` 且为错误时，把 `code` 记到该会话的整理状态对象上（`settlementStates.get(session.id).lastTurnError = { code, message }`），其余逻辑不变。`background-review.mjs` 在启动整理 / 纠正子会话后**立即**取得对应状态对象的引用（子会话销毁时 Map 条目会被删，引用仍可读），结果为 `error` 时读 `lastTurnError.code` 判断是否重试；取不到按“非格式错误”处理，不重试。不使用已标记禁止新调用的 `snapshotEvents` / `eventAt`。
- **A2 可读失败原因**：任务记录的 `summary` 不再写原始 `stopReason`，按类别写中文：格式错误“模型返回的整理结果格式有误（已重试 1 次）”；超时“整理超时”；中止“已停止”；其他“知识整理没有完成”。原始值另存 `error_code` 供排查。
- **B1**：产品启动时，若 DSH 界面语言不是中文，切换为内建中文 locale（ID 为 `zh`，经 `ctx.locale.getLocale()` / `setLocale()` 正式接口，不改词典、不用 CSS）。
- **B2**：公司研究任务的提示词加一句：过程中给用户看的说明与最终回答都用简体中文。
- **B3**：Agent 模式提示词加一句：先调用 `read_page_context` 读取本轮页面上下文，再决定是否读研究页、原文或网页。Ask 保持不变。
- **C**：`fresh` 为真时不发送提示，只建会话并打开议题面板显示开场；“继续研究”行为不变。
- **D**：发送时的快照必须与发送当下屏幕上显示的内容一致。Codex 已复现：刷新开始时各块保留旧数据，但 `ovDone` / `emoDone` / `toDone` 被清零，`assistant/snapshot.ts` 只按完成标志判“未加载”。修法：某块**已有可显示的数据**就按数据写入快照（可注明“正在刷新，以下为 HH:MM 的数据”），只有既无数据、也未完成时才写“未加载”。加测试覆盖“刷新中 / 刷新完成”两种时刻。
- **E**：据 Codex 核对：“相关研究材料”已走对象登记层 `openRegisteredObject`（没有独立主页的对象按登记层约定开抽屉，这是预期，不改）；“成员公司”只在 `page.spec.links` 有 `contains` 时呈现（页面数据没有就不显示，不新造数据，在 §8 注明哪些行业页有）。本轮只需把公司页首卡“所属行业”做成可点，进入对应行业页（经对象登记层）。
