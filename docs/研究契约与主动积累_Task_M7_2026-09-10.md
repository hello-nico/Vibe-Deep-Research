## 公司 Wiki 内容分层与 API 字段范围

创建公司 Wiki 时按需获取扶摇快照，落入既有初始化/发布路径；已有公司的显式刷新复用该 Provider 与组合逻辑。API 失败不阻断基础 Wiki 创建，返回具体缺口；成功读取不等于触发全文重写。复用现有 HithinkClient 的凭据、限流和错误处理，不新增任意 HTTP/浏览器工具。

| 内容 | 数据路径与边界 |
| --- | --- |
| 扶摇原始财务/估值字段 | API → Provider 规范化 → 公司 Wiki；无需创建 Document、Block、Evidence、Claim 或“查看依据”卡片。保留来源、期间、单位、as-of，技术元数据不展示 |
| 需派生的比率与指标 | 优先使用 API 明确口径的现成指标；必须派生时使用现有确定性计算并保留输入口径，不能让模型心算补齐，也不因此强制走文档证据链 |
| 已有文档依据与硬关系 | 继续使用现有 Evidence/Claim 链；API 数值不伪装成财报引用，不借本次调整放宽硬关系准入 |
| 分析判断与材料关联 | 允许 Wiki 保留有明确性质的研究内容、假设与 Link；不把每段文字都转换为事实或强制补一条 Evidence |
