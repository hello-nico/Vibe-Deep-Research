## 2. 写入协议（所有维护写入）

1. **提案 → 用户确认 → 执行 → 回执 → 审计。** 按一次可理解的维护意图组织一份提案，展示目标、具体变更与依据；用户通过 DSH 原生选项组件授权；各项保留独立结果。
2. 无新增不弹确认；部分失败不得显示整批成功；不为每个实体或关系重复弹窗。
3. Jev 判断、Agent 提议都**不是**写入授权。实体与硬关系同样遵守，不设自动写入例外。
4. 草案与「待授权」状态由 Backend 持久化，插件只读取与展示。
5. 确认必须对应用户所见的草案或提案；版本冲突要求重读，不静默覆盖；重复确认不重复写入。

### 研究关联的现行端点与状态

- Stock `research_links.py` 校验端点身份：公司、行业、Theme、Comparison Wiki slug、资料 `document:`、记录 `note:`、成果 `result:` 和容器 `topic:`；这不是硬关系端点的扩展。
- 提案绑定原始来源与目标，确认必须重复原端点，并校验对象存在、依据和有效期，不允许后来的界面选择改写目标。研究关联是软链接，不进入事实或硬关系准入。
- 议题内的用户假设连接两个不同的对象，端点不能是 Topic，说明 1–200 字；记录为 hypothesis。找依据后走提案、确认升格为 confirmed，不创建硬关系；缺状态的旧关联按 confirmed 读取，不重写历史。
- 身份闭集、提案和假设校验见 Stock `backend/app/services/research_links.py:63–99,218–275,494–545`。议题的后续产品形态与生命周期由 T11/T12 另行实现。

### 草案的现行失效语义

- 公司、行业研究草案由 Backend 的 `ResearchDrafts` 保存 pending / published / invalid 状态与记录，DSH 只留引用；默认有效期 24 小时，读取和发布时核实有效期与基线。
- 基线是 `base_research_hash`（研究块哈希），不是整页 input_hash；机器事实/API 刷新不自动使研究草案冲突。研究块变化、缺失基线或到期会失效，用户放弃记为 discarded；失效草案不得发布，不自动重做或延长有效期。
- Theme/Comparison 继续用原临时发布凭证，不冒充公司/行业持久草案。任务与状态展示沿失效回执提供重新整理入口，不把草案称作已采用。
- 实现依据：Stock `research_drafts.py:63–98,138–150` 与 `page_drafts.py:35,200–208`；草案→采用流程由 T10 重新设计，重构时整体改写，不能先修改当前授权语义。

## 3. 数据更新与判断更新分开

- **数据更新**：原件、解析、指标、资料时间线。可由确定性 Backend 工具提前完成；快信息（新闻、自媒体）默认只读不入库，慢信息（财报、研报、公告）作为可追溯资料入库。
- **判断更新**：研究判断、主张、成立/失效条件。**只能在「我的研究」绑定具体议题的会话中，由用户与 Agent 共同研究后修订，用户确认后保存。** 其他入口、后台维护、数据刷新、关联维护、对象创建都不授予判断修订权限。
- 议题 Agent 继续研究时先读「上次判断依据的版本 → 当前版本」的差异，再决定是否修订；差异辅助定位，不自动判定旧结论失效。
- 过期报告只提醒、不失效（决定见 decisions）。

## 4. 确定性刷新（公司与行业「刷新资料」）

流程：**检查 → 比较 → 待确认 → 执行 → 回读**。不经 Agent 或 Jev，不夹带判断更新。

| 结果 | 条件 | 动作 |
|---|---|---|
| 最近已检查 | 同范围最近一次完整成功检查 ≤ 60 分钟、目标版本未变、无待确认变更 | 直接返回上次检查时间，不访问外部来源 |
| 检查中 | 同对象已有检查任务 | 返回同一任务（single-flight），页面可离开 |
| 无更新 | 检查成功、内容一致 | 记录成功检查，不建提案、不弹确认 |
| 待确认 | 发现具体差异 | 冻结差异、来源、目标版本与有效期（15 分钟） |
| 部分可更新 | 公司部分 Provider 成功且有差异 | 只写成功部分，失败部分保留旧值与原日期 |
| 检查失败 | 来源持续不可用或无法核对 | 不建提案、不推进成功检查时间，提供重试 |

- 60 分钟比较的是 Backend 记录的来源检查时间，不是页面 `as_of`。
- 临时故障（连接、TLS、超时、限流）由 Backend 有界重试；确定性失败（结构不符、身份不匹配、原文变化）不盲重试。
- 公司刷新在**确认前**取数并比较字段差异；全部失败或零差异不发布新版本。
- 错误以稳定错误码加阶段返回，工作台按错误码显示，不按中文字符串匹配。

## 5. 数据纪律

- 数字必须能回到真实证据；派生数字用确定性计算并保留输入口径；Provider 数值不伪装成财报引用。
- 空值、真实 0、不适用、未配置、调用失败分别处理；刷新失败不覆盖已有好值；同期间不同来源冲突不静默覆盖；跨期间不混算。

## 6. 验收层级

- 写入协议：`integration-probe`（提案→确认→回执→冷读→审计记录）。
