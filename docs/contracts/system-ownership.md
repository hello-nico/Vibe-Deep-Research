# 契约：系统职责与数据归属

状态：反映 2026-10 的当前实现；产品即将重构，重构时整体改写，不作为重构的约束。（2026-10-04 从 M6、M8.5、M9.1 与 AGENTS「当前入口与职责」提取，已对照当前代码核实）。
本文件是所有模块契约的上位：谁拥有什么数据、谁是唯一写入方。其他契约只引用，不重复。

## 1. 四个 Owner

| Owner | 唯一拥有 | 不承担 |
|---|---|---|
| **DSH 运行时**（`desktop/dsh/runtime/`） | 模型配置与凭据、会话、工具注册与执行、子 Agent 父子身份、轨迹、取消、权限与审批 | 金融事实准入、页面排版、研究判断 |
| **Stock-Research Backend** | 资料原件与解析版本、证据、事实、实体与硬关系、Wiki（四类）及其版本、议题（Topic）、研究关联、沉淀记录、研究成果（图表、计算、报告）、研究记忆、维护提案与执行回执、刷新检查记录 | DSH 会话、产品布局、用户界面偏好 |
| **Stock-Research DSH 插件**（Stock `dsh/`） | 研究工具的注册与参数适配、按角色的工具集与提示词（`consumers.mjs` 登记表）、研究宿主与收尾事件适配 | 第二套模型循环、独立事实库、产品 UI |
| **产品**（Vibe `desktop/` + `orchestrator/`） | 页面、导航、对象呈现、发起用户操作；本机数据服务；Client SQLite（`<dataRoot>/client/choices.sqlite`：自选 `watchlist`、加入研究的公司 `research_roster`、持久界面偏好 `prefs`） | 研究正文、会话日志、写入研究数据、直接读 Backend 文件 |

## 2. 数据流向规则

1. 产品向 Backend 发送规范对象 ID 与筛选条件，Backend 返回数据和知识。产品不保存任何研究正文的第二份副本。
2. 产品 HTTP 适配只做受限转发：`/finance-research`（研究读取、上传与引用解析，白名单代理）、`/finance-notes` 与 `/finance-note-digest`（只读转发 Backend 记录）、`/finance-api`（本机数据服务：行情、自选、偏好）、`/finance-model`（页面模型调用）、`/finance-maintenance-refresh`（确定性刷新）及若干宿主状态端点。**不扩大为任意上游代理，浏览器不获取服务端凭据。**
3. DSH 工具经 Stock 插件调用 Backend 正式接口。模型不直接读写 Backend 存储或产品文件。
4. 浏览器内的缓存、Map、标题匹配只做交互防重，不能作为业务正确性的依据；成功以 Backend 回读为准。

## 3. 选择与知识分开

- 「我选择研究什么」（自选、研究名单）归 Client SQLite；「已经积累了什么」（Wiki、议题、记录、成果）归 Backend。
- 取消自选或移出研究名单，不删除 Wiki、议题或记录。
- 空研究名单不能降级为「全部公司」；已加入但尚无 Wiki 的公司照常展示并说明资料状态。
- Backend 不可用时，本地选择仍可读，知识区域显示可重试的错误；记录接口失败不能返回空列表冒充「没有记录」。

## 4. 后台任务

- 后台 Agent 任务（公司研究、知识整理、图文报告生成）都是真实的 DSH 子 Agent：执行、父子身份、轨迹归 DSH；成果归 Backend；产品只做任务身份绑定与只读展示，不建队列、调度器或轨迹副本。
- 执行终态（运行中、结束）不等于业务结果。业务结果区分：完成、无新增、部分完成、失败、取消、待审阅，以 Backend 回读为准。
- 后台任务状态同步显示在研究名单对应行与研究页工具栏（决定见 decisions「后台 Agent 任务状态同步」）。

## 5. 验收层级

- 归属变更（新增持久字段、存储、公开接口）至少到 `integration-probe`：通过产品接口写入，Backend 冷读回。
- 「选择与知识分开」的页面行为到 `ui-journey-smoke`。
