# 问助手回答存入沉淀

状态：2026-09-23 用户确认，待实施。Claude Code 规划，Cursor（Vibe）/ Codex（Stock）实施并回填 §9。**执行方只跑自动检查**，效果由用户验收。不提交、不 push。

权威：[Human Checklist](../human-checklist.md)「问助手回答存入沉淀与 Agent 读取（2026-09-23）」；[todo](../todo.md) §4。

> 界面文案：按钮用「保存为记录」，对用户统一称“研究记录”，不出现“沉淀”。

## 1. 目标

问助手的回答可一键保存为研究记录；深度对话与我的研究的 Agent 能按关键词找到并读取这些沉淀，把用户已认可的问答用起来。

## 2. 现状（2026-09-23 Claude 核实，零件已具备）

- 存储：Stock Backend `notes`（`backend/app/services/notes_store.py`），分类含 `ask`；`GET /notes?query=&category=&offset=&limit=` 与 `GET /notes/{id}` 已支持筛选与全文。
- 保存：Vibe `lib/notes.ts` `addNote(kind, title, content, operationId)`（“问助手”映射到 `ask`，带操作身份可安全重试）；按钮 `components/ui/SaveNoteButton.tsx`（Backend 确认后才显示成功，失败可重试），目前只用于今日要点。
- 读取工具：Stock `dsh/src/my-research-tools.mjs` 的 `note_list` / `note_read`，只在 `state.role === "my_research"` 注册；`note_list` 只有分页，没有筛选。
- 工具清单：`dsh/src/consumers.mjs` `DEEP_RESEARCH_TOOLS` 不含 note 工具；`MY_RESEARCH_TOOLS` 在其后追加 `note_list`、`note_read`。
- 问助手过程列表：`components/TaskTranscript.tsx`（步骤类型 `user` / `assistant` / `tool`），由 `components/ui/FinanceAiDock.tsx` 的 `AssistantTranscript` 使用；同一组件也用于报告等任务过程。

## 3. 冻结决定

- 存 Backend `notes`，分类 `ask`；不写 Client SQLite；不新增 Backend 接口或表。
- 保存内容（Markdown 正文）：
  ```
  ## 问题
  <用户可见问题原文>
  ## 回答
  <该轮最终回答原文，保留引用链接不改写>
  ---
  来源：<页面名称> · <回答完成时间>
  ```
  标题：`问助手 · <问题前 40 字>`。
- 只有问助手面板显示按钮；报告等任务过程不显示（`TaskTranscript` 用可选属性开启，默认关闭）。
- 沉淀不是证据：Agent 读到的沉淀只作线索与用户既往关注，其中数字与结论须回到原引用核对后才能使用；正文不把沉淀当来源引用。

## 4. 范围

### A. Vibe：存入按钮（Cursor）

- `TaskTranscript` 增加可选属性（如 `saveTurns`）；开启时，在每一轮**已结束**的最终 `assistant` 步骤下方显示 `SaveNoteButton`，沿用其现有文案「保存为记录」/「已保存为记录」/「没存上，点这里重试」（界面术语：沉淀统一叫研究记录，见界面文案收敛 Task 术语表），组件不改。
- 运行中（streaming）或该轮失败、中止、无回答正文时不显示。
- 问题取该轮对应 `user` 步骤经 `visibleUserPrompt` 处理后的文本；页面名称取问助手当前绑定页面。
- `FinanceAiDock` 的 `AssistantTranscript` 开启该属性。

### B. Stock：Agent 读取（Codex）

- `consumers.mjs`：`note_list`、`note_read` 移入 `DEEP_RESEARCH_TOOLS`，从 `MY_RESEARCH_TOOLS` 追加列表中去掉（避免重复）。
- `my-research-tools.mjs`：两个工具的注册与执行条件放宽到 `deep_research` 与 `my_research`；错误文案同步。
- `note_list` 增加可选 `query`（关键词）与 `category`（枚举与 Backend `NOTE_CATEGORIES` 一致）参数，透传 Backend；返回形状不变。
- `DEEP_PROMPT` 与 `MY_RESEARCH_PROMPT` 各加一句：用户问题涉及其过往关注或保存过的问答时，可用 `note_list`（带关键词）查找、`note_read` 读取；沉淀是用户保存的既往回答，不是证据，数字与结论须回到原引用核对。

## 5. 验收

- **执行方（自动）**：
  - Vibe：`cd desktop && npm run typecheck && node --test test/*.test.ts`；`git diff --check`。新增测试：已结束的回答显示保存按钮且内容格式符合 §3；运行中 / 失败 / 未开启属性时不显示。
  - Stock：`cd dsh && pnpm run test`（含构建）；`git diff --check`。新增测试：`deep_research` 与 `my_research` 均注册 note 工具、其他角色不注册；`query` / `category` 透传；非法分类拒绝。重启现用工作台。
- **用户验收（用户自己走）**：
  1. 在任一页面问助手提问，回答结束后点「保存为记录」，显示已保存；「我的研究」记录页能看到这条（分类问助手）。
  2. 新开深度对话，问“我之前存过关于 <该主题> 的问答吗，结论是什么”，Agent 能找到并读取这条沉淀，并提示需核对原引用。
