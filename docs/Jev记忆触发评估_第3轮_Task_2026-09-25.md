权威：[研究记忆机制 v2 设计](研究记忆机制v2_设计_2026-09-24.md)（本轮结论将改写其 §3.2–3.4）；[Jev 中文效果验证](Jev中文效果验证_Task_2026-09-24.md) §11（第 2 轮：窄判断可用、相关度不可用）；[Human Checklist](../human-checklist.md)「Jev 判断接入边界」。

## 1. 目标

验证 Jev 能否只看**用户本人的一条消息**，可靠地判断它属于哪类记忆触发，并据此决定后续设计是否成立：

| 选项 | 含义 | 产品动作（通过后才做） |
|---|---|---|
| `preference` | 表达回答方式、口径、格式上的长期偏好 | 写入画像 |
| `correction` | 纠正助手的错误做法或口径 | 写入纠正；针对某对象数据口径的纠正改为提议写到该对象 |
| `tracking` | 要求以后在某事件 / 时间点回来看某件事 | 建议题跟踪项（用户确认） |
| `recall` | 询问自己以前说过、看过、判断过什么 | 由宿主代码先查记忆与研究记录，结果放进本轮 |
| `none` | 其余（绝大多数研究问题） | 不做任何事 |

不评估记忆文本生成、跟踪项字段抽取与召回排序。

## 2. 前置决定（2026-09-25 用户已确认）

1. **发送边界变更**：此前 Jev 只发公开内容。本轮要把**用户在对话里输入的原话**发给外部 Jev 服务（Vercel AI Gateway → TypeSafe）。用户需确认同意，并记入 Human Checklist。
2. 仍然不发：上传资料与“我的资料”原文、附件、研究记录正文、页面快照、工具结果；消息里粘贴的长段外部原文（单条 > 800 字）整条跳过。
3. `correction` 需要上下文：变体 B 附上一条助手回答的前 400 字。用户需同意这部分也可以发送；不同意就只跑变体 A。

## 3. 样本

- **来源**：本机 DSH 会话，只取用户手输的消息：深度对话、问助手、议题会话。排除后台会话（公司研究、知识整理、报告任务）、自动生成的提示（报告任务说明、找依据、“带着这些变化继续研究”等产品模板句）和 @ 引用序列化片段本身（只保留原话与对象名称）。沿用 `session_candidates.py` 的读取方式：在宿主机流式读取，不落地会话副本；把 §2 的跳过规则写成代码，并做单测。
- **规模**：真实消息全量去重后，最多取 400 条。真实正例预计很少，另由 Claude 编写**合成样本**，每类 20 条（共 100 条，含易混淆的反例，如“这个口径是什么意思”不算纠正），单独标 `synthetic`，与真实样本分开统计。
- **盲标**：Claude 先对全部样本标注类别（`labels.jsonl`：`id`、`label`、`note`），**在看到 Jev 结果之前**完成并锁定；跑完后只对分歧样本复核，改标须写理由。

## 4. 题目与变体

- `memory_trigger`（choice，5 选 1，选项描述即 §1 “含义”列，各带一个正例与一个易混反例）。
- 状态字段：`message`（用户原话）、`objects`（本轮对象名称，可空）；变体 B 另加 `previous_answer`（上一条助手回答前 400 字）。
- 变体 A（无上下文）与 B（有上下文）各跑一遍，比较 `correction` 与 `none` 的区分效果。
- 题面、选项描述、状态结构写进脚本常量并提交，便于复现。

## 5. 运行

- 脚本：新增 `backend/scripts/jev_eval/evaluate_r3.py`（`prepare` / `run` / `render` 三步，结构同 `evaluate_r2.py`），传输复用 `app/services/jev_gateway.py`；在 Backend 容器内运行，密钥只从环境读取，不打印、不写文件。

## 6. 通过标准（Claude 裁决）

按**真实样本**计算，合成样本只作补充参考：

| 用途 | 标准 |
|---|---|
| `preference` / `correction` 直接写入 | 在所选阈值下精确率 ≥ 0.9；另报告召回率 |
| 0.5 到直写阈值之间“问你一下” | 这一段的正例占比 ≥ 0.5，否则取消这一段 |
| `tracking` | 精确率 ≥ 0.85（用户会确认） |
| `recall` | 精确率 ≥ 0.8（误触发只多一次查询） |
| 普通问题被误触发（真实 `none` 被判成其他类） | ≤ 2% |
| 延迟 | p95 ≤ 2 秒 |

同时给出每类的混淆矩阵、阈值–精确率曲线（按 0.05 步长列表即可）、单次平均费用。某类没通过，只否决这一类的产品动作，其他类照常。

## 7. Out of Scope

产品接线（每条消息触发、写入、提示“已记住”）；M5 跟踪项结构；记忆文本改写；向量或关键词召回；上传资料与研究记录内容。

## 8. Stop Conditions

- Claude 盲标（`labels.jsonl`）未锁定前：不得运行真实调用，只可完成 `prepare`、脚本与单测。
- 真实样本中 `none` 以外的正例合计少于 20 条：跑完后停止裁决，回报分布，由用户决定是否补充真实对话再测。
- 跳过规则无法可靠识别粘贴的外部原文或私有资料：停止，回填样例。
- 预算或 Jev 不可用：停止，记录已完成部分。

**真实误触发（阈值 0.5）逐条**：“草案还没出现，请重新校验”“上轮收尾未完成，请重新核对”被判为纠正（0.74–0.86）；“读取已有研究成果 / 刚才那份已保存的成果”被判为回忆（0.62–0.76）；“记录接口已恢复，请重新读取”被判为纠正（0.56）。前两类是“一次性让它重做”，写成长期纠正会污染记忆；后一类判成回忆代价很小（多查一次）。合成样本的错误：“别每次都写免责声明”判成纠正、“三季报出来后对比成本”漏判跟踪、“这次回答简短一点”判成偏好（0.63）。

**裁决**

1. **可用，采用变体 B**（带上一条回答前 400 字）。高阈值下 B 的召回更好，误触发同样为 0。
2. **偏好 / 纠正 / 跟踪直接生效阈值 0.9**：真实普通问题误触发 0/65，合成样本精确率 100%，召回 80–95%。
3. **0.7–0.9 之间不直接写入**，改为在回答下方问一句“要记住吗？”由用户确认；低于 0.7 视为无触发。
4. **回忆阈值可放宽到 0.7**：误判只是多查一次记忆和记录，不写入任何东西。
5. **局限**：真实样本里偏好 / 纠正 / 跟踪为 0 条，这几类的数字只来自 Claude 编写的合成样本，可能偏乐观。因此产品接入先做**影子模式**：对真实消息判断并记录，不执行任何写入，攒到至少 30 条真实正例后，用真实数据复核阈值，再打开写入。
