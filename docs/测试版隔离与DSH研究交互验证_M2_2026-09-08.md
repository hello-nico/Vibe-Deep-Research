# M2 · 测试版隔离与 DSH 研究交互验证

日期：2026-09-08。状态：阶段一基本隔离已实现并验证。首页会话与设置入口由 M3 开发预览承接，不再写「尚未接入」。M2 未作为安装包关闭。
本 Task 包含两个顺序阶段。日常通过仓库开发入口快速迭代，阶段性交付可与原安装版并存的测试 App；同一任务覆盖实现、Review 与实机验收。详细执行证据见 [阶段一验证记录](M2_阶段一验证记录_2026-09-08.md)。

## 用户决定与目标

- 以 Vibe-Deep-Research fork 为开发主体，保留现有桌面与业务页面基础。
- 先隔离测试版身份和运行环境，再验证「首页和抽屉共用 DSH 会话能力＋一个真实文档工具＋点击引用回读」。
- Stock-Research Backend 继续提供现有服务；本任务不修改它的业务代码、生产配置和正式知识。
- 首页和抽屉共用会话实现，不据此推导所有页面必须共用同一个 session；本任务不决定长期跨页聊天历史策略。
- 本 Task 不撤销 [M1](首页与盘面取舍_M1_2026-09-08.md) 的界面取舍，不夹带六阶段研究页重设计。
- 用户会频繁改代码和验证：复用现有 `scripts/setup` / `scripts/start`，不把每次重新打包、寻找带时间戳的 App 当作日常开发流程。本次初始化由用户自行运行。

## 日常启动与验证方式

首次在仓库根目录初始化（用户执行）：

```bash
cd /Users/apple/ts/src/Vibe-Deep-Research
./scripts/setup
```

以后启动只需：

```bash
./scripts/start
```

- 启动器同时管理本机 API（8765）和 Vite（5930），检查可用后自动打开 `http://127.0.0.1:5930`；不自动打开浏览器时加 `--no-open`。Ctrl+C 关闭两端。
- 修改前端后由 Vite 热更新；修改编排器后端后需 Ctrl+C 再启动，当前没有后端自动重启。
- 这条入口运行浏览器 UI，不是原生 App 热更新。原生窗口、随包依赖、启动/退出及最终集成验收才重新构建测试 App：`node packaging/macos/build.mjs --test`。
- 默认开发数据根为仓库 `.local`，Codex 默认位于该数据根下 `codex-home`；配置或 `VRA_DATA_ROOT` / `VRA_CODEX_HOME` 可以覆盖，启动前需核对，不得指向原安装版的数据。API 和 Vite 必须使用同一数据根。
- 开发端口 5930 / 8765、原安装版 5938、测试 App 5939 分开；其他源码实例可能占用开发端口，启动器应明确报错，不自动连接占用者。
- 当前仅核对开发脚本、配置及热更新机制，未执行本 fork 的 `scripts/setup` / `scripts/start` 全流程。测试 App 的实机验证不能替代开发环境启动验证。
- 后续 DSH 接入必须同时接通开发启动与测试 App 启动，并分别隔离 DSH 状态；当前测试 App 的 `DSH_HOME` 配置不会自动作用于 `scripts/start`。

## 阶段一：测试版身份和运行环境隔离

1. 为测试版配置独立 App 名称、Bundle ID、产物路径和明显的测试标识；原 App 不覆盖、不重签、不改内部资源。
2. 隔离数据根、Codex 登录根、WebKit 持久存储、DSH home/profile/session/log 与临时运行文件；不自动复制原版凭据、研报、持仓或聊天。
3. 独立分配测试版 UI 与 DSH 服务地址，检查实际占用；启动器、窗口 URL 策略、就绪检测、代理与服务端使用一致配置。端口冲突应明确失败，不连接占用者。
4. 子进程由测试 App 管理；退出只处理自己启动的进程，不能按进程名杀死原版、用户 DSH 或 Stock-Research Backend。
5. 首次接入需要用户完成的认证在测试环境内进行。配置标签来自实际可用来源，原版已保存配置不代表 DSH 已配置。
6. 生成独立测试 `.app` 用于阶段性原生验收；日常修改走上面的开发入口。本轮不要求 DMG、Developer ID 公证或公开发布。

## 阶段二：DSH 交互和真实引用闭环

1. 在现有首页中央区域和公共抽屉接入同一套 DSH 会话组件/适配实现；保留外壳和未涉及页面，不重建全站 slot 树。
2. 优先复用 DSH 客户端服务与现成渲染能力。实现前确认客户端加载、React 单实例及版本、连接/认证和 App 打包路径；不能以隐藏第二套 React 或重复事件总线掩盖不兼容。
3. 发送使用 DSH session，接受回执与最终回答分开；从会话事件展示流式回答、工具开始/完成/失败，停止调用实际 session cancel。
4. 两个入口绑定显式 session 身份。保留现有首页与按页助手的入口区别，验证切页/换对象/关闭抽屉时旧回调不能污染新会话；是否继续后台执行不得由 UI 卸载偷偷决定。
5. 本次验证 Agent 模式；普通「问模型」保留当前行为并做回归，不假称已迁入 DSH。两模式不能同时拥有同一请求；模式切换时明确处理在途轮。统一无工具 DSH 模式留待后续评估。
6. 加载 Stock-Research 已有只读文档工具，使用真实 Backend 和一份已入库报告；允许目录/index/scan 等必要前置调用，不新造一个绕过阅读边界的工具。
7. 固定自然问题，例如「根据这份已入库年报，解释该公司的主营业务，并指出依据」。对象与报告从实际可读资料选择，不能在问题中塞入答案或伪造工具结果。
8. 至少一次真实 pinned Block 阅读成功；工具输出保留文档、revision、hash、Block 身份。界面显示真实工具过程，不把模拟进度当作执行事件。
9. 回答引用绑定本会话实际返回的来源；点击后经受限读取入口调用现有 Backend，回读相同 revision/Block 并显示原文、来源和定位信息。不用整份文件链接替代 Block，不把未经核对的模型文本转换成有效引用。
10. 文档不存在、Backend 不可用、无效引用和版本不匹配均显示实际失败；不能回退为其他 revision，也不能用占位内容冒充回读成功。

## 改动范围与 Owner

- 本 fork：`packaging/macos/`、`orchestrator/src/packaged.ts`、现有 `scripts/start` / `startup.ts` 及必要启动/受限代理接点；`desktop/src/core/ai/`、`FinanceAiDock.tsx`、相关上下文/引用展示与测试。复用现有开发入口，不新建平行启动体系。
- DSH 运行环境：测试版消费钉住依赖与独立配置，不修改正式宿主锁文件/补丁；现有启动能力优先复用，不能顺带升级运行时。
- Stock-Research：只通过现有 HTTP 与已注册工具读取；Backend 仍是文档和证据 Owner。必要前端只读 bridge 不提供任意 URL、文件路径或写入转发。
- 文档：本 Task 是该闭环的范围与验收依据，索引与 Human Checklist 只引用它。

## 验收证据

| 验收项 | 必须提供的证据 |
| --- | --- |
| 开发迭代 | 初始化后 `scripts/start` 可启动；前端保存后热更新、后端重启生效；退出清理自有进程。DSH 接入后，两入口和引用先在开发环境验证，再做 App 验收 |
| 安装隔离 | 原版与测试版实际 Bundle ID、路径、端口、数据根及 WebKit/DSH 存储配置；不输出凭据 |
| 并存与退出 | 原版保持可用时启动测试版；退出测试版后原版仍可用，测试版无自有服务遗留；原版无需重配登录 |
| 两入口一致 | 真实测试 App 内首页和至少一个业务页抽屉分别发送，记录 session 身份、流式过程、错误和停止行为 |
| 对象隔离 | 工具运行中切换对象/页面，旧结果不能挂到新对象；模式切换不得启动重复请求 |
| 真实工具 | DSH session ID、工具名、真实 Backend、报告与 pinned Block 身份、实际返回结果；mock 不计此项 |
| 引用回读 | 点击回答引用后回读原文；核对文档/revision/hash/Block 与工具结果一致；保留截图及脱敏调用记录 |
| 失败边界 | 断开测试连接、无效引用、取消等定向检查；说明哪些使用替身，不能算真实服务验收 |
| 打包结果 | App 产物路径、构建版本/源码状态、文件 hash、完整性签名检查；安装包内实际运行，开发浏览器不能替代 |
| 最小回归 | 相关类型检查、构建、会话/窗口策略定向测试；普通问答和一个现有行情页仍可使用 |

收尾报告分开列出确定性检查、真实模型/Backend、安装版 UI 和用户验收。未完成的证据明确标记，不用测试数量代替闭环。

## Out of Scope（不在范围内）

- 六阶段研究替换、研究归档重设计、完整 Wiki/Topic/Radar/分析原语迁移。
- 知识维护、草案发布、事实写入、数据库迁移或生产 Backend 配置调整。
- 改造全部行情页、删除原运行时全部代码、复制旧用户资料或会话。
- 全站 UI-slot 化、全局聊天历史/跨页恢复产品决策、所有模型来源兼容承诺。
- Windows 安装包、正式版覆盖升级、公开发布、公证与完整性能验收。

## Stop Conditions（停止边界）

- 隔离不成立、可能碰到原版数据/进程，停止运行测试包，先纠正边界。
- DSH 接入要求改动正式宿主、升级依赖闭包或大范围改造前端，先汇报具体冲突与候选办法，不扩大本 Task。
- 现有 Backend 无法提供可核对的真实报告，记录阻塞，不自动导入资料或改生产配置。
- 引用不能绑定真实 pinned Block，或交互需改变未确认的 session/任务归属，先报告证据，不用假引用或隐含语义补齐。
- 必须授权额外数据写入、账户迁移或公开发布才能继续时，停在该动作前；继续完成不依赖它的验证。
