# 事实候选对齐准入白名单 · 会话标题可读

状态：2026-09-24 用户实测发现，Claude 规划，待 Codex 实施并回填 §8。**执行方只跑自动检查**。不提交、不 push。A 在 Stock-Research（`dsh/` 为主），B 在 Vibe `desktop/`。

## 1. 问题与证据（2026-09-24 Claude 诊断）

- **A. 事实候选大量被拒**：深度对话结束显示“本轮有 1 条事实未通过核对”。Backend `agent_extractions` 最近 4 条 `rejected` 原因全部为 `admission policy rejects metric predicate: <名>`（`top_five_customer_sales_share`、`equity_installed_capacity`、`trading_business_gross_margin`、`overseas_revenue`）。准入白名单在 `backend/config/fact-admission-policies.json` `allowed_metric_predicates`（26 个：`revenue`、`net_profit`、`net_profit_attributable`、`gross_margin`、`operating_cash_flow`、`total_assets`、`total_liabilities`、`eps`、`roe`、`installed_capacity`、`electricity_generated` 等），Stock DSH `stage_extraction`（`dsh/src/extraction-tools.mjs`）只校验谓词格式，**不告诉模型哪些可准入**，模型自造谓词，暂存后在研究结束时整批被拒（海螺水泥一轮暂存 13 条）。
- **B. 会话标题不可读**：@ 对象后发送的首条消息，DSH 自动标题取自发给模型的序列化文本，显示为“引用材料：宁德时代 \`compan…”。DSH 会话控制接口提供 `sessions.rename`（`@deepseek-ai/dsh-api-session-controller`）。

## 2. 冻结决定

- **A**：
  - `stage_extraction` 的 metric 谓词改为**枚举**，取值与 `fact-admission-policies.json` 当前策略的 `allowed_metric_predicates` 同源（构建时读取该文件生成，或 DSH 启动时从 Backend 读取，二选一并回填理由；**不在两处手写两份**）；不在白名单的指标在本地直接拒绝，错误提示列出可用谓词并说明“其余指标只在回答中说明，不暂存为事实”。
  - 工具说明加一句：只有白名单指标能成为公司事实；经营比率、客户集中度等非白名单指标照常在回答中引用原文，不暂存。
  - relation / lifecycle 候选不变。
  - 不放宽 Backend 准入；是否扩充白名单（如海外收入、前五大客户占比）是另一项决定，不在本 Task。
- **B**：
  - 首条消息发送后，若会话标题仍是 DSH 自动生成（未被用户改过）且包含产品序列化引用（`引用材料：`、`引用议题：` 等 `lib/researchMentions.ts` 能折叠的格式），用同一折叠规则生成可读标题（如“宁德时代 · 华友钴业供应关系”，取折叠后的首条消息前 30 字）并调用 `sessions.rename`。
  - 用户手动改过的标题永不覆盖；只处理本产品发起的深度对话会话，不处理后台任务与问助手会话。
  - 若 DSH 无法区分“自动标题 / 用户标题”：停止并回填（见 §6）。

## 3. 范围

- A：`dsh/src/extraction-tools.mjs`（枚举与本地拒绝）、构建或启动读取逻辑、测试；Stock `docs/human-checklist.md` 记一句“暂存事实指标与准入白名单同源”。
- B：Vibe `dsh/client.tsx`（发送后重命名）、`lib/researchMentions.ts`（导出折叠为纯文本的函数，若尚无）、测试。

## 4. 验收

- **执行方（自动）**：Stock `cd dsh && pnpm run test`；Vibe `cd desktop && npm run typecheck && node --test test/*.test.ts`；两仓 `git diff --check`；重建 `dsh/dist` 与 finance-ui，重启工作台。新增测试：白名单外谓词本地拒绝且提示含可用列表；白名单与 Backend 配置一致（读同一文件断言）；白名单内谓词照常通过；标题折叠（含 slug、反引号的输入 → 可读标题）；用户改过的标题不重命名。
- **用户验收**：
  1. 深度对话问一个会读年报、涉及客户集中度或海外收入的问题，结束后不再出现“事实未通过核对”（这些指标只在回答里说明）；轨迹中 `stage_extraction` 调用明显减少。
  2. @ 一家公司发问，会话标题显示公司名与问题，不含 `companies/…` 与反引号；手动改名后再发消息不被改回。
