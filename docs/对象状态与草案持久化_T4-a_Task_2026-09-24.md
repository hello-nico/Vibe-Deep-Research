## 1. 目标

1. 研究页草案由 Backend 持久保存并拥有状态：待发布 / 已发布 / 已失效（过期、底稿已变、已放弃），不再只靠临时目录与 DSH 本机任务记录拼出“待授权”。
2. 一个只读接口按对象批量给出状态，供页面徽标、任务记录与提醒卡统一读取。

## 2. 现状（2026-09-24 Claude 核实）

- 草案：`backend/app/services/page_drafts.py` `PageDraftStore` 写在 `default_tmp_root()/wiki-page-drafts/<token>.json`，TTL 24 小时，`purge_expired` 过期即删；记录无“归属对象 / 状态 / 来源会话”。研究页草案经 `POST /api/v1/wiki/page-drafts/research` 签发，`POST /wiki/page-drafts/publish` 发布；Theme / Comparison 草案走 `/page-drafts/validate` 与研究关联存储（`list_drafts`）。
- “待授权”：Stock `dsh/src/background-review.mjs` `upsertBackgroundTask` 写在 DSH 本机 `research/background-tasks.json`（`status: awaiting_authorization`、`draft_token`），Backend 不知道；草案过期或页面更新后任务仍停在“待确认”。
- 其他叠加状态已在 Backend 持久化，只是分散：刷新检查 `app/services/refresh_checks.py`（`GET /maintenance/refresh-checks/current?page=&slug=`，需 hook token）；维护提案 `app/services/maintenance.py`（`maint-<24hex>`，`get_proposal`）；图文报告 `WikiReportStore().list(slug)`（每条带 `input_hash`，可与页面当前版本比较）；页面存在与建立中：`GBrainAdapter.existing_page(slug)`、`pending_path`。

## 3. 冻结决定

- **研究页草案台账**：新增 Backend 持久存储（研究记忆根下，如 `research/page-drafts/`，不在 tmp），每条：`draft_id`（`draft-<24hex>`，与发布凭证 token 分开）、`slug`、`base_input_hash`、`specs`、`source_session_id`、`source_task_id`、`created_at`、`expires_at`（沿用 24 小时）、`status`（`pending` / `published` / `invalid`）、`invalid_reason`（`expired` / `base_changed` / `discarded`）、`published_input_hash`、`updated_at`。
- **状态读时判定**：读取时若已过期或页面当前版本 ≠ `base_input_hash`，把 `pending` 落为 `invalid` 并写原因（幂等）；不起后台扫描。过期记录不再删除，只标失效（保留 30 天后可清理，本 Task 不做清理）。
- 发布凭证仍由原 `PageDraftStore` 校验；发布成功时同步把对应台账记录置 `published` 并写 `published_input_hash`。发布前若台账判为 `invalid`，拒绝并返回 409 `{code: "draft_invalid", reason}`。
- 只覆盖**研究页草案**（知识整理产出的公司 / 行业研究块）。Theme / Comparison 草案维持现状（归议题，另议）。
- **不自动重做**：失效只标记；“重新整理”由 T4-b 前端发起既有公司研究任务，本 Task 不新增重做接口。
- **对象状态接口**（只读，走共享读锁）：`POST /api/v1/wiki/objects/status`，body `{ "slugs": [...] }`（1–50 个，公司 / 行业 slug）→ 每个对象：

  ```json
  { "slug": "companies/600585-sh", "existence": "missing|building|published", "input_hash": "…|null",
    "refresh": { "state": "none|checking|candidate", "checked_at": "…|null" },
    "maintenance": { "pending": 0 },
    "drafts": { "pending": 1, "latest": { "draft_id": "…", "status": "pending|published|invalid", "reason": null, "created_at": "…" } },
    "report": { "exists": true, "stale": false } }
  ```

  字段从 §2 现有来源汇总，不复制数据；某一来源读取失败时该字段为 `null` 并在 `errors` 列出来源名，其余照常返回。
- 新增 `GET /api/v1/wiki/page-drafts?slug=&status=`（列台账，最新在前）与 `POST /api/v1/wiki/page-drafts/{draft_id}/discard`（置 `invalid/discarded`）。
- **DSH 接线**：`background-review.mjs` 签发研究草案时把 `source_session_id` 与任务 id 传给 Backend；任务记录保存 `draft_id`。任务记录的 `awaiting_authorization` 展示以 Backend 台账状态为准（读取接口可由 T4-b 前端调用，本 Task 只保证数据可读、任务记录带 `draft_id`）。
