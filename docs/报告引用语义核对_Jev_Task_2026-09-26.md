# 报告引用语义核对（Jev，草案）

状态：2026-09-25 Claude 定稿（依据 [Jev 第 4 轮评估](Jev引用核对评估_第4轮_Task_2026-09-25.md) §9.4），**演示之后派发**；依赖 [报告引用数字核对 Task](报告引用数字核对_Task_2026-09-26.md) 先完成。实施仓库：Stock-Research `backend/`；Vibe `desktop/`（沿用“待核”标记）。

## 1. 目标

数字核对拦不住的错位——数字对得上但语义不对（“预计”写成“已实现”、提问写成陈述、期间或口径错配），以及不含数字的结论——在报告发布后由 Jev 做一次语义核对，结果只做“待核”提示，不拦截发布。

## 2. 拟定做法（阈值待第 4 轮结果确定）

1. 报告发布成功后，Backend 后台对每个 `claim:` / `evidence:` / `source:` 引用元素做一次 `citation_check`（支持 / 冲突 / 证据不足），输入沿用第 4 轮变体（结论句 + 原文块摘录 ≤ 1,500 字 + 报告名与报告期）。
2. **规则：“支持”概率 < 0.7 → 标“待核”**（第 4 轮：正确引用误标 1/19，问题引用标出 68/70；真实错块引用 13/13 判为证据不足）。输入必须带报告名与报告期（变体 A；不带时误标升至 5/19）。
3. 结果写报告记录的 `semantic_checks`（引用、选项、概率、题面版本），前端与数字核对共用“待核”标记，悬停说明区分“数字对不上”与“语义可能不一致”。
4. 仅核对公开原文（定期报告 / 公告）；上传资料与研究记录不发送。复用注入隔离的每日预算。
5. 报告生成不等待核对；核对完成后刷新报告页即可看到标记。

## 3. 已知局限

- “预计 → 已实现”这类语气错位识别较弱（9/14），但错判时把握偏低（0.64–0.65），阈值 0.7 已能覆盖大部分。
- 原文摘录被截断会导致误标，摘录必须保留结论涉及的全部行（沿用第 4 轮修正后的收窄规则）。

## 4. 范围（预估）

Backend `app/services/citation_semantic_check.py`（新）、报告发布后的后台任务与存储；Vibe 待核提示文案区分。测试与验收在定稿时补全。

## 5. Out of Scope

深度对话回答的实时核对；自动改写报告内容。
